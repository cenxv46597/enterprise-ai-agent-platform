# 网页第三步：工作空间内的知识库列表

2026-10-16，起点 `bdf4148`。在已有 Cookie 登录与本人工作空间第一页上，接入知识库浏览。

## 目标与原因

点击工作空间后，展示该空间的知识库第一页，并能返回工作空间列表。
这一步把已有 HTTP 资源接口接入网页，学习前后端契约、父级范围绑定与异步页面状态。
范围仅为浏览，不包含知识库详情、文档列表、上传、问答或成员管理。

## 概念与设计取舍

比较两种布局：A 为进入知识库视图、提供返回入口；B 为同页保留空间列表并展示知识库。
学习者确认 A，取舍由导师解释，不记学习者已独立说明完整理由。实现和主要测试由导师团队完成。

沿用现有 React 状态，不加路由框架。所选空间与知识库只在页面内存中；F5 后按原 Cookie
恢复身份并从工作空间列表开始，不保存深链接或自动恢复所选空间。
网页不预取全部空间的知识库，只有进入、刷新或显式重试时读取当前空间。

## 调用链与完成条件

工作空间按钮 → 保存所选空间 → 清空旧知识库并显示加载 → 请求列表 → 校验整批响应 → 展示结果。

请求为 `GET /api/v1/workspaces/{workspace_id}/knowledge-bases?limit=20&offset=0`，
复用同源 Cookie、10 秒超时及安全错误处理。后端仍校验用户与当前成员关系，并按空间过滤、
排序、分页；前端另核对返回项的 `workspace_id`、UUID、名称、重复 ID 和最多 20 条的边界。
错配或结构非法时整批拒绝，不展示部分列表。这层响应校验不替代后端权限检查。

- 成功返回 `[]` 才显示“该工作空间暂无知识库”；满 20 条提示可能还有更多，不自动翻页。
- 网络或其他失败保留当前身份与空间上下文，提供显式重试；失败不冒充空列表。
- 401 清理登录、所选空间与知识库；404 显示空间不存在或无权访问，并可返回。
- 返回会取消当前请求、清空知识库并重新读取工作空间，避免继续使用旧成员列表。
- 沿用取消与操作序号隔离：返回、切换、退出或原期限到期后，迟到响应不能恢复旧视图。
  原登录期限不随导航延长，退出仍等待后端确认。
