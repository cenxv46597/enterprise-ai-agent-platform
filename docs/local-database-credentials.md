# 本机数据库凭据管理

## 目标与配置

当前项目是单机开发的 FastAPI 与 PostgreSQL 系统，使用被 Git 忽略的 `.env` 保存本机凭据。Compose 的 `POSTGRES_PASSWORD` 从 `EAAP_POSTGRES_PASSWORD` 读取，缺失或为空时拒绝解析配置；应用库、独立测试库的连接地址引用同一个变量。API 密钥字段继续仅由本机配置。

首次初始化步骤见 [README](../README.md)。初始化命令使用 `secrets.token_urlsafe(32)` 生成随机口令，写入 `.env`，不输出口令。生成值使用 URL 安全字符；如果自行选择含 `@`、`:` 等保留字符的密码，需要正确编码数据库连接地址。

`.env.example` 保留空的口令字段和变量引用，不包含可以直接登录的默认密码。不要将真实 `.env` 添加到 Git，也不要在截图、日志或聊天中展示完整连接地址。检查 Compose 配置使用 `docker compose config --quiet`；不带 `--quiet` 会输出展开后的配置，其中包含口令。

## 两种方案与选择

- 所有人共享固定开发口令：复制示例即可运行，但公开示例也就公开了可用于实际开发数据库的凭据，容易误用于其他环境。
- 每台机器生成随机口令，通过 `.env` 注入：多一步初始化，却能让公开示例和实际凭据分离；同一个变量同时用于容器和连接地址，减少重复修改。

当前采用第二种方案，使用已有 Docker Compose 与环境配置加载器，没有引入新的凭据管理服务。它适合本项目的单机规模；`.env` 仍是明文文件，只应由需要运行项目的本机用户访问。

## 已有数据卷的口令轮换

PostgreSQL 镜像的 `POSTGRES_PASSWORD` 仅用于首次初始化数据目录。更新 `.env`、重建容器并不会替已有数据库角色更换密码。

轮换现有数据库时必须依次完成：

1. 确认目标是本项目本机数据库，保存现有连接配置用于失败恢复。
2. 生成新随机口令，在已认证的数据库连接中修改实际角色口令。
3. 更新本机 `.env` 的口令与连接地址，保留其余模型配置。
4. 使用新连接验证应用库和测试库，使用旧口令验证认证失败。
5. 更新数据库容器的环境配置，保留原数据卷，再次验证连接与健康状态。

上述步骤需要协调进行；数据库角色与本机配置只成功更新一侧时，应恢复一致状态。已运行的后端进程需要重启，以重新读取配置并建立使用新口令的连接池。旧连接仍可能保持已认证状态，不能只用旧连接判断旧口令是否失效。

日后手动修改角色口令，可以使用 `docker compose exec db psql -U eaap -d eaap` 进入本机数据库后执行交互式 `\password eaap`，避免将明文密码写入 SQL 命令行历史；随后同步本机 `.env` 并重新验证。不要删除数据卷来代替轮换。
