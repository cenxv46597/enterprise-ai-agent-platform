# 日常 GitHub 版本管理流程

## 2026-10-12 起的现行约定

学习者提供目标仓库 `https://github.com/cenxv46597/enterprise-ai-agent-platform.git`，默认分支使用 `main`。保留本地已有历史，不覆盖远程历史，不使用强制推送。

每个功能模块完成后依次执行：

1. 说明本次实际修改、设计理由、测试结果与已知限制。
2. 检查 Git 状态、忽略规则、待提交文件和敏感信息；首次上传也检查既有历史。
3. 展示本地提交范围和拟用提交信息；按学习者恢复的“完成且验证的模块本地提交”约定执行暂存与提交，报告提交 ID 和剩余工作区状态。
4. 本地提交与 GitHub 推送分开。没有单独的推送确认，不执行 `push`；本地提交不是云端备份。
5. 学习者要求推送时，再核对全部待推送提交、敏感信息与远程状态，展示目标与范围，经确认后普通推送到 `origin/main`。
6. 推送后核对本地与远程提交 ID，提供 GitHub 页面链接。未推送时明确报告“仅本地提交”。

若新变更超出已说明范围、混入无法归属的修改或发现真实秘密，先暂停相关操作并说明，不把本地提交授权扩展为删除文件、改写历史或推送授权。

若远程已出现其他提交，先读取并说明差异，按情况正常合并或变基，不能以强制推送替代处理。认证需要由学习者在本机完成，不在聊天中收集令牌。
