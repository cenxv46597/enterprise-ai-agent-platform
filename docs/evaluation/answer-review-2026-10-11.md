# 回答质量审核准备：2026-10-11

## 范围与实际结果

复用 2026-10-10 的原始六题真实问答、公开虚构运维说明和固定题集。没有重跑检索或生成，也没有调用模型、访问数据库或读取本机配置。原报告中的 AI 辅助说明保持原样，没有代填为人工验收。

已生成 [逐项审核模板](answer-review-2026-10-11.json)，共有六题、十六项检查：

- 四个实际回答的引用范围与公开原文匹配，并位于重建的对应文本块范围内。
- 两个弃答没有引用，引用检查记为不适用。
- 六题的回答或弃答决策符合固定题集预期。
- 逐项人工审核完成数为 **0/6**，审核覆盖率为 **0%**，六题仍待审核。
- 人工审核通过比例为 **`null`**：尚无已完成人工审核的分母，不能据此声称答案全部正确。

这里的“待审核”指新模块要求的逐项人工记录尚未完成，不是否定旧报告已有的 AI 辅助核对。旧报告与新记录属于不同的验收证据。

## 核心数据流

公开检查项与来源摘要 → 验证原报告、题集及语料 → 核对响应契约、引文和块范围 → 验证审核记录与展示内容绑定 → 保留逐项判断 → 重新计算人工审核覆盖率与已审核通过比例。

审核记录的每项状态为“待审核”“通过”或“不通过”。“通过”和“不通过”都必须说明理由；不通过还需填写确实存在于答案及原文中的片段。程序检查字段与片段，不能自动证明理由在语义上正确。

`reviewer_kind` 区分“人工”和“AI辅助”；即使 AI 辅助把全部检查项判为通过，也不计入人工质量分。审核者名称由填写者申报，当前没有登录或签名来验证身份。

## 可复现的受控反例

学习者先预测：引文正确、来源编号正确时，省略必要条件的答案仍通过 `_validate_citations`。新增测试使用现有生产函数验证了成功返回引用，再以独立受控人工记录将条件遗漏记为不通过。

故障测试还记录操作顺序颠倒、无依据补充、错误回答或弃答、未完成审核、AI 判定不能冒充人工分、答案变化导致审核失效、展示检查项变化，以及输入汇总不能伪造通过数。

这些测试验证分层审核与记录机制；不宣称程序自动发现了所有语义错误，也不将受控测试记录计入真实六题成绩。

补充固定题集反例：把重启步骤原文中的“健康检查通过后”改成“健康检查完成后”，其余文字及引用保留。题集的五个辅助提示词全部命中，现有生产引用校验也通过，但“完成”允许检查失败的情况，改变了恢复导入的必要条件。测试证明提示词命中不足以作为语义通过标准，没有实现自动语义判定。

完整后端回归 **535 项通过、无跳过，156.27 秒**，使用独立测试库与受控模型。随后补充两条审核展示内容一致性保护，最新审核模块 **54 项专项通过，1.85 秒**。完整回归与后续专项分别记录，不合并为虚假的完整测试总数。最初专项运行被 Windows 临时目录权限阻止，改用授权的新临时目录后验证通过，没有修改业务逻辑来绕过测试。

增加上述提示词反例后，审核模块最新专项为 **55 项通过，1.82 秒**。本次未重跑完整后端回归，真实六题的人工审核完成数仍为 0。

## 如何运行与填写

在仓库根目录执行，仅验证公开来源并显示汇总：

```powershell
.\.venv\Scripts\python.exe backend/scripts/evaluate_answers.py --plan
```

生成自己的新模板，已有文件不会覆盖：

```powershell
.\.venv\Scripts\python.exe backend/scripts/evaluate_answers.py --write-report --report docs/evaluation/answer-review-local.json
Copy-Item docs/evaluation/answer-review-local.json docs/evaluation/answer-review-input.json
```

核对模板中每题的实际答案和 `rubric_checks`，只编辑相应 `review`：填写 `reviewer_kind`、`reviewer_name`，再逐项填写 `verdict` 和 `reason`。不通过时补充 `answer_excerpt` 与 `evidence_excerpt`；尚未检查的项目保留原来的待审核状态。不要改动展示答案、来源摘要或检查项，避免核对对象与判定绑定对象不一致。

例如审核者实际完成一项检查后，可按下面结构填写；示例结构本身不是任何真实题目的审核结果：

```json
{
  "verdict": "通过",
  "reason": "答案明确保留原文要求的前提。",
  "answer_excerpt": null,
  "evidence_excerpt": null
}
```

再生成新的结果文件，脚本从原来源重新读取答案并核对审核副本，重新计算分数：

```powershell
.\.venv\Scripts\python.exe backend/scripts/evaluate_answers.py --write-report --reviews docs/evaluation/answer-review-input.json --report docs/evaluation/answer-review-result.json
```

如果更换模型、修改答案或标准，需要建立新的来源与版本，不能手工改摘要来沿用旧成绩。输入、输出都限定在 `docs/evaluation` 的 JSON 文件，错误只显示固定阶段与类型，不输出原始正文。
