# ADR 0032：范围内文件名查找与文档列表翻页

状态：已采纳。2026-10-22确认范围，2026-10-23继续实现与收尾。

## 背景

网页原文档列表只读取默认前20条。上传结果按ID直达处理页解决了刚上传文件的入口，
但员工查找早已入库的报销制度等资料时，仍可能找不到第一页以外的记录。
本人已确认把文件名查找和普通/匹配列表手动翻页合为一个业务闭环。

## 决定

- 沿用 `GET .../documents`，增加可选 `filename_query`，不新建语义检索或Agent接口。
  缺省保留原数组响应、全部处理状态、`limit=20/offset=0`及创建时间/ID升序；
  既有后端 `status` 条件可与文件名取交集，网页本步仍不提供状态筛选。
- 查询先通过真实成员与知识库父级验证，SQL继续约束workspace/KB，
  在此范围内匹配文件名，然后排序、分页。不能只过滤浏览器已有的20条。
- 复用ADR0027候选查询的文件名校验语义，将其提取为共用标量类型：
  去首尾空白后1—255 Unicode码点，禁止NUL，显式空白参数返回422。
  `icontains(..., autoescape=True)`进行不区分大小写的字面包含匹配，
  `%`、`_`及转义符本身不作为用户提供的通配符。使用绑定参数，不拼接用户SQL。
  不调用固定五份候选工具，不接会话选择任务或模型。
- 网页保留输入草稿、已提交条件、目标offset，输入本身不发请求；查找/清除显式读取首页，
  清空时省略参数。刷新、重试、翻页、处理页返回及上传后列表刷新保留已提交条件与页码。
  未提交草稿不替换当前条件；返回知识库/空间、401、退出成功或原登录期限到期清理条件。
- 普通与匹配结果共享20条分页；使用原offset契约，前端只允许安全非负整数的整页偏移。
  保持数组响应，不增加总数查询：满20条只能允许手动尝试下一页，不能证明另有记录。
  空尾页可回退，首页无匹配、空知识库和请求失败分别展示。
- 复用原单请求锁、AbortController与操作序号隔离；新读取清旧行，失败保留目标条件/页码。
  已确认上传结果独立于列表，可按ID继续处理不匹配当前条件的新文件；不得因此重复上传。

## 取舍与限制

扩展已有列表比另建搜索接口少一套响应/鉴权契约；保留省略参数的旧行为，减少现有CLI等调用者迁移。
共享候选线索验证不等于复用五份候选响应，二者用途和分页结构不同。

沿用offset便于接入现有列表；与游标相比，它不提供数据变动期间跨页不重不漏的保证。
没有新增数据库索引、总数、游标、快照、迁移或依赖；没有大规模性能基准。
文件名匹配遵循数据库大小写与排序规则，未承诺Unicode规范等价、模糊拼写或正文语义搜索。

该功能只找文档元数据，不改变整库知识检索范围、ready含义或答案质量保证，
也不会读取原文件、切块、向量化、生成回答或恢复工作流。
