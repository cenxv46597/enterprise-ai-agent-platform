# ADR 0016：先实现显式有界知识智能体

- 日期：2026-10-11。
- 状态：已实现，受控模型与真实数据库验证；真实任务质量待验收。
- 范围：阶段 3.1，单次运行、单个只读知识工具；不持久保存会话。

后续更新：阶段 3.2 的 [ADR 0017](0017-native-tool-calling.md)将默认动作传输改为原生工具协议并保留 JSON 显式选项。本记录保留阶段 3.1 的历史选择，循环、范围、重复与证据边界继续有效。

## 背景

现有 RAG 固定检索后生成。希望让模型根据任务提出下一步搜索问题、读取搜索结果、补充检索或结束，同时保持范围校验、证据来源和执行上限。当前只有一个知识工具，已有 Python、FastAPI 和兼容 JSON 请求层。

动作与观察循环可参考 [ReAct 原始研究](https://arxiv.org/abs/2210.03629)。本实现只要求结构化动作，不收集模型内部思考过程，不复现论文实验或宣称论文成绩。

## 方案比较

### 显式 Python 循环

适合少量同步工具：状态、步数、参数校验、停止和故障都可以直接阅读和测试，复用已有依赖。代价是后续复杂分支、恢复、持久化与并行编排要自行实现；不能把一个循环视为这些能力已经完成。

### LangGraph 状态图

提供状态编排与持久执行等基础设施，适合更复杂或长期运行的流程。需要新增框架、理解状态更新及恢复语义，当前单工具场景收益有限。[官方定位](https://docs.langchain.com/oss/python/langgraph/overview)

当前选择显式循环。出现实际分支、跨请求恢复或长任务需求后重新评估 LangGraph。不是先封装一个通用框架。

## 动作协议与工具

首版复用现有 JSON 请求层和生成模型配置，输出一个 `tool` 或 `finish` 动作。它是结构化动作协议，不是服务商原生 Function Calling；原生工具消息、工具调用 ID 和多工具调用留到后续模块。

`knowledge_search` 通过注册表提供描述与参数 schema，参数只能是 `query`。知识库 UUID、工作空间、检索策略、重排开关和返回量由后端指定，模型不能改变这些范围或执行任意文件、SQL 与网络操作。不存在当前用户身份认证；范围约束不是 RBAC。

注册表拒绝重复名称，未知工具和无效参数作为固定错误观察返回，不执行工具。知识工具复用已有搜索编排，每次最多五段，可选择向量或混合策略，可显式重排。工具不是直接调用 HTTP 自己绕一圈。

## 状态与结束边界

学习者确认相同搜索动作已完成后，第二次请求应停止并标记重复动作。实现采用该选择；规范化范围与失败后重复请求的处理由导师补充。

- 每次运行生成新 `run_id`，状态仅在本次内存中存在，没有会话记忆、断点续跑或后台任务。
- 决策最多八次，默认四次；最后一次决策只能结束。仍请求工具时停止，避免执行一次无法继续观察的工具调用。
- 经过参数校验与去除问题首尾空白后，对工具名和参数计算确定性标识。重复动作停止，即使第一次超时也不自动重复；语义相同但措辞不同不一定被识别，步数上限作为最后保护。
- 证据按真实块 UUID 合并，最多二十块，正文总量最多 `min(生成上下文预算,12000)` 字符；保留首次出现顺序，不对多次结果做新的全局重排。超限整批停止，不偷偷截断状态。
- 同一块多次出现时允许距离或融合分数改变；原文、文档归属或偏移冲突则停止，避免混用两个版本。当前没有原地编辑接口，此检查是快照一致性保护。
- 动作模型接收本次问题、剩余步数、工具 schema、观察与有界原文，每轮重新构造副本。原文只出现于证据池一次，观察通过运行内编号引用；不同决策请求仍会重新发送状态，费用不能只按唯一正文计算。
- `finish` 后直接使用证据池生成，复用原有上下文与引文校验，不重新检索。程序不接受动作模型直接填写最终答案。

## 运行状态与失败恢复

`completed` 表示正常结束，结果可能回答也可能弃答，不代表语义通过。`stopped` 表示重复动作、步数、证据上限或快照冲突，`result` 为 null。`failed` 表示决策或生成技术故障，或者全部工具尝试失败后结束，`result` 为 null；不把技术失败当成正常证据不足。

工具超时、服务错误、容量问题产生固定错误观察，动作模型可以选不同参数继续，也可以结束；没有自动网络重试。若全部尝试失败且无成功工具结果，结束记为 `failed/tool_error`；成功空检索后结束可正常弃答。部分成功的运行仍保留错误步骤，不能据最终回答掩盖中间故障。

运行记录成功返回时 HTTP 为 200，调用方必须检查业务 `status`。配置缺失 503、输入 422、范围 404、模型身份冲突 409、向量数据异常 500。配置和基础数据错误不作为模型可自行修复的工具观察。未知程序异常不宽泛捕获。

模型决策、问题向量、重排及生成均在数据库事务外。首次决策前检查知识库范围，工具执行时再次使用既有搜索范围检查；当前文档不可原地编辑、权限未实现，不宣称覆盖未来撤权或删除的并发语义。

## 记录与成本

响应包含动作类型、工具名、有效检索问题、结果状态、固定错误码、阶段耗时、重排信息、证据编号与块 UUID 映射。证据摘要不返回整个正文、向量或磁盘路径。日志只记录运行 ID 与固定停止/失败原因，不记录原文、问题、凭据或模型内部思考。

动作决策复用 `EAAP_GENERATION_*` 的服务和模型，独立 `EAAP_AGENT_*` 控制等待与输出长度。默认每次决策总期限二十秒；步数限制不是整个运行的墙钟期限，也无法取消正在处理的模型请求。原工具和生成仍有各自期限。全链路 deadline、限流、token 和费用记录后续实现，未知用量不报告零。

最多八次决策、七次实际搜索；每次有候选的搜索可能调用一次向量服务，开启重排可能再调用一次模型，结束时有证据再生成一次。不同问句重复检索仍可能产生费用；重新发起整个运行不会复用旧结果。

## 验收与下一步

受控模型验证正常两步、多次检索、来源去重、超时观察后改用新问题、拒绝跨库参数、各类停止与故障、以及真实数据库事务边界。控制器测试不证明真实模型会正确选择工具或完成任务。

下一模块接入服务商原生工具调用和第二个受限工具，建立少量任务样例，再决定是否需要框架。真实任务成功率、工具选择准确率、调用次数、延迟、费用和恢复能力仍待实测。
