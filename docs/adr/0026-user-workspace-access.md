# ADR 0026：用户身份与工作空间成员校验

状态：已采纳，2026-10-13。程序验收与应用库迁移状态以学习记录和当前 Git 为准。

## 背景

原有接口只核对 URL 中的工作空间 ID、知识库 ID 及数据库父子关系。调用者若知道另一
工作空间的有效 ID，仍可能请求其文档、检索、问答或会话。路径 ID 不能证明调用者身份。
原始项目要求注册、登录、JWT 与 RBAC；学习者选择先确认个人身份，再校验工作空间
成员关系，并指出未经验证的身份会导致越权风险。

## 选择

- `users` 保存规范化用户名与 Argon2id 密码哈希；注册和登录分开。登录返回 30 分钟
  HS256 签名访问令牌，包含用户 ID、签发者、签发时间与过期时间；验证固定算法和必需
  字段，再从数据库读取当前用户。HTTP `X-User-Id` 及 URL ID 均不作为身份凭证。
- `workspace_memberships` 使用工作空间与用户联合主键，角色首批为 `owner`、`member`。
  每次工作空间请求从数据库检查当前成员资格；令牌不缓存工作空间列表或角色。因此
  成员关系变化在下一次请求的校验中生效，已签发令牌本身仍有效至到期。
- 新建工作空间与创建者的 `owner` 关系在同一事务提交。工作空间列表先按当前成员
  限定，再排序和分页；详情及所有下级知识库、文档、检索、问答、智能体、会话、偏好
  和工作流 HTTP 入口统一检查成员。非成员返回 404，未认证返回 401。仅所有者能把
  已注册用户加入为 `member`；成员可以使用现有下级业务接口。
- 迁移 `0010` 仅新增用户与成员表，不自动认领历史工作空间。历史工作空间在明确指定
  已注册所有者前对所有用户不可见。本机维护命令只允许给完全没有成员的工作空间
  指定首位所有者，避免任意注册用户接管历史资料。
- 本地/测试环境没有配置签名密钥时，每个应用进程随机生成临时密钥；进程重启后需
  重新登录。生产环境必须提供至少 32 字符的 `EAAP_JWT_SECRET_KEY`。密钥只在本机
  配置，不写入仓库或响应。共享部署仍需 HTTPS 与入口防护。

## 比较

仅继续核对 URL 父子关系改动最少，但无法回答“甲是否有权访问 B 公司”。共享工作
空间密钥能限制范围，却不能区分同公司的员工，也难以针对个人撤权。选择个人登录
加成员表，支持可核对的用户与工作空间关系；代价是新表、密码管理和每次请求的成员
查询。

服务端不透明会话可立即撤销单个令牌，但需要额外会话表与清理生命周期。原始范围
明确要求 JWT，首版采用短期 JWT，并每次查询用户和成员关系。它不能让已签发令牌
立即失效；若出现即刻注销需求，再设计令牌版本或会话存储。

## 边界

当前角色只区分“所有者可添加成员”和“普通成员不能添加成员”；普通成员仍能调用
工作空间内已有上传、修改设置及模型接口，不能称为只读角色或完整 RBAC 权限矩阵。
会话和知识库级偏好尚无个人所有权字段，同一工作空间成员间并不提供私人会话隔离。
公开注册/登录暂无限流、邮箱验证、密码重置、刷新令牌或撤销列表。本地 stdio MCP
仅由已经通过 HTTP 成员校验的 Host 调用，不能单独作为对外授权接口。

密码哈希及令牌约束参考 [OWASP 密码存储说明](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、
[FastAPI JWT 指南](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/) 与
[PyJWT API](https://pyjwt.readthedocs.io/en/latest/api.html)。
