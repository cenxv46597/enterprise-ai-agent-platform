# ADR 0029：网页登录使用页面内存会话与开发代理

状态：已采纳，2026-10-15。首步仅登录与本人工作空间第一页。

后续：仅页面内存保存令牌的决定已由 [ADR 0030](0030-persistent-web-cookie-session.md) 替代，
以满足刷新和重开后的会话恢复；以下保留第一步设计历史。

## 方案与决定

平台已有 FastAPI 身份接口和成员范围检查，需要让使用者通过页面进入，逐步替代 CLI 交互。
采用 React + TypeScript + Vite 单页入口；相比新增 Next.js 服务端渲染，本步不需要 SSR、
公开内容索引或额外服务端业务层。后端保持权限和数据来源的唯一判断方。
后续出现路由或服务端渲染的实际需求时再评估扩展。

会话比较两种方案：A 将 JWT 仅保存在页面内存，刷新后重新登录；B 持久保存以便刷新后恢复。
学习者确认 A。本版不引入持久浏览器令牌存储，代价是刷新和重新打开页面需要登录；
这也不等于解决 XSS 或实现完整生产认证。现有后端没有刷新和撤销令牌接口，
不通过前端存储伪造这些能力。

前端按 login → me → workspaces 顺序调用既有三个接口，登录提交后清空密码输入框。
令牌通过 Authorization 请求头发送，不放 URL、日志或界面。用户名和资源数据经过
结构检查，名称按 React 文本渲染，未知响应和服务端故障只显示固定安全提示。
401、主动退出和到期时清除内存会话；取消与操作序号共同阻止迟到结果恢复旧页面。
浏览器退出不撤销已签发 JWT。

## 开发与边界

开发服务器仅监听 127.0.0.1:5173，把同源 `/api` 代理到 127.0.0.1:8000。
因此本步不修改后端 CORS，也不在前端配置模型密钥。代理属于开发配置，生产托管与
HTTPS 仍待实现；构建成功不代表已完成生产部署。

列表固定第一页 20 条，显示服务端授权范围内的名称，不推断 owner/member，
不让用户输入内部 UUID，不创建空壳知识库或问答入口。后续逐步接入已有下级接口。

验证结果、学习参与和本机操作见[网页登录记录](../frontend/frontend-login.md)。
