# ADR 0025：可提取文字 PDF 的入库与切块

- 日期：2026-10-13。
- 状态：采用；实现与专项验证结果以学习记录为准。
- 范围：本地单用户文档上传与首次切块，不改变向量、检索和问答契约。

## 背景

现有上传只解析 UTF-8 TXT/Markdown；首次切块又从原文件读取文字。直接允许 `.pdf`
扩展名会让二进制文件进入 UTF-8 读取路径。PDF 需要提取文字，同时保持原来的
`uploaded → processing → parsed/failed` 状态和后续切块、向量链路。

## 比较的方案

**A：共用解析函数，上传和首次切块各提取一次。** 只保存原 PDF，不增加派生文件、
数据库字段或清理规则；切块与上传得到同样的解析文本。代价是首次切块重复解析，
若原文件被外部改动或解析器版本改变，两个时间点的结果可能不同。

**B：上传时保存提取文本快照，切块直接读取快照。** 避免重复解析，方便固定当时的
文字结果；但需要同时管理原件与派生文本的对应、写入失败、清理、对账和版本一致性。

学习者选择 A，尚未独立给出理由。当前文件默认不超过 5 MiB，且首次切块后同配置
重试复用数据库中的块；采用 A 可沿用现有单原件存储与状态流程。若实际 PDF 解析
成本成为瓶颈，再用测量结果评估快照或异步处理。

## 决策

1. 增加 `.pdf` 的媒体类型 `application/pdf`。上传保存一份原 PDF，然后用共用文本
   解析函数检查可提取文字；首次切块从原件调用同一函数。TXT/Markdown 也经此入口
   按 UTF-8 读取。上传解析成功只到 `parsed`；切块不自动生成向量。
2. 保留默认 5 MiB 单文件上传上限；PDF 另外最多 100 页、提取后最多 1,000,000
   字符。损坏、加密、无可提取文字或超过 PDF 解析上限的已接收文件记录 `failed` 与
   固定安全错误码，不公开解析器原始异常。上传前拒绝的不支持类型、空文件、超过
   字节上限的请求仍不创建文档记录。
3. 只处理 PDF 文字层，不做图片文字识别。按固定规则合并提取文字后，现有确定性
   切块计算字符范围；`start_char`/`end_char` 指向合并文字的左闭右开区间，不指向
   PDF 字节偏移或页码。不伪造页码引用或原版面位置。
4. 沿用现有数据库事务、原件对账和同配置切块重试规则，不新增迁移。首次切块若原件
   损坏、不可读或解析结果无效，返回已有来源错误路径，不静默使用上传时的判断。

## 后果与验收边界

- pypdf 用于本地受限解析基线。文件字节、页数和字符数限制并非进程级资源隔离，
  不能保证恶意压缩流不会耗尽 CPU 或内存；对外接收不可信 PDF 前需隔离解析进程，
  设置执行时间、内存及输入预算。pypdf 对内容流解压的内存风险见
  [官方提取说明](https://pypdf.readthedocs.io/en/6.4.0/user/extract-text.html)。
- 首次切块目前在文档行锁与数据库事务内重读并解析原 PDF，解析耗时可能延长锁的
  持有时间；本地单用户基线先沿用现有流程，出现实际延迟或并发瓶颈时需调整事务
  边界并重新验证原件与文档元数据的一致性。
- PDF 的阅读顺序、表格和复杂版式可能与视觉页面不同；程序断言只能验证固定样例、
  状态、字符范围及故障处理，不能据此宣称真实语义质量或模型回答质量。
- 后续若需要页码级引用，应增加明确的页到字符范围映射及相应一致性验证，而不是
  从当前全篇字符位置推断页码。
