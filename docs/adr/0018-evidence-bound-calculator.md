# ADR 0018：原文绑定的受限计算器与确定性收尾

- 日期：2026-10-11。
- 状态：已采纳，接口与执行路径通过程序和协议验收。真实工具选择与任务质量待验收。
- 范围：阶段 3.3；继承 ADR 0016 的有界循环和 ADR 0017 的单动作原生协议。

## 背景

已有工具只能搜索知识库。第二个工具需要演示模型选择、程序执行和执行结果观察，同时让学习者区分“文档事实”和“计算得到的数值”。直接让模型自行算数，无法保证最后展示的数值来自工具执行。

学习者已选择计算结果独立记录、引用指向两个输入来源；避免混淆派生结果与原文的理由由导师解释。独立实践与解释能力另行记录，不据此宣称全部掌握。

## 方案比较

1. **任意表达式**：较灵活，但表达式解析、运算符与资源限制、输入来源绑定较复杂。`eval` 会执行 Python 表达式，禁止使用。受限语法树虽然能避免直接 eval，也不是当前两个工具规模必须引入的能力。
2. **两个绑定操作数**：操作仅有加、减、乘、除，每个输入的来源与格式可独立验证。能力较窄，不能直接执行复合公式，但实现清楚、故障可解释，适合当前模块。

选择第二种，不新增框架或依赖，不使用 eval、任意表达式、动态导入或 shell。每轮仍只执行一个动作，不支持多个原生调用，也不支持把计算结果作为后续操作数。

## 请求与输入来源

`calculator` 接受 `operation`、`left`、`right`。每个操作数只有运行内 `evidence_id`、逐字 `quote` 和十进制字符串 `value`；禁止额外字段。

- 证据来自当前运行、当前已获准知识库的搜索快照。
- 引文必须位于对应文本块，并包含恰好一个完整的受支持数字词项。
- 引文中数值与 value 数值相等；核对完整原文边界，拒绝截取负号、位数、小数、指数、百分数或分组格式造成的合法子串。
- 绑定记录保存真实文档与块 ID、文档名、块编号、引文和字符范围；位置核对用于说明输入出处。
- 不接受用户问题中的任意常量，不转换单位，不从程序结果生成新的原文证据。

同一块内引文重复时沿用当前实现的首次出现位置规则。引文真实存在不代表模型选对业务字段、时间范围、币种或公式；这些仍需任务标注与人工语义核对。

## Decimal 规则

输入为十进制字符串，整数最多 12 位、小数最多 6 位，可为负数。严格 schema 拒绝非字符串、正号、额外前导零、NaN、Infinity、指数和超长数值；规范化小数尾零与负零。

直接构造 Decimal，不经过 float。运算使用完整新建的局部上下文，精度 50，采用 `ROUND_HALF_EVEN`，并保留有关异常 trap，避免全局上下文变更影响结果。

加减乘在输入边界内精确计算；除法量化到 8 位小数，以半偶规则舍入。结果以固定十进制字符串输出并去掉尾零，不返回科学记数法。`rounded` 表示除法是否发生舍入，`decimal_places` 记录除法使用的上限。除零和范围异常返回固定错误，不向外暴露原始异常。

不支持百分数、千分位、分数、科学记数法或单位换算。不会以浮点误差容差替代输入来源验证。

## 原文与派生结果分开

`ToolContext` 提供不可变 SearchHit 元组，工具只能读取当前已收集原文。`ToolOutput` 分开承载 hits 与 calculation；计算器不返回原文 hits，成功结果放在独立 calculation。

控制器在运行内为成功计算分配 `calculation_id`，保存到 `AgentRun.calculations`，步骤记录对应编号。JSON planner 状态与原生配对 tool 观察都会收到该结果。失败观察只含固定错误码。

计算记录标记 `provenance="program_calculation"`，绝不包装为 `GenerationSource`。例如 `120.50 + 30` 得到 `150.5`，引用只对应输入原文；不能用输入文本块的 ID 声称原文包含结果。

## 收尾与失败语义

有成功计算、末次计算尝试也成功时，由程序按成功记录生成算式说明与输入引文，不再调用回答模型。措辞限定为“按以下原文数值计算”，不额外推断计费、退款或其他业务政策。

末次 calculator 尝试失败后收到 finish，返回 `failed / calculation_error` 与空最终结果；已有成功记录仍可用于追踪，但不能作为失败任务的最终答案。不同有效参数修正后成功可以继续完成，历史错误保留。

没有计算尝试的普通知识任务继续使用原 `answer_from_hits` 及引用校验。原 `/answers` 不接入计算器，契约保持原样。模型如果根本未选择计算工具，仍可能通过普通知识生成路径给出数值，需要任务验收检查，不能把当前机制宣传为对所有数值回答的证明。

未知工具、输入错误、来源错误、除零和范围错误遵循工具观察路径。重复动作、步数与证据保护继续停止；默认最多 4 次决策、最多 8 次，最后一轮只能结束。计算记录数量最多 7，与当前工具轮数边界相配。

## 影响与限制

优势是算术结果、舍入政策、输入出处与执行轨迹可重复验证；新增 API 计算记录不会改变普通问答协议。代价是当前只支持两个原文操作数，复杂公式与用户提供数量暂不可表达。

本轮没有会话持久化、计算结果链式引用、单位推理、并行工具或真实任务指标。正常 completed 表示循环完成，不能代表模型选择与业务结论已通过语义验收。

## 验证与后续

数值与来源专项 72 项、多工具无数据库场景 16 项通过；相关回归包含两个真实独立数据库 API 场景，共 **263 项通过（71.48 秒）**。最终完整后端回归 **1011 项通过、无跳过（215.48 秒）**，本轮新增 90 项。具体说明见 [阶段 3.3](../phase3-calculator.md)。测试使用模拟模型，不产生真实模型调用费用。

当前 Agent 与工具部分的基础收尾标准为有界循环、原生协议、两个受限工具和可复现多工具验证。达到该标准后按学习者要求提醒新开对话；Memory、MCP、持久恢复和真实任务质量属于后续阶段。
