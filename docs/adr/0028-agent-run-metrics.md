# ADR 0028：在实际调用边界记录Agent运行统计

状态：已采纳，2026-10-14。首版仅包含三项运行统计。

## 方案与决定

现有步骤轨迹同时包含成功执行、参数拒绝、重复拦截和步数停止。直接数action=tool的
步骤会把未执行的动作也算进去；选择在registry.execute入口计数，进入后故障仍计一次。
学习者能判断“第一次校验拒绝、第二次执行成功”实际执行一次；边界设计与实现由导师完成。

AgentRun追加可选metrics：total_ms、decision_count、tool_execution_count。
使用进程单调时钟测量从run_agent调用开始到返回运行对象的耗时；计数保存在运行内，
共同outcome返回成功、失败、停止或等待时附加冻结快照，不放入模型决策状态。
决策次数计planner.decide调用，包含程序决策，不能称为模型HTTP请求数；工具次数计
注册表执行调用，不是SQL条数、HTTP次数或成功次数。仍抛出输入/配置等异常而未返回
AgentRun的路径沿用原处理，不补造运行对象或统计。

单次接口公开metrics，会话沿用已有轮次JSON保存并重放。没有新表或迁移。
旧AgentRun/轮次没有统计时保持缺省None，不根据旧步骤补造耗时或零次数。
total_ms只覆盖本次控制器运行，不包含HTTP鉴权/响应传输或两次请求间的用户等待，
不通过步骤耗时相加推算；重放返回当时的统计，不重新计时。

## 边界与后续

该首步没有请求级追踪、跨运行聚合、外部观测平台、Token或费用。模型使用量需要服务商
响应及适配层的真实记录，不能从决策数推算；程序测试耗时不作为模型性能或质量指标。
