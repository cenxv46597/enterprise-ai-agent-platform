# ADR 0019：持久会话与结构化整数条件补充

- 日期：2026-10-11
- 状态：已采用；程序验证与真实模型语义验收分别记录。

## 背景

现有 `/agent-runs` 的证据、消息、动作去重和步数都只存在于一次运行。用户问全年费用，
原文只给出“月费 120 元，每次上门服务费 30 元”，系统需要追问全年上门次数。
用户下一条只回复“三次”，后端必须恢复原问题并确定正在补哪个字段。

学习者选择 B，并独立说明仅让模型依据历史推断可能造成歧义。代码实践尚未由学习者完成。

## 比较与选择

方案 A：仅保存最近消息，每轮由模型重建当前任务。实现较少，但待补字段、业务状态和恢复
对象都依赖重新推断，难以确定性验证回复绑定、并发修改与无效输入。

方案 B：结构化保存当前任务与一个待补字段，并提供有界近期消息辅助决策。程序确定输入
应该填入哪里，模型负责提出追问的对象与规则依据；代价是新增契约、表和状态转移。
当前采用 B。

存储继续使用 PostgreSQL。已有数据库可以让状态与轮次一起原子提交，不需新增服务。
Redis 可提供低延迟临时状态，但需要另外设计持久性、过期和跨存储一致性；当前没有测得
需要它的瓶颈。本模块也没有因需要状态而引入 LangGraph。

## 决策

新增会话入口，保留原 `/agent-runs` 与 `/answers` 的单次业务契约。
每个会话固定属于一个知识库，工作空间沿知识库核对。当前依然没有身份认证，范围校验不能
视为用户授权。

`Conversation` 保存 `status / version / task`；`ConversationTurn` 保存客户端请求编号、
请求摘要、模式、用户消息、公开回复与完整公开结果。状态与本轮记录共同提交。

会话状态为：

- `idle`：没有待补任务，可以提交问题。
- `waiting_for_user`：已有原问题、规则原文快照和待补字段，等待补充。
- `ready`：字段已填好、原问题已恢复，执行用户数值计算的能力尚待接入。

会话入口注册 `ask_user`。模型提供字段名、中文对象与时间范围、单位、证据编号与逐字规则。
程序核对引用存在于本次搜索的指定证据；确定性回复先展示规则原文，再提出问题。
原问题与完整证据快照保存到数据库，公开任务只展示来源身份与位置，不直接返回整块正文。

只支持一个 `0..9999` 非负整数待补条件，单位限定为“次、个月、人、件”。完整的阿拉伯
整数、常用中文整数及可选正确单位可以解析。“零次”有效；“三个月”不能填入“次数”，
“三次或四次”“大概三次”等保持等待并提示输入范围，不调用模型猜测。
中文整数解析是保守子集，不覆盖自然语言中的所有数量表达。

确认值独立记录为 `user_message`，保存原始回复及请求编号。它不是文档原文，不能传给
当前只支持两个原文输入的计算器。补充成功返回 `ready` 与
`execution_deferred=user_numeric_calculation_not_supported`，不生成年度总额，不计任务完成。
本模块恢复的是业务任务及输入，不是从任意工具步骤恢复运行检查点。

`mode=new_task` 显式替换当前任务。旧轮次仍保存用于查看和重试，但短期上下文从最近的新
任务起截取。等待期间的普通消息统一按待补回复处理，不自动把长句判断为话题切换。
`ready` 后的普通继续请求返回冲突；修改已确认条件和执行恢复留给后续模块。

## 短期上下文

最近最多三组完整问答、合计最多 4000 正文字符，按时间顺序提供给动作决策器。
放不下整组时停止，不截断问答，也不跳过去选择更旧消息。它不是完整 token 预算。
原生适配器把近期消息作为用户数据字段传入，保持本次运行的 assistant/tool 配对规则；
JSON 适配器读取相同的状态字段。历史文本不进入原文证据池。

最终答案仍由本轮原文生成或程序计算，本模块没有新增长期摘要、向量记忆或长期偏好。
有界历史可辅助检索问题理解，但真实模型的指代判断效果尚待验收。

## 并发、重试与事务

短事务读取范围、版本、待补任务和近期消息；释放事务后调用模型；短事务以旧版本为条件
写回状态、插入轮次。读取会话时用短暂共享锁，使状态与近期消息保持一致。
写回不先获取会话共享锁，避免两个写者同时升级锁造成死锁。

客户端必须提供 `expected_version` 和 `request_id`。不同请求并发时只有一个版本写回成功，
其余返回 `409`；已提交的相同请求重放原结果，不追加消息、不再调用模型。
相同编号但正文、模式或预期版本不同会冲突。范围检查先于重放。

版本检查与已提交重放不保证外部模型恰好调用一次。两个同时首次到达的请求可能都调用
模型；模型结束后进程退出也可能没有提交记录。当前接受这个边界，不自动重试、不持锁
等待模型，不把重复请求保护宣传为付费请求 exactly-once。

保存或接受待补条件时再次核对原文身份、知识库归属、正文和位置；原文变化返回冲突，
不把陈旧规则配上新输入。最终提交前故障时，状态更新与轮次插入一起回滚。

会话最多 200 轮，达到上限要求新建会话。没有自动过期、历史删除或任务队列。

## 验证与限制

见 `test_conversation_counts.py`、`test_clarification_agent.py`、`test_conversation_api.py`、
`test_conversation_migration.py`。测试使用模型替身、MockTransport 和独立 PostgreSQL。
迁移在临时模式验证旧数据保留及模型一致性；不是对生产环境的迁移认证。

程序能证明字段结构、引用存在、回复类型、版本和事务行为。它不能证明真实模型选对了
待补字段、时间范围或业务条件。特别是“全年”是否意味着连续使用十二个月，不能通过
会话状态自动得到确认。真实模型任务成功率尚未知。
