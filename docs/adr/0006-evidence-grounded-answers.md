# ADR 0006：基于检索证据回答，证据不足时弃答

- 日期：2026-10-10
- 状态：已采纳；阶段 1.5 已实现并通过本地故障验证，真实模型问答质量待联调。
- 范围：指定知识库的一次同步回答与引用校验，不保存会话或回答历史。

## 问题

检索返回前 5 段，只表示这些段落在候选中较接近问题，不能保证它们足以回答。例如，“退款审核通过后三个工作日到账”与退款有关，却没有说明如何提交申请。学习者已能识别这种差别。

证据不足是正常业务结果，接口返回 `200` 和明确的弃答；不关闭接口，也不把它混同于模型超时等技术故障。弃答只能说明本次检索到的资料不足，不能据此断言整个企业没有相关资料。

## 方案比较与选择

### 距离阈值与生成判断、程序校验

- 距离阈值便于自动过滤候选，减少生成请求；但距离不是答案正确率，同一阈值也未必适用于不同语料。没有标注数据时，任意阈值可能误删有效证据，仍无法确认段落是否包含所问步骤。
- 生成模型可以判断证据是否支持具体问题，并组织回答；但可能误判或编造。程序能够检查输出格式、引用归属和引文是否存在，不能证明答案在语义上忠于证据。

当前使用生成模型判断与程序校验，不设置未经评测的余弦距离阈值。没有检索结果时直接弃答，跳过回答模型。后续用标注问题评估错误回答与错误弃答，再决定是否增加阈值或其他策略。

### 简单业务服务与编排框架

- 简单服务依次执行检索、预算控制、生成和校验，复用现有 FastAPI、Pydantic 与 HTTP 客户端，流程容易测试。
- 编排框架有利于复杂分支、工具调用和多步工作流，但增加依赖与调试概念，当前单次问答尚未需要。

当前采用简单业务服务与独立 `GenerationProvider`，向量生成和回答生成分别配置。学习者已确认使用 DeepSeek 官网的 `deepseek-flash`，基础地址为 `https://api.deepseek.com`；配置示例已更新，新密钥本机配置仍待完成，不增加新组件或数据库迁移。

首个回答模型使用 Flash 建立基线，后续可用相同问题比较 Pro 的质量与成本。目前[官网价格](https://api-docs.deepseek.com/quick_start/pricing/)中 Flash 的输入、输出单价均更低；这不证明真实语料下答案质量已经达标。应用仍依赖显式配置，模型别名及默认思考模式的行为需在真实联调时记录、核对。

## 流程与证据边界

1. 校验问题、`top_k` 和工作空间、知识库范围，调用已有检索服务。
2. 无命中时直接返回固定弃答，不实例化回答模型适配器。
3. 默认以 12000 字符限制证据正文。按检索排名放入完整文本块；放不下的块跳过，继续检查后续块，不截断原块。全部块都无法放入时返回 `422`。字符预算不等于服务商的 token 上限。
4. 给实际传入模型的文本块分配本次请求内的来源编号。要求 JSON 模式输出严格结构：`answer`、`abstained`、`citations[{source_id, quote}]`。
5. 草稿弃答时必须为空答案、空引用；正常回答必须有非空答案和引用。程序检查来源编号属于本次传入集合、引文是该块的连续子串，并拒绝重复引用。
6. 服务端根据来源编号构造真实文档、块 ID、文件名、块编号，以及引文在解析文本中的 `[start_char, end_char)`；不接受模型提供的文档 ID 或路径。相同引文在块中重复时选择首次出现，只保证该位置存在，不保证它对应模型意图中的某次出现。
7. 草稿弃答转换为固定提示：“目前检索到的资料不足以确认这个问题的答案。”有效回答和引用一起返回。

两类外部模型调用均在数据库事务外。回答使用检索已返回的文本快照，不持有贯穿整个请求的事务或锁。当前没有原地编辑文档、会话保存或引用版本接口；人工修改数据库后，历史引用仍能定位原内容的保证尚不存在。

提示词将文档当作不可信证据，禁止把文档中的指令当成操作要求，当前也没有工具执行权限。这些措施不能保证抵御所有提示注入。引文确实存在，也不能自动证明它支持答案中的每一项结论。

## 接口与配置

`POST /api/v1/workspaces/{workspace_id}/knowledge-bases/{knowledge_base_id}/answers`

- 请求：`question` 为严格字符串，去首尾空白后 1 至 2000 字符；`top_k` 为严格整数，默认 5，范围 1 至 20；拒绝未知字段。
- 响应：`answer`、`abstained`、`citations`。每条引用包含 `chunk_id`、`document_id`、`document_name`、`chunk_index`、`quote`、`start_char`、`end_char`。字符范围对应引文，不是整个块或文件字节偏移。
- 无证据及模型按契约弃答返回 `200`、固定提示和空引用；这是业务结果。
- 范围、检索模型冲突、输入与数据状态错误沿用 `404`、`409`、`422`、`500`。有证据但回答配置缺失或无效返回 `503`；模型调用、结构或引用不合法返回 `502`；模型超时返回 `504`。

回答模型需要显式配置 `EAAP_GENERATION_BASE_URL`、`EAAP_GENERATION_API_KEY`、`EAAP_GENERATION_MODEL`，兼容地址要求 HTTPS。密钥只留在本机环境配置中。空结果不要求回答模型的地址、密钥和模型名，但仍须满足已有检索服务的向量配置依赖；数值字段由全局 `Settings` 启动校验，必须合法。

接口采用非流式同步处理；没有自动重试、持久会话或缓存。错误和日志不包含问题正文、文档正文、密钥或服务商原始响应。

## 验证与重新评估条件

本轮使用模型替身、模拟 HTTP 与真实 PostgreSQL/pgvector，覆盖无证据跳过生成、模型弃答、合法引用定位、越界与伪造引用、预算、格式错误、超时和事务边界。新增问答 45 项、生成 HTTP 71 项，完整回归 378 项通过、无跳过。额外修复并验证坏草稿在序列化警告中输出正文的风险；测试执行结果见 README。

真实向量及回答模型尚未联调，标注语料与端到端回答质量仍待验收。下一步用公开产品或技术文档及 5～10 个标注问题，分别观察召回、引用可核查性、答案支持程度和弃答是否合理；不能以本地故障测试通过代替这些质量指标。工作空间筛选仍是数据范围控制，不是用户权限。
