# ADR 0012：在公开演示中记录生成请求正文

- 日期：2026-10-11
- 状态：已实现；本地测试验证，新的真实生成快照待采集

## 背景

学习者选择比较提示词时使用同一组证据。原六题报告记录了检索结果和最终引用，却没有保存生成时经过字符预算筛选的资料；最终引用也不能表示模型看到的全部资料。因此不能从旧报告完整还原当时的生成输入。

## 备选方案

1. 业务层记录选中的块：便于保存数据库身份及字符位置；可能遗漏适配器整理后的消息、系统提示词和输出参数。
2. 适配器在发请求前记录正文：能保存最终问题、来源编号、资料顺序、系统提示词和显式参数；仍不能证明请求送达，缺少服务商返回的运行环境与未显式设置的默认参数。
3. 全量网络日志或通用追踪平台：覆盖更多链路，但需处理凭据、私有资料、访问控制和额外组件。当前六题公开演示不需要这些成本。

## 决策

选择方案二，复用已有 Python、JSON 文件和演示脚本，不增加数据库表或服务。

- 共享请求层支持可选回调，正常问答默认关闭。演示脚本通过 FastAPI 依赖覆盖显式开启。
- 回调只接收请求正文的副本，不接收地址、认证头和密钥，不能修改实际发送的数据。
- 仅接受本次固定问题及来自公开演示原文的资料，未知字段、错误编号与非公开资料拒绝保存。
- 保存完整消息及显式请求参数，同时计算正文、输入、提示词和公开文本的 SHA-256；摘要便于检查内容变化，不是防篡改签名。
- 回调保存成功后才允许发送请求。验证或保存失败阻止模型调用，记录耗时计入请求总预算。
- 快照明确标记“请求发送前”。路由正常返回后另记收到答案响应；这不等于答案语义正确。
- 没有观察到生成请求且路由正常弃答时，快照为 `null`，不编造模型调用。
- 采集要求新报告；不能给旧报告补写后来重跑的输入。续跑新快照报告时必须保持采集模式。

## 范围和限制

仅供固定公开资料的本地实验，不是所有线上请求的审计日志。字符预算与供应商 token 限制仍是不同约束。文件替换失败会阻止发送；这不能保证操作系统崩溃或掉电后的持久性。请求被服务商处理但本机超时仍可能产生费用，快照不能解决这类不确定结果。

本轮没有重新运行真实 RAG；现有快照能力经受控 HTTP 与真实测试库验证。旧回答评审仍使用完整公开文档。严格的同证据提示词实验、来源到数据库块的完整映射、生成响应模型版本和用量记录留待实际对比模块。

## 复查条件

下一次授权真实问答时使用新报告采集输入，再按相同问题、资料与顺序比较两版提示词。若以后需要记录企业私有内容，应先设计访问控制、保留期限及脱敏规则，再讨论线上追踪。
