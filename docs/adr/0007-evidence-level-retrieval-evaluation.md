# ADR 0007：按支持问题的具体证据验收检索

- 日期：2026-10-10
- 状态：标注粒度已采纳；带干扰语料与评测实现尚未完成。
- 范围：本次仅记录设计决策，未生成新语料、运行真实 API 或实现评测代码。

## 背景

当前 6 题单文档真实联调只有 5 个块，top_k=5 返回了全部候选。
既有联调及其原报告继续保留，本 ADR 不改变其记录或结论范围。
后续带干扰资料的评测需要判断检索结果是否包含支持当前问题的证据。
学习者已选择按具体支持段落验收；本记录只确认这一粒度决策。

## 为什么文档命中可能假通过

demo-product.md 同时包含“服务重启恢复”和“上传格式与限额”两个小节。
问题问服务异常后如何重启并恢复导入，所需证据是暂停、重启、检查和恢复顺序。
若结果只返回该文档中 TXT、Markdown、PDF 的上传格式说明，文档名仍命中。
按文档名验收会判为成功，但返回的段落无法支持服务恢复问题，因此会假通过。
选择具体段落的意义是核对问题所需的事实依据，并非仅增加标注细节。

## 方案比较与决策

文档级标注维护简单，但同文档的无关块也能通过，无法区分上述情况。
具体证据级标注能定位支持问题的段落，但原文变化后需要维护和复核标注。
采用“文档名 + 运行前预先标注的短连续原文”作为预期证据。
固定样例中的文件名须唯一，短原文须能明确定位其支持的事实。
不硬编码本机 document_id、chunk_id 等 UUID。
正确来源在评测运行前确定，不根据模型生成的答案反推或临时补标。

## 证据完整性

短原文应保留必要的前提、时限和操作顺序，不能只选出现主题词的半句。
沿用现有字符切块；切块边界处须核对返回内容是否完整覆盖必需证据。
跨块时，仅返回其中一部分不算完整命中；需要检查返回块的共同覆盖。
overlap 或多个返回块重复覆盖同一份证据，只计一次。

## 验收边界

检索证据命中和回答忠实性分别核对：命中证据不保证答案保留条件与顺序。
答案可以换一种说法；逐字相同、词语出现或引文存在均不能替代语义核对。
本阶段记录预期证据命中事实及人工错误原因，不宣称正式 Recall 或整体质量。
带干扰语料、固定 top_k 比较和评测实现仍待完成，不能将本决策写成实现已完成。
本决策不新增自动续检、重排或评分模型。
后续实现与真实运行应另行记录，当前 6 题联调仍以原报告为准。
