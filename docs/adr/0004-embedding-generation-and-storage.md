# ADR 0004：事务外生成向量，事务内整批保存

- 日期：2026-10-10
- 状态：已采纳；代码和本地故障验证已完成，真实模型联调待本机配置。
- 范围：阶段 1.3，已有文本块的向量生成与 PostgreSQL 保存。

## 问题

文本块已经能够追溯原文，但尚无用于语义检索的向量。模型服务可能超时、返回错误数量或维度，也可能在部分批次成功后失败。必须避免数据库出现部分向量，或文档被提前标记为 `ready`。

同时，数据库事务无法与外部模型请求一起提交。模型等待期间持有数据库行锁会影响其他请求；释放锁后，写回前又需要确认文本和模型配置没有变化。

## 方案比较与选择

### 模型服务接口与本地模型

- 模型服务接口：本机无需下载模型或配置推理环境，便于先完成链路；依赖网络、服务额度与调用费用，文本会发送给服务商。
- 本地模型：便于离线处理，不产生按次接口费用；需要模型下载、推理依赖和资源管理，本机运行时间也需要测量。

学习者选择模型服务接口，并确认首个模型为百炼 `text-embedding-v4`、1024 维。接口地址从控制台复制对应地域和业务空间的兼容地址，不能将示例中的占位符直接作为配置。密钥只放本机 `.env`，通过 `SecretStr` 持有。

### 等待模型时持锁与分段事务

- 一个事务内读取、调用模型、保存：逻辑直观，但网络等待会延长锁持有时间和连接占用。
- 短事务读取快照、事务外调用、短事务校验并写入：减少锁持有时间；需要再次校验快照，并接受并发请求可能重复调用模型。

当前采用第二种。无需加入任务队列、分布式锁或任务租约。以后若同步耗时或重复付费成为实际问题，再设计后台任务与请求去重。

### 在文本块加字段与独立向量记录

- 在 `Chunk` 加可空 `VECTOR(1024)`：与现有文本块一起管理，查询和迁移简单，适合每块只有一组向量的当前范围。
- 独立向量记录和索引批次：便于多模型、版本切换和历史管理，但增加关联、状态与清理规则。

当前采用直接加字段。首个模型配置保存在知识库中：`embedding_provider`、`embedding_model`、`embedding_dimensions`。接口身份不包含密钥。三项同时为空，或同时有效；首个完整结果提交后固定。同一维度不代表不同模型的向量可以混用。

## 数据流和事务边界

1. 接口核对工作空间、知识库和文档归属，结束归属检查事务。
2. 首个短事务按“知识库 → 文档”顺序锁行，检查状态和模型身份，读取块 ID、编号、内容与切块配置。相同配置已有完整结果时直接复用，不调用模型。
3. 结束事务，释放锁；通过 `EmbeddingProvider` 协议调用适配器。此时没有活动数据库事务。
4. 校验完整向量列表。末尾批次失败时抛异常，不返回前面已经成功的部分。
5. 第二个短事务仍按“知识库 → 文档”顺序锁行，重新读取并刷新 ORM 对象，核对配置、状态和全部块快照。
6. 全部向量、知识库模型配置及文档 `ready` 状态在同一事务提交。异常时全部回滚，原有 `parsed` 文档和文本块保留。

初始快照也需要短暂锁行：PostgreSQL 默认的 `READ COMMITTED` 按语句读取已提交数据，不保证连续查询来自同一个时刻。否则可能先读旧 `parsed` 状态，再读到另一请求刚提交的向量，误判数据损坏。

## 接口与限制

`POST /api/v1/workspaces/{workspace_id}/knowledge-bases/{knowledge_base_id}/documents/{document_id}/embeddings` 不需要请求体。成功返回文档 ID、`ready`、模型、维度、块数及 `reused`；不返回向量数组。

- 文档未解析、未切块、模型配置冲突或生成期间快照变化：`409`。
- 超过同步块数上限：`422`，默认 200 块，可配置至 1000。
- 配置缺失或无效：`503`；模型调用或结果异常：`502`；等待超时：`504`。
- 数据库已有部分向量、零向量或状态不一致：`500`，需要检查记录，不能作为成功重试。

适配器每批最多 10 段，按返回 `index` 恢复顺序，检查模型名称、数量、维度和有限数值；拒绝布尔值、超出 float32 范围及保存为 float32 后全零的向量。批次响应上限为 2 MiB。

默认每次 HTTP 读写等操作的等待上限为 30 秒，总处理预算为 120 秒；每批和每个可用响应片段检查预算。同步读取不能被立即抢占，这不是严格的墙钟硬截止。不自动重试或跟随重定向，异常和日志不包含服务响应原文、输入文本或密钥。

百炼还限制单段输入的令牌数。当前字符切块不能精确保证令牌上限，默认 500 字符用于首批小文件；超限由服务返回错误。真实联调必须检查实际语料，不能把本地测试通过视为任意文本均可处理。

## 重试语义与当前边界

- 成功提交后响应丢失：同配置重试复用已保存结果。
- 两个首次请求并发：可能各调用一次模型，最终只保存一套完整向量，另一请求复用已提交结果。
- 模型成功但数据库提交失败：数据库回滚；重试可能再次调用模型并产生费用。
- `ready` 表示该文档的完整向量已经保存，具备下一阶段检索的数据条件；检索接口与问答接口尚未实现。
- 当前没有更换模型、覆盖重建或原地编辑文本块的接口。更换配置时需要新的知识库；多模型或重建流程以后单独设计。

## 迁移与验证

迁移 `20261010_0004` 启用 `public.vector`，新增可空向量和知识库配置字段；旧文档和块保留，初始新字段为空。降级删除新字段及其中的数据，但保留扩展，避免影响其他对象。降级验证仅在临时数据库执行。

验证使用模拟 HTTP 响应及真实 PostgreSQL/pgvector，覆盖结果校验、失败批次、超时、事务外调用、整批回滚、重试、并发锁、模型混用和迁移。测试替身只用来控制事务和故障，不能证明真实模型可用或检索质量。学习者本轮选择暂不配置接口，真实百炼调用留待联调。
