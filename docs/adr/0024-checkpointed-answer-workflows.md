# ADR 0024：固定知识问答的检查点、执行权与显式恢复

- 日期：2026-10-12。
- 状态：采用；程序验收完成，学习者实践、逐题面试与真实语义质量待验收。实际成绩见[阶段 4.6](../backend/phase4-answer-workflows.md)。
- 范围：独立知识库 `answer-workflows` 入口；不改变已有问答、Agent、会话、计费或 MCP 契约。

## 背景

当前单次问答在内存完成检索与生成，失败后没有可继续的步骤。已有持久会话保存待补条件和轮次，不代表能恢复任意工具或生成执行。
实际需求是检索与来源核对已成功、生成发生超时后，读取数据库检查点继续生成。
学习者选择保存检查点的 B 方案，独立理由是避免重复时间与调用消耗；数据库核对本身不耗模型 token，外部向量/生成收费仍取决服务。

## 比较的方案

**整条任务重新执行：** 状态较少，但会重复向量与检索，可能得到不同资料；暂不采用为已保存检查点的默认恢复路径。
**显式检查点恢复：** 多出状态、来源再验和恢复规则，能复用已完成工作；本轮采用。

**只在最终写回 CAS：** 防覆盖，但无法阻止两个首次请求先调用模型，不能承担执行前互斥。
**先短事务领取，再带令牌/版本/租约写回：** 竞争请求在调用前拒绝，接管后旧执行者不能覆盖新状态；本轮采用，不持锁调用模型。

**固定 Python 服务：** 两步流程清晰，复用现有检索、上下文与引用函数，无新依赖，适合当前规模。
**通用工作流框架/后台队列：** 有利于复杂分支、调度与并行，但新增运维和运行契约；等待实际需求，不提前引入。

## 决策

### 固定流程和数据

新增 `answer_workflows`、`answer_workflow_attempts`，迁移 `20261012_0009` 仅建表，保留已有数据。
创建只保存 `pending`；显式执行领取 `running`，固定 `retrieve → generate → done`。
检索本地 `vector/hybrid`，固定 top 5；生成复用已有证据回答与逐字引用校验。
不支持 MCP、rerank、答复偏好、动态步骤或恢复任意 Agent 轨迹。

创建时冻结现有生成字符预算与 12000 的较小值。
检查点保存选入预算的完整原文、范围、策略及来源；最多五块、正文总量 12000 字符、序列化 JSON 100000 UTF-8 字节，严格版本并拒绝重复块。
同时拒绝检查点正文超过任务创建时冻结的预算，不能用全局上限替代任务预算。
空 `hits` 合法，确定性正常弃答且不调用生成；候选全部无法完整装入预算为故障，不伪装成空检索。
排名和距离不构成语义质量判断，字符预算不等于 token 预算。

### 来源与事务

保存检查点、生成前、最终成功写回前重新查询 ready 文档和非空向量，完整匹配知识库归属、文档/块 ID、文档名、编号、正文及字符位置。
事务外调用向量与生成，短事务持有行锁保护领取、来源检查和写回。
旧来源已变化或检查点无效时清除检查点并标记不可直接重试，需要新建任务，不静默重新检索。
查询使用 `populate_existing` 防 ORM 旧对象缓存干扰核对；知识库路径过滤仍不等于身份认证与资源授权。
检查点只冻结选中证据，不是全知识库版本；新资料加入不自动重新召回。需要最新证据集合时新建任务，不能将恢复宣传为最新全库重检索。

### 领取、租约与写回隔离

每次执行先核对 `expected_version`，短事务锁定工作流，保存新的 `active_request_id`、递增版本和 900 秒租约。
每次保存检查点/结果/失败前检查任务仍 running、执行编号和版本相同、租约未过期；未过期 running 拒绝竞争请求。
来源锁等待后再次核对实时租约，避免等待前仍有效、实际写回时已过期。
租约由锁定后的数据库 `clock_timestamp()` 判断，而非事务开始时间；相关时钟语义见 [PostgreSQL 17 官方说明](https://www.postgresql.org/docs/17/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT)。
首版不续租；过期 running 不自动执行，以新请求编号、当前版本和 `recover_interrupted=true` 显式接管，并保存旧尝试 interrupted 回执。
损坏检查点在接管时规范化为不可重试失败，不能因旧中断回执无法序列化而继续发模型请求。
最多五次尝试，版本范围 0..32；达到上限要求新建，既有终态回执仍可重放。
租约是执行权期限，不是模型截止时间、资源隔离或安全授权；不保证取消旧网络调用。

### 重放和错误

创建编号在知识库内唯一，相同规范化创建 payload 返回当前资源；冲突 payload 返回 409。
执行编号在工作流内唯一，相同完整 payload 返回不可变终态回执，不再执行；同编号修改版本/恢复标记等返回 409。
尚无终态回执的同编号返回执行中/结果未知冲突，不能借重试重复领取。
旧失败回执不等于当前资源状态，GET 才是当前状态来源。
可恢复的向量/生成/配置/服务错误持久化固定码，其他来源、检查点或预算故障不可直接重试；不保存第三方原始异常或凭据。
数据库事务失败以安全 503 返回，不用旧版本尝试写入失败；调用方先 GET，再决定原 ID 重放或过期恢复，不能盲目认定原操作没有提交。
execute 仍复用即时构造的 EmbeddingDep，恢复检查点及旧回执重放虽不发向量 HTTP，也需基本向量配置可构造；缺失可在领取前503，不成为持久failed。create/GET不依赖该提供方，零请求不等于无需配置。

### 不承诺外部恰好一次

执行前互斥降低正常竞争重复调用，请求重放避免已提交请求再次执行。
服务商已处理、程序在提交终态前崩溃仍留下未知窗口；租约接管后的生成可能再次付费。
本轮保证数据库状态与旧 worker 写回边界，不保证外部模型或费用 exactly-once，不暗示提供方具有幂等协议。

### 迁移与部署边界

0009 降级同一事务先锁两表，再检查任意数据；包括 pending，非空拒绝删除，不擦除任务或回执。
测试库升级/降级与本机应用库升级分别验证，不能因新脚本存在宣称应用已升级。
本轮本机应用库已另外正常0008→0009，七张旧表计数前后相同，新两表各0行，compare_metadata=[]，没有删除或重建数据。
当前仍本地单用户同步原型，没有认证、审批、删除、队列、调度、续租或生产运维保证。

额外成本是两张表、来源重复查询、显式恢复和版本冲突处理；收益是有可解释的步骤进度、失败回执和恢复边界。
后续动态流程、异步 worker 或远端服务扩展须重新评估租约续期、取消、调度、外部幂等、权限和观测，不把当前两步服务包装成通用工作流引擎。
