# ADR 0010：离线逐项审核答案，区分程序校验与人工语义判定

- 日期：2026-10-11
- 状态：审核工具已实现；真实六题的逐项人工判定待完成

## 背景

检索和上下文覆盖均不能证明最终答案保持原文的条件与顺序。学习者对现有 `_validate_citations` 的代码评审判断正确：真实引文与合法编号会通过校验，即使答案省略“检查通过后”的前提。

原始六题真实报告含 AI 导师的辅助说明，尚没有本模块规定的逐项人工审核记录。这些旧说明保留原样，不自动转换成新的人工质量成绩。

## 方案比较

明确检查项加人工审核易于核对和解释，适合当前六题规模，但需要人工时间。增加模型评审可以提高大量题目的处理速度，但存在成本、输出波动与评审误判，还需人工样例校准。

当前采用第一种方案，使用已有 Python 与 Pydantic，不增加服务、模型调用、数据库表或依赖。

## 决策

1. 固定公开检查项分别描述事实支持、完整性、必要条件、操作顺序与弃答依据，每项附有公开原文。
2. 程序核对最终响应契约、引文字符范围及重建的文本块范围，弃答的空引用记为不适用，不算引用通过。
3. 审核者逐项填写通过或不通过及理由；不通过需要定位答案片段与对照原文。片段由程序检查确实存在，但是否支持语义结论仍由审核者判断。
4. 待审核、部分审核与 AI 辅助复核不进入已完成人工质量分母。单独报告审核覆盖率；没有完成人工审核时，通过比例为 `null`，不能写成 100% 或 0% 的答案质量。
5. 全部人工检查通过且弃答决策符合题集才记为该题人工通过。输入汇总被忽略，每次按实际记录重新计算。
6. 原报告与题集绑定规范 JSON 摘要，答案绑定问题、预期决策与实际响应摘要。审核副本必须展示同一份答案及检查项；来源、答案或标准变化后拒绝复用旧判定。
7. 保留原报告，不覆盖已有输出。只读公开目录，离线执行不读取 `.env`、连接数据库或调用模型。

## 影响与限制

测试能验证记录和统计机制，以及生产引用校验的边界，不能证明程序具有自动识别语义错误的能力。初始六题均待人工审核，原四个回答的引用有效、两个弃答决策符合题集，也不能替代新的人工质量分。

审核者类型与名称由记录申报，当前没有身份认证或签名机制，仍需维护者确认来源。小型原始单文档题集的结果不能推广为带干扰知识库或整个系统的可靠性。

后续若题集扩大，可用相同检查项对比模型评审与人工判定的一致性，再决定是否引入评审模型。语义缺陷先作为评测失败记录，与超时或非法引用等线上技术错误分别处理。
