# ADR 0015：有界候选重排与可见降级

- 日期：2026-10-11。
- 状态：已采纳；模拟模型与真实数据库验证，真实排序质量尚待验收。
- 范围：阶段 2.2，搜索与问答的可选增强；不修改向量或原文。

## 背景

当前演示库四份文档、二十九块，已接入向量和词项融合。名次融合利用两个通道的排名，不能判定段落是否直接回答问题。需要在召回后提供可替换的重排边界，并保留关闭重排的比较基线。

学习者选择运行时超时后返回原检索顺序并标记降级。选择已确认，理由由导师补充：已有候选仍可使用，调用方必须能识别增强步骤未成功；生成仍须判断证据充分性。学习者尚未独立解释全部边界。

## 两种方案

### 专用交叉编码重排模型或服务

联合处理问题与段落、给出相关性得分，适用于召回后的第二阶段。可批量评分，需要额外模型运行环境或服务配置；中文表现、输入限制和延迟要实测。不能把其他数据集指标直接写成本项目成绩。[官方检索与重排说明](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

### 已有生成模型的整组排序

将问题和有界候选同时发送，要求返回全部编号的排列。复用已有兼容 JSON 请求层，便于先验证编排、来源与故障行为；代价是增加一次生成请求，可能受输入顺序影响，也可能输出无效编号。生成式重排有研究依据，但论文成绩不证明当前 DeepSeek 配置能提高质量。[原始研究](https://arxiv.org/abs/2304.09542)

当前采用第二种作为可选基线，复用 `EAAP_GENERATION_*` 的地址、密钥与模型。通过独立 `RerankProvider` 替换适配器时，不要求改变业务调用或数据库。没有新增推理框架、依赖、搜索服务或迁移。

## 候选与协议

- `rerank=false` 为默认，直接沿用旧召回和上下文路径，不调用重排、不读取重排服务配置。
- 开启后先召回 `candidate_k` 段，再重排并返回 `top_k`；`1 <= top_k <= candidate_k <= 20`，默认候选量 20。
- 向量与混合策略均可使用；混合先各通道取二十、融合后选候选二十。两路并集最多四十，未进入融合前二十的块仍不参与重排。
- 原文总长度上限 20000 字符，在发送重排前校验。不能截断原文或偷偷减少候选；超限返回 422，可减少候选数或关闭重排。此前问题向量调用可能已发生。
- 模型仅获得本次局部编号和原文，无磁盘路径、数据库 UUID 或正确答案。返回 `ordered_ids`，必须是全部局部编号的完整排列。
- 适配器和业务边界都校验编号；重复、遗漏、越界、布尔值和字符串编号均拒绝。
- 模型不返回回答、引文或改写内容；最终来源从本地 `SearchHit` 快照按编号选取。来源编号在上下文选择后重新生成。
- 重排只改变顺序，不做相关性阈值过滤；即使所有候选无关也可以排列成功，生成仍可以弃答。

## 事务、失败与可解释性

数据库读取在原检索短事务内完成，重排调用在事务外。等待时新增加的资料不补入本次候选；本次回答基于召回时的原文快照。现阶段没有原地编辑、删除或权限变更接口，这不是未来权限撤销的通用保证。

运行时超时、服务异常或完整排列校验失败，保留原候选前 K，返回 `reranking.status="degraded"` 及固定故障类型；不自动重试。配置缺失返回 503；输入或容量问题返回 422；原检索错误沿用既有处理。不会把这些问题标记成“没有资料”。未知的程序错误继续暴露，不用宽泛异常捕获掩盖错误。

成功时 `status="applied"`，空库为 `skipped_empty`。记录候选量、已验证的响应模型和重排步骤耗时；搜索保留原余弦距离、融合分数、通道排名，并增加原召回排名与重排排名。`metric` 仍描述召回度量；成功重排时最终顺序由模型排列决定。降级时重排排名为空。

默认等待配置为单次网络等待 15 秒、整个重排请求 20 秒，输出上限 512 token，可配置。一次 HTTP 尝试没有自动重试；生成失败时调用方重试整个问答仍可能再次产生重排费用。超时不能证明远端未执行。当前不记录重排 token 用量或费用，不用零代替未知；总问答期限与全链路追踪待后续工程模块。

## 验收与重新评估条件

本轮验证是受控排列与故障规则，不是 DeepSeek 的排序质量。保留默认关闭直到在同一语料、同一候选快照、同一标注问题下，比较候选证据覆盖、最终前五覆盖、弃答、端到端延迟和实际消耗。出现漏召回不能靠重排修复，应定位召回阶段。

后续如延迟或成本不满足目标，或中文专用重排服务实测更好，再替换适配器；不因测试通过直接开启默认。资源上限、故障处理和原文来源契约保持一致。
