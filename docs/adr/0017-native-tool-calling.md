# ADR 0017：原生工具调用与逐次结果回传

- 日期：2026-10-11。
- 状态：实现完成，受控协议与真实数据库验证；真实模型任务效果待验收。
- 范围：阶段 3.2，继承 ADR 0016 的单工具、有界循环；不新增计算器或持久会话。

## 背景

阶段 3.1 让模型在正文中输出动作 JSON，程序解释并执行。它便于学习，但没有演示原生 `tools`、`tool_calls` 和 `tool_call_id` 的消息关联。此次接通原生协议，同时继续由后端决定知识库范围、执行上限和最终回答。

## 方案比较

1. **正文 JSON 动作：** 格式简单，易于重放，现有适配器已经验证；模型的动作和结果仍靠用户数据约定关联。保留为显式兼容选项。
2. **原生工具协议：** 请求传入工具 schema，响应单独携带函数名、JSON 参数和调用编号，执行后回传配对工具消息。协议字段更多，需要检查截断、多调用、非法参数和历史配对；更适合展示工具协议能力。

本轮默认 `EAAP_AGENT_PROTOCOL=native`；`json` 显式选择旧适配器。不根据错误自动改协议或重试，避免额外请求与隐藏故障。配置值错误按现有规则返回 503。还没有对两种协议进行真实任务质量或成本比较。

## 协议边界

- 使用 Chat Completions 的 `tools` 与 `tool_choice=auto`，不附加 JSON `response_format`，不启用 Beta strict 模式。
- 当前只接受一个 `function` 调用；一次返回多调用，整次决策失败，不执行任何工具。学习者已确认拒绝整组并明确报告协议错误；避免部分执行与缺失配对结果的理由由导师补充，独立解释情况另记学习日志。
- 响应只有一个 choice，索引严格为整数零；调用必须以 `finish_reason=tool_calls` 结束。截断等结束原因失败，不执行残缺参数。
- 参数必须为无重复键的 JSON 对象，拒绝 NaN、Infinity、数值溢出及过大参数；仍通过注册表严格验证业务 schema。未知工具、业务参数错误回传固定错误码，可在下一轮选择不同动作。
- 每轮调用编号唯一，结果消息必须与请求编号相同。重复编号是协议故障；新编号不改变重复动作的判定，重复动作依旧按工具名和规范化参数识别。
- 工具调用原始参数字符串和公开前置文字只在本次内存中保存，回传时不改写。控制器再次核对回传参数与实际执行参数一致。对外轨迹新增 `tool_call_id`，不返回内部消息历史或原始非法参数。
- 正常 `stop` 且无调用时转换为 `FinishAction`。结束文字不直接成为答案，仍用已有证据回答及引用校验；没有资料按既有规则弃答，技术失败不能变成正常弃答。

## 状态与工具结果

历史由 `run_agent` 持有，每轮传副本给适配器；适配器自身无会话历史，跨运行复用也不会混用资料。每个请求重建同一问题、已完成 assistant/tool 配对，以及当前剩余决策轮数。结果包含固定成功/错误状态；成功时传运行内证据编号与原文，不传磁盘路径、向量或认证信息。

只有实际执行完成或业务参数拒绝才追加可继续观察的结果消息。重复动作、步数、证据保护会直接停止，不会再发一轮模型请求。本轮最多七组历史配对；请求正文最多 512 KiB，响应沿用 256 KiB 上限，失败不自动截断。

知识范围和证据预算仍由后端绑定。调用编号负责消息关联，不代表权限或幂等键。整个接口重新发起会产生新运行与新成本，没有跨请求恢复。

## 服务商兼容与传输复用

把配置、HTTPS 地址验证、有限响应、总期限、错误脱敏和无重试的 HTTP 路径提取为 `CompatibleChatTransport`。JSON 与工具客户端各自验证请求和解码响应，JSON 快照重放仍拒绝工具字段，没有放宽原有契约。没有新增 SDK、框架或依赖。

根据 [DeepSeek 工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/) 和 [思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，当前官网默认思考模式需要连续回传额外思考字段。本轮只在基础地址的 hostname 严格等于 `api.deepseek.com` 时发送 `thinking={"type":"disabled"}`。其他兼容地址不发送专属字段，不根据模型名称猜测能力。

本轮不支持思考模式的工具历史。若响应仍携带非空 `reasoning_content`，返回协议错误，不丢弃该字段后继续构造不完整请求。没有真实调用验收，第三方服务的扩展字段与默认模式需要另行验证。

## 验证与剩余工作

使用 MockTransport 验证真实 HTTP 请求正文、调用编号、完整结果回传、恢复、跨运行隔离、重复动作与编号、多调用、截断、JSON 歧义、时间与体积边界；使用独立 PostgreSQL 验证 API、向量/混合搜索与原文引用。测试结果见[阶段 3.2](../backend/phase3-native-tools.md)。

下一模块接入受限计算器，先明确“企业原文事实”与“程序计算结果”的来源和验收，再扩展输出契约。多工具并行、完整用量、真实任务成功率、持久会话、记忆与 MCP 尚未完成。
