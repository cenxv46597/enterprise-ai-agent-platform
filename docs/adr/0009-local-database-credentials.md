# ADR 0009：本机独立数据库口令与保留历史的轮换

- 日期：2026-10-11
- 状态：已采纳并在本机执行

## 背景

首次 GitHub 上传前，学习者要求复查配置示例及全部 27 次历史提交。旧默认口令存在于配置和 24 次历史提交中，实测仍能登录本机 PostgreSQL，不能认为只是虚构测试数据。学习者要求保留历史，并授权先修改口令。

## 方案

1. 保留固定开发口令：复制配置最简单，但会公开仍可用于真实本机数据库认证的凭据。
2. 为本机生成随机口令，从被忽略的 `.env` 注入：增加初始化步骤，避免实际口令随代码公开；已有技术栈已经支持环境文件，无需新组件。

## 决策

采用方案 2。示例口令字段为空；Compose 强制要求非空 `EAAP_POSTGRES_PASSWORD`，应用库与测试库连接地址引用该变量。初始化使用 Python 标准库生成 URL 安全的随机值，不将真实口令打印到输出。

针对已有数据卷，实际修改 PostgreSQL 角色口令，再同步本机 `.env` 并更新容器环境。保留原数据卷和全部 Git 历史，通过实际轮换让历史里的旧口令失效。重启已运行的后端以重新读取配置。

## 验证与影响

本机新口令可连接应用库和测试库，旧口令的新连接认证失败；容器重新创建后再次验证通过。工作空间、知识库、文档与文本块数量未变，原 API 配置保留。空口令配置被 Compose 拒绝。

轮换后完整回归 483 项通过、无跳过，146.59 秒；通过新配置只读确认 Alembic 版本仍为 `20261010_0004`，没有结构变更。

`.env` 仍是明文的本机配置文件；本决策适用于当前单机开发规模。历史中仍有旧口令文本，本次只验证其对本项目本机数据库失效，没有验证其他系统。提交和推送仍需学习者确认。
