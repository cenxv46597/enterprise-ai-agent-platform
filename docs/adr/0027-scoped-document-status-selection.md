# ADR 0027：固定文档状态查询与候选选择

状态：已采纳，2026-10-14。验证证据以最新学习记录为准。

## 背景与方案

文档处理进度属于数据库元数据，不需要读取PDF正文。模型自由生成SQL虽然灵活，
也会扩大越权、查询预算与错误处理范围；学习者已选择固定查询方案B。
程序提供find_documents和get_document_status，模型仅填写文件名线索或目标文档ID，
session、工作空间及知识库由已经授权的HTTP调用方绑定。查询沿Doc→KB关系约束两层范围，
只读取必要元数据，不接收任意SQL或存储路径。

同名文件由用户选择。模型重新搜索并解释“第二份”可能遇到排序变化；直接要求用户填写UUID
不便使用。因此保存展示时的有界候选快照，以编号映射到原来的文档ID，再读取最新状态。

## 决定

- 会话消息新增response_mode，默认knowledge，开始状态任务时显式指定document_status。
  continue沿用已保存任务类型，new_task显式替换；模型不能切换程序的回答模式。
  状态模式只注册两种固定查询工具。单次/agent-runs入口仍保留原有工具集合。
- 候选最多五份并保留has_more。零匹配正常结束并说明无匹配；唯一完整候选可继续查询；
  多份或截断结果立即等待用户，不支付一次让模型自行挑选的后续决策。
- 独立DocumentSelectionTask保存原问题、文件名线索和候选顺序。复用Conversation.task
  JSONB、waiting_for_user状态与版本/请求摘要机制；旧整数PendingTask结构保持兼容，
  默认knowledge请求的摘要不新增字段。没有数据库结构变更或迁移。
- 公开列表展示编号、文件名、上传时间、大小和截断提示。首版只接受范围内的数字编号，
  不解析“第二份”等自然语言；has_more不能被当成展示了全部匹配，用户可选择当前页或new_task细化。
- 用户选择后，后端绑定快照ID，用程序动作查询而非让模型再次挑选。每个HTTP请求重新校验
  成员与父子路径；固定状态查询再次限制workspace/KB。写入候选快照前复验来源及展示字段，
  来源已变化返回409，版本和轮次写回一起回滚；新增其他匹配不会重排已有候选。
- 查询使用短事务，决策模型调用前关闭事务。最终写回复用会话版本CAS和已提交响应重放；
  重放返回当时结果，GET读取当前会话，不重复模型或状态查询。
- 成功取得选定文档状态后清空待办、会话回到idle，run.status为completed。文档failed仍是
  查询成功；程序模板展示查询时的状态与已知安全原因，无正文生成或虚假引用。
  选择后的查询故障保留待办，允许用户以新请求编号和当前版本再次选择；不自动重试。

## 取舍与边界

用独立选择任务比把文件编号伪装成“次数”多一类契约，但避免伪造制度证据、混淆条件与目标。
模板回答限制表达方式，也减少一次不必要的生成请求；模型仍负责初始文件名线索和唯一候选动作，
真实规划质量未验收。该任务只有只读元数据查询，不代表通用SQL助手、任意Agent恢复或完整RBAC。
尚无前端、候选分页、自然语言选择和个人私有会话隔离；workspace成员共享会话的既有边界仍在。
