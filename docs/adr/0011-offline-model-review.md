# ADR 0011：离线模型辅助评审，隔离执行失败与质量判断

- 日期：2026-10-11
- 状态：代码、模拟验证与真实单题联调已完成；人工校准待完成

## 背景

学习者指出当前没有专职人工审核者，担心需要逐句整理所有企业文件。逐项规则属于离线题集验收，不是文档入库或每次问答的前置步骤。模型辅助评审可提高批量核对效率，但评审建议不能自动等同于事实正确。

## 备选方案

1. 离线评审：不影响用户问答延迟，便于保留来源和逐题结果，适合当前六题规模；不能在请求返回前阻止错误。
2. 在线评审：生成后再调用模型，可参与返回决策；增加每次问答费用、延迟及故障路径，仍可能误判。
3. 仅人工样例审核：最容易直接核对和解释，没有模型评审费用；题集扩大时人工成本增加。

## 决策

1. 接入可选的离线评审，保留现有人工记录机制。使用已有 Python、Pydantic 和 httpx，不增加新组件。
2. 配置使用独立 `EAAP_REVIEW_*` 字段，计划模式不读取配置；显式运行模式才调用服务。允许主动选择同一服务和模型，不隐式回退到回答配置。
3. 抽取兼容 JSON 请求层，共用地址验证、总等待期限、响应体积限制、安全错误和无自动重试策略。问答与评审拥有各自的输入、输出及异常契约。
4. 评审提示词有版本和摘要，固定温度为 0，记录模型、参数、语料与任务摘要。问题、资料和答案按不可信数据处理，不把预期弃答标签交给模型。
5. 模型只返回逐项建议；身份由程序设为 AI 辅助，不能提交人工身份。检查集合、答案绑定和原文片段由程序再次验证。
6. 技术失败保留未知质量结论，继续后续题，按调用预算限制执行。质量不通过仍是成功执行；无法判断不进入 AI 通过比例的分母。
7. AI 建议比例与人工质量比例分别汇总，并报告覆盖率。只累加服务确实返回且通过格式校验的 token 用量；缺失用量或费用不记为零。
8. 全部输入与调用上限先校验；请求前排他创建新文件，逐题记录执行状态。原报告与已有审核文件不覆盖。中断状态不视为完整结果，不支持自动续跑或重试。

## 范围和限制

旧报告未保存实际生成上下文，本轮复核的是答案与公开完整文档的一致性，不能证明模型只使用当时的证据。现有检查项是小型固定题集，没有覆盖任意企业问题。

评审模型同样可能遗漏条件或误解原文；相同生成和评审模型还可能出现共同盲点。初次开发使用模拟服务验证契约；随后一次真实单题返回三项通过建议，详见[记录](../evaluation/model-review-first-case-2026-10-11.md)。未把 AI 建议计为人工验收，可靠性仍需对照样例验证。

逐题刷新使用本进程新建的文件，正常调用间中断时可保留已写记录；刷新并非原子替换，不能保证写入途中崩溃后的完整性。扩大任务规模后再考虑原子检查点、恢复及批次执行期限。

## 复查条件

真实单题验证后再扩大题集，比较模型建议与少量可靠的人工结论。只有明确测量费用、延迟和错误拦截效果后，才重新讨论在线评审。后续生成记录应捕获实际选中上下文，以支持严格的同证据对比实验。
