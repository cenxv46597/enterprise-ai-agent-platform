# ADR 0013：用固定公开生成快照比较两版提示词

- 日期：2026-10-11
- 状态：已实现；模拟验证，真实配对实验待执行

## 背景

学习者选择提示词对比时使用同一组检索证据。已能记录准备发送的生成请求，但旧六题报告没有这份输入。提示词实验需要固定问题、资料、资料顺序、来源编号、请求模型与显式参数；超时也不能被记成质量通过或失败。

学习者随后选择重新测试全部六题，以检查新增提示词是否引入回退。本轮将这一选择落实为全题集预检和验收清单，复用已有十六项规则，不再拆出新的评测模块。真实六题生成与质量核对仍待执行。

## 备选方案

1. 每版重新运行完整 RAG：能够检查完整业务效果；检索及预算选中资料可能变化，难以归因到提示词。
2. 重放固定生成请求，只替换系统提示词：便于核对控制变量，无需数据库或重新生成向量；不反映检索变化和端到端性能。

本轮选择方案二，完成提示词实验基础。完整链路评测留作不同目的的独立实验，沿用现有 Python、Pydantic、httpx 和 JSON 文件。

## 决策

- 默认计划模式不读凭据、不创建网络客户端或输出文件。明确选择模拟或真实执行，默认一题两次调用尝试。
- `--all-cases` 全选固定六题，与逐个指定题目互斥。默认调用上限仍为 2，全选必须显式设置 `--max-calls 12`；选择全题集不自动扩大预算。
- 输入绑定固定公开语料和题集，重算快照摘要、来源数和字符数；缺失、变化或重复题目快照在执行前拒绝。
- 计划模式显示缺失题目和 `ready_for_generation`，便于先查看资料缺口；执行时缺失快照必须在配置和模型调用前拒绝。
- 六题回归清单绑定题集、原文和既有十六项规则，保留事实、条件、顺序与弃答检查。完整配对加语义核对才形成验收依据；易读性不能抵消必要条件遗漏，待审核不计通过。
- 保留原始 `user.content` 字符串；两版只替换 `system.content`，不重新编码资料。共用请求层提供严格正文重放入口，认证配置单独注入。
- 基线使用快照里的系统提示词，候选附加条件、顺序和事实核对要求。候选尚未替换线上提示词。
- 正常输出复用生产 `GeneratedAnswer` 契约，引用必须在其指定的本次资料中存在且不重复。不伪造快照缺失的数据库块 ID 或字符位置。
- 每版保存请求、摘要、执行状态、返回模型标识、有效草稿与已知用量。未知或坏用量记未知，不丢弃已验证有效的答案。
- 已收到模型响应但草稿或引文校验失败时，保留收到响应的事实和已知用量，不把它混成超时，也不计为有效配对。
- 单版失败继续另一版，不重试。完整配对数只统计两版均取得有效草稿的题目；它是执行覆盖率，不能当作质量比例。
- 语义结论保持待审核、质量比例与赢家为 `null`。不把弃答标签一致、引文存在或模拟输出当作答案正确。
- 输出排他创建新文件，调用前后保存本地检查点；记录失败阻止后续请求，不覆盖原快照。
- `--mock` 明确使用受控脚本输出，真实模型调用为 0。真实执行拒绝受控构造的默认输入，要求实际采集的新公开快照。
- 新增受控六题练习输入，每题使用公开全文按 500/50 参数切出的五块资料。它不是历史真实请求或检索成绩；十二次模拟尝试与六组输出只证明批次可运行，不证明六题语义通过。

## 限制

摘要用于核对内容，不证明历史来源真实性。快照未保存服务地址，本轮两版使用相同的本机配置，但无法验证其与历史服务一致；未显式设置的服务端参数和远端运行环境也不可完整复现。同一模型别名、资料及参数仍可能返回不同答案。

固定顺序的一次两版实验无法估计随机波动，不能宣称候选已改进模型效果。需要多题、可靠语义判定及必要的重复实验。两版返回不同模型标识时应先检查实验可比性。

调用计数是本地尝试状态，包括中断时的“执行中”；不是请求送达或计费证明。当前文件原地刷新不是崩溃安全的原子检查点，尚未实现自动续跑。超时题保留未知结论；正常响应之间的中断可以保留已写完结果。

## 复查条件

在授权采集真实输入后完成固定六题配对，逐项核对条件、顺序和弃答，观察新旧策略的回退。题集扩大后再考虑重复运行、盲评、批次期限、原子检查点与统计方法，不引入新评测平台。当前评测收拢后，开发主线进入混合检索；不以继续细分评测阶段代替业务能力推进。
