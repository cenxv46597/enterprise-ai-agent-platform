# ADR 0022：显式、有限字段的持久答复偏好

- 日期：2026-10-12
- 状态：已采用，阶段 4.4 程序验收及应用库升级完成；真实风格与忠实性、学习者实践仍待验收。

## 背景与方案比较

会话已经保存近期消息和结构化业务待办，但它们不能自动成为跨任务的长期偏好。
“这次请详细解释”只针对本次；“以后都详细解释”表达持续偏好。这两种话的时间范围不同，
不能将一次要求直接推广到所有后续回答，也不能因消息存入数据库就声称系统具有长期记忆。

方案 A：模型阅读聊天后自动抽取、更新自由文本偏好或历史摘要。
对用户方便，但需要解决抽取歧义、冲突、来源、撤销和注入问题；还可能把业务文档中的指令
或一次性要求保存成长期行为。当前没有可靠的自动抽取语义验收，不先引入该机制。

方案 B：通过独立 API 显式保存有限枚举字段，并为更新提供版本校验。
用户需要主动设置，但保存对象、持续时间、清除动作和生效版本都容易说明和验证。
首版只有 answer_detail：concise、detailed 或 null，null 表示清除当前设置。

本轮采用 B。学习者独立说明了“这次详细”仅本次、“以后详细”是长期要求，记录为区分时间
范围的设计理由，不等于已完成自动识别、API 实现或代码实践。两句话是教学场景；本模块
不从自然语言聊天自动创建或清除偏好，持久修改必须调用显式 PUT 接口。

## 范围与存储

采用现有 PostgreSQL，为同一知识库保存一份版本化设置，复用 SQLAlchemy、Alembic 与
严格请求契约。不增加 Redis、向量索引、摘要服务或记忆框架。
相比只存在进程/会话内存中，数据库设置可以跨新任务、新会话和应用重启保留；相比通用
自由文本记忆，有限字段能够直接校验并映射到服务端固定风格句。

这是本地单用户知识库级设置，不是私有用户记忆。工作空间/知识库归属检查只限定资源，
不能代替身份认证与权限隔离；多用户部署前还需要用户身份、所有权与访问权限设计。

没有 TTL。当前值持续到用户显式修改或清除，不随着近期聊天窗口滚动消失。
清除仍保留版本记录，而不是删除行后恢复为初始 version=0，避免陈旧写入重新创建旧偏好。
这条版本墓碑不是仍保留有效偏好，也不是承诺清除历史消息或历史生成输入快照。

## API 与并发

知识库路径下新增 GET/PUT answer-preferences：

- GET 返回 knowledge_base_id、version 和 answer_detail；尚未设置时 version=0、answer_detail=null。
- PUT 接收 expected_version 与 answer_detail；成功更新版本，过时版本返回冲突。
- 清除用当前 expected_version 提交 answer_detail=null，保留新的版本墓碑。

偏好版本与会话消息 expected_version 是两个不同对象的版本，不能混用。
更新使用版本条件写入；并发首次创建和并发修改都不能互相覆盖。
PUT 不等于带 request_id 的会话请求重放：一次成功更新后，用旧版本重复提交仍是陈旧写入，
客户端应读取当前设置并判断结果，不把写入响应丢失当成从未执行。

## 会话生成快照

会话处理读取当前偏好快照；若最终走有证据的生成路径，本次请求使用读取时的这个版本。
读取之后并发更新偏好不会让正在生成的请求改用新值，新值在下一请求读取时生效。
不在模型调用期间持有更新锁，也不因当前偏好后来变化而重写已生成的历史回答。

MessageRead 增加 answer_preference，可为 PreferenceRead 或 null。
只有存在有效非空偏好且进入最终生成偏好能力时才记录该快照；尚未设置、清除当前值、
空检索、停止、追问、计算器说明和确定性计费均返回 answer_preference=null。
清除后的版本墓碑通过偏好 GET 查询，不包装为空偏好生成快照。
该字段记录进入偏好生成能力调用路径时的设置，不保证网络请求已经发出、模型已收到或实际遵守。
不支持该能力时明确失败且不记录快照；进入该路径后超时，失败响应可保留尝试时的版本。
AgentRun 内部同名元数据在会话公开 run 字典中排除，避免重复展示。

已提交消息 request_id 重放返回原响应和原偏好快照，不读取新偏好后替换旧响应。
new_task 清空旧任务/聊天上下文边界，不清除知识库偏好；新建会话也可读取同一设置。
历史轮次保存当时使用的快照，清除当前设置不会擦除它们。
单次 /answers 和 /agent-runs 暂不读取偏好，继续保持已有行为。

## 风格与可信边界

只把已校验枚举映射为服务端固定风格句，加入最终有证据生成的系统提示词。
不保存用户自由文本指令，不把聊天历史、原文或用户自称的角色提升为系统指令。
concise/detailed 都不能放宽证据不足弃答、引用来源、知识库范围或数值来源要求。
没有改变检索、决策器、工具参数、业务公式和程序计费结果，也没有增加风格后处理截断。

程序可以验证使用的快照、固定映射、生成请求与持久化边界；不能仅靠提示词证明真实模型
一定更简洁、更详细或更忠于证据。实际风格、必要条件保留与回答质量另行进行真实语义验收。

## 迁移与验证

降级在同一迁移事务内先取得 answer_preferences 表的 ACCESS EXCLUSIVE 锁，再检查是否
存在行；只要有数据就拒绝删表，包括已经清除当前值的版本墓碑。空表才允许删除，

## 不解决的问题

没有聊天自动抽取、自由文本偏好、任意长期事实、自动摘要、历史向量检索、跨知识库记忆、
身份认证、用户级权限或通用长期记忆平台。一次性请求与长期设置的概念已经区分，
但没有新增自然语言解析“这次/以后”的功能，也没有宣称所有回复路径都支持风格偏好。
