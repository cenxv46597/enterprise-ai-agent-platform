# ADR 0003：文本块的唯一标识与整批幂等保存

- 日期：2026-10-10
- 状态：已采用

## 背景与学习者参与

同一份文档生成 10 个块，保存成功后响应丢失，客户端重新请求。学习者判断数据库仍应只有 10 条，并提出使用“文档 ID + 块编号”识别同一个块。

这个组合在原文和切块规则不变时成立。前一步已验证：改变块长度会使同一编号对应不同内容，因此还必须明确重切块的边界。

## 比较的方案

### 每份文档保留一套固定配置

使用 `(document_id, chunk_index)` 唯一约束，文档记录保存块长度、重叠长度和算法版本。同配置重试返回原记录；参数或算法版本不同返回 `409`。

优点是规则和查询简单，已有块 ID 稳定，适合当前小规模、不可编辑的文档入库。代价是无法直接调整已保存文档的切块策略。

### 保留多套切块版本

创建切块批次，用 `(batch_id, chunk_index)` 唯一标识块，并让引用关联固定批次。

可以对比策略并保留历史引用，但还需要选择当前批次、管理旧索引和清理历史数据。当前尚未进入检索评测，选择第一种；需要重切块与历史引用时再设计批次迁移。

## 决策

### 数据库兜底唯一性

新增 `chunks` 表，保存独立 UUID、文档 ID、块编号、内容和字符起止位置。唯一约束为 `uq_chunks_document_id_chunk_index`。同一文档不得出现两个第 1 块，不同文档可以各有第 1 块。

数据库还检查编号为正、位置范围有效、内容字符数等于范围长度。文档的三个切块配置字段必须同时为空或同时为有效值。已有文档在迁移后保留空配置，无需自动重处理。

唯一约束能阻止重复行，但不能单独保证一次任务的整批完整性，也不能单独把并发冲突转换为成功重试。

### 服务拥有整批事务

`persist_document_chunks` 接收没有活动事务的数据库会话，在一个事务中：

1. 锁住已有文档行，验证文档为 `parsed` 或 `ready`。
2. 检查配置与已有块。同配置返回原记录；不同配置拒绝覆盖；只有配置或只有块时报告状态异常。
3. 首次执行读取文件得到解析文本，调用独立切块函数。
4. 写入全部块和三个配置字段，一次提交；任何异常撤销全部写入。

锁文档行可以覆盖“还没有任何块”的首次执行。两个请求处理同一文档时，后者等待前者结束，再读取其已提交结果。锁只持续到事务结束，不同文档无需等待同一行锁。当前使用 PostgreSQL 默认的读已提交隔离级别。

这种方案需要一次持有整批数据，并在读取文件和切块期间持锁。当前文件上限为 5 MiB、同步处理，尚未为大文件任务引入队列或独立进程。

接口参数使用严格整数，并限制在 PostgreSQL `Integer` 范围内。服务在生成列表前，按文本长度与步长预估块数和累计字符数；单批最多 10,000 个块、累计 10 × 1024 × 1024 个字符，超限返回 `422`。同时约束这两个量，避免“块数不多但每块很长且高度重叠”仍耗尽内存。这些是本地同步处理的保护上限，不是吞吐量性能保证。

### 独立接口与来源范围

在已有文档路径下增加：

- `POST /{document_id}/chunks`：JSON 参数为 `chunk_size`、`overlap`；空对象采用 `500`、`50`。首次成功和同配置重试均返回 `200` 及按编号排序的块列表。
- `GET /{document_id}/chunks`：返回已保存块；未切块时为空列表。

两个接口都检查工作空间、知识库和文档的归属。不匹配返回 `404`；参数无效或处理量超限返回 `422`；未成功解析或配置冲突返回 `409`；文件不可读、包含 PostgreSQL 文本不支持的空字符或切块状态异常返回安全的 `500`，不暴露磁盘路径。

上传仍只完成原文件保存与解析，切块由上述接口显式触发。保存文本块不会把文档变成 `ready`，向量索引尚未实现。

原文件由上传生成独立存储键，当前没有原地编辑接口。位置对应 `read_text_utf8` 返回的解析文本：换行统一后使用 Python 字符切片，不是原文件的字节偏移。手工改写文件会破坏这个前提，不能当成受支持的文档更新。

## 验证与实践

集成测试使用独立 PostgreSQL 测试库，每个用例在临时模式中建表，覆盖：

- 两次保存均为 10 个块，块 UUID 和顺序不变。
- 两个独立会话同时请求，最终只有一批且返回相同 UUID。
- 全部块已写入、提交前故障，其他会话看不到任何块或配置；随后可成功重试。
- 唯一约束、字符范围及配置约束拒绝非法数据。
- 参数与版本冲突、资源归属、未解析状态和安全错误响应。
- 整数范围、空字符和高重叠造成的处理量超限，拒绝时不保存任何结果。
- 中文及换行解析后的原文回溯，原始文件字节保持不变。

学习实践：运行 `python -m pytest backend/tests/test_chunk_persistence.py -q`，先找到“10 条与 UUID 不变”的断言，再解释提交前故障为什么不留下已写入的 10 条记录。需要先设置独立的 `EAAP_TEST_DATABASE_URL`。
