# ADR 0002：字符切块基线与原文位置

- 日期：2026-10-10
- 状态：已采用，当前完成独立算法与测试；数据库持久化和上传流程接入待下一小步。

## 背景与学习者参与

同一文档内可能出现完全相同的句子。学习者提出按出现顺序编号来区分重复文本。该思路推广为：在同一文档的一次切块结果中，为所有块从 1 连续编号，同时记录位置以便直接取回原文。

文档名称和原文件存储键已由现有文档表保存。文本块携带文档 ID，来源展示和原文件定位在后续持久化时通过文档关联获取，避免在每个块中复制文件名和路径。

## 比较的切块方案

- **按固定字符数切块。** 长度有上限、规则简单、容易复现和验证来源位置；可能截断句子、章节或 Markdown 代码块，字符数也不等于模型词元数。
- **按段落或章节切块。** 较容易保留语义结构，但段落长度不固定，仍需处理超长段落，文本与 Markdown 还可能需要不同的规则。

当前选择第一种作为小规模产品或技术文档的可测量基线。后续使用检索评测比较质量，再决定是否采用段落、章节或模型词元边界；本次不引入新的解析框架或模型服务。

## 算法与输出约定

`split_text(document_id, text, chunk_size=500, overlap=50)` 返回不可变的 `TextChunk` 列表。默认长度与重叠数只是初始配置，尚未经检索质量评测。

- `document_id`：来源文档 UUID。
- `chunk_index`：本次切块内从 1 连续递增的序号。
- `content`：当前文本块内容。
- `start_char` / `end_char`：传入字符串中的字符范围，左闭右开、从 0 开始；可直接调用 `text[start_char:end_char]` 获取内容。

每步截取至块长度上限，下一步从本块末尾减去重叠长度的位置开始；到达文本末尾立即停止，避免重复处理末尾。块长度为正整数，重叠长度满足 `0 <= overlap < chunk_size`。空文本和全空白文本没有块；其他文本保留原有空白、换行和字符，不对块内容单独裁剪。

## 位置的含义与边界

位置指向调用方传入的 Python 字符串，单位为 Unicode 码点，不能用作 UTF-8 文件字节偏移，也不保证完整保留视觉组合字符。本函数不规范化换行。当前文件读取方法会把换行解析为统一形式，因此后续回溯必须使用与切块时一致的解析文本。

确定性指同一文档 ID、同一文本和同一配置产生相同结果。序号只在同一次切块方案内区分块；改变原文或切块参数可能改变编号所对应的内容。后续持久化与重切块时需要设计配置记录及旧引用的处理规则。

算法当前独立调用，没有改变上传接口、创建文本块数据库表或推进 `parsed` 状态，也未实现向量生成和检索。
