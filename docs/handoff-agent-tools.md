## 1. 用户目标与长期约定

学习者是准备 AI 应用、Agent 与后端实习的本科生。项目为“企业知识与工作流智能体平台”，目标是可展示、可解释、可验证的求职项目，并掌握设计理由和面试表达，不只是获得能运行的代码。

第一次完整要求保存在本机私有附件，未纳入仓库。新对话开始时，由学习者提供其本机路径或重新附上内容：

```text

```

原要求中的英文 README、注释建议，已被学习者后续“设计和后续内容先使用中文”的明确选择覆盖。继续用中文解释、文档和教学。

协作规则：

- 每个完整模块按八段说明：当前目标、为什么需要、核心概念、设计、实现、验证、学到了什么、下一步。
- 重要设计先给出至少两种方案与当前规模的取舍，让学习者参与。
- 阅读真实代码，围绕真实风险提出问题；每次只有一个核心问题。根据回答评价，再补充知识与小实践。
- 模块完成后准备 2–3 个真实岗位面试问题，逐个讨论，不用连续细碎提问拖延整个能力模块。
- 学习者选择推荐选项只代表确认选择，导师提供的理由不能记成学习者已经独立解释或完成实践。
- 优先 Python 与现有技术栈，先理解 Agent 循环再考虑 LangGraph，不为“高级”引入组件。
- 更新重要 ADR、README、架构图；简历、指标与功能只描述实际完成和验收内容。

学习者观察到我们大量时间在守住一致性规则。已解释原子性、幂等性、快照与协议约束的区别；后续应复用已有保护，把教学集中在新增业务能力，同时分开说明程序规则与真实任务效果。

## 4. 实际技术栈与业务边界

当前后端：Python、FastAPI、Pydantic、httpx、SQLAlchemy、Alembic、PostgreSQL 17 与 pgvector、pytest。数据库用 Compose 本地运行；应用本身还没有完整生产部署。没有 Redis、LangGraph、MCP、认证前端或新 SDK。

本机应用库与独立测试库分开，测试库配置变量为 `EAAP_TEST_DATABASE_URL`。迁移 head 为 `20261010_0004`；本轮 Agent 与工具没有数据库迁移。数据库测试不得使用日常应用库。

已确认业务选择：一次上传只属于一个知识库、同步处理、同工作空间内知识库名称唯一；文件解析后状态 `parsed`，向量索引完成后为 `ready`。文本与 Markdown 是当前已支持的上传类型，不能宣称已支持 PDF。

向量模型已选百炼 `text-embedding-v4`、1024 维；回答与 Agent 决策复用 DeepSeek 官网 `deepseek-flash` 配置。密钥仅在本机配置，不将已配置等同于每种协议都通过真实调用验收。

## 5. 已完成与验收证据

### 阶段 1：RAG 基础与评测工具

已实现资源元数据、单文件保存与 UTF-8 解析、只读存储对账、确定性字符切块、整批事务与重试复用、向量保存、知识库范围检索、生成答案、原文引用与证据不足弃答。外部模型请求放在数据库事务之外。

早期真实联调：五块向量保存和复用成功；六题 RAG 为四个回答、两个弃答。更大公开虚构资料的检索演示有四份文档、29 个候选块，前 5 与前 10 均覆盖正例的五条必需证据。此结果不是全量语义标注 Recall，也不代表复杂语料质量。

离线上下文覆盖、人工审核模板、模型辅助评审、请求快照与两版提示词重放工具已经实现。真实单题模型评审有三项 AI 建议通过，使用 4982 token；没有把它计成人工质量分。

**仍未验收**：六题新真实生成快照、固定同证据的两版真实输出、十六项语义规则逐项核对。六题受控模拟实验不是真实模型实验，质量比例和提示词赢家未知。不要为了收尾补写历史快照或宣称新提示词更好。

### 阶段 2：检索增强

向量基线与可选 `hybrid`：范围内 BM25 和精确向量各取前 20，再按块 UUID 合并，用 RRF 融合；限制 2000 块、100 万正文字符。模型请求前后检查容量与范围。受控场景能验证词项补入候选，历史候选回放不能证明真实全量召回提升。

可选重排：模型返回候选编号的完整排列，映射回原命中再取 top_k。运行故障明确降级为原检索顺序，配置和输入错误分别报错。没有以默认开启重排或新增框架代替实际收益验收。

阶段 2.2 完成时完整后端回归 818 项通过，无跳过，模型使用替身，数据库为独立真实 PostgreSQL。

### 阶段 3：Agent 与工具基础

3.1 有界 Python 循环：注册工具、结构化决策、执行观察、去重、证据快照与预算、完成/停止/失败。`max_steps` 是决策次数，最后一轮工具请求在执行前停止。默认 4、最多 8；只在内存保留运行状态，没有跨请求幂等或恢复。

3.1 的 868 项测试分段验证通过：首次 695 项通过后出现本机数据库 TCP 连接错误；从失败项起复测全部剩余 173 项通过。不能把它描述成一次完整无故障运行，根因未确认。

3.2 默认原生协议：严格单调用、完整 JSON 参数、编号唯一、请求与结果配对、时间和体积界限。旧 JSON 适配器供显式选择，不自动切换。DeepSeek 官网请求关闭思考模式，不保存内部思考。完整回归 921 项通过、无跳过，使用模拟模型与真实独立数据库，没有新增付费调用。

3.3 受限计算器：仅加减乘除，两个十进制原文操作数，整数最多 12 位、小数最多 6 位；除法 8 位半偶舍入。完整原文数字边界核对，派生结果独立记录，不包装成 `GenerationSource`。计算收尾由程序返回算式和输入原文引用，不调用生成模型；末次计算失败则 `failed / calculation_error`。普通问答保持原生成路径和 `/answers` 契约。

3.3 定向回归 263 项通过（71.48 秒），最终完整回归 1011 项通过、无跳过（215.48 秒），本轮新增 90 项。受控脚本及模拟 HTTP 测试验证程序与协议，不代表真实模型已经会选对工具、公式或业务条件。当前尚无真实 Agent 任务成功率，本轮真实模型请求为零。
