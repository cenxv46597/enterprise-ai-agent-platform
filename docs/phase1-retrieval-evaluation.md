# 一阶段：带干扰资料的检索评测草案

> 状态：设计草案。具体新语料尚未生成，本阶段真实 API 尚未运行。

## 小型目标

验证加入干扰资料后，固定数量的检索结果能否包含直接支持问题的证据。
检索证据命中与回答忠实性分别核对，不用引文存在或词语命中代替语义判断。
本阶段仅比较固定 top_k=5 和 top_k=10，不设计自动续检循环。

## 语料与隔离

使用独立知识库，保留既有单文档真实联调的知识库、语料和记录。
既有联调只有 5 个块，top_k=5 会返回全部候选，筛选能力尚未得到验证。
新语料沿用“岚桥知识工作台”的虚构设定，继续明确非真实企业制度。
保留唯一有效的目标事实，加入日志、导出、权限等同产品邻近主题资料。
干扰资料可共享“恢复、文件、令牌”等词，但不能复制、改写或冲突于目标事实。
避免不同版本都合法、不同适用条件未说明的多份答案，减少标注歧义。
完成现有字符切块后，可检索候选块数应明显多于 10，建议至少 20 个。
保持现有 chunk_size=500、chunk_overlap=50，不为题目特意调整切块。

## 固定问题集

沿用已有 4 个可回答问题：服务恢复、上传格式、令牌更换、备份恢复。
沿用已有 2 个应弃答问题：退款申请方式、支付币种。
新干扰资料不得补上这两题缺失的答案；退款到账时限仍不能支持申请步骤。
评测前冻结语料版本和问题，两个 top_k 使用同一版本、同一问题。
正例逐题写清必须保留的事实、条件和操作顺序，标记其直接支持证据。
两条弃答题不以“无证据”为召回分，只记录弃答是否合理、有无编造。

## 两种证据标注

方案一：只标注文档名，检查结果是否命中该文档。
优点是维护简单，不必绑定具体文本或本机数据标识。
缺点是同一文档中的无关块也可能被算作命中，造成假通过。

方案二：标注文档名与支持问题的短连续原文，用原文定位证据。
优点是能区分同文档中的具体支持段落，核对事实依据更精确。
缺点是文档文本修改后必须复核标注，切块边界处还需检查证据完整性。
草案建议采用方案二，直接沿用连续原文标注的思路，不硬编码本机 UUID。
连续原文应足以表达待核对事实，条件和顺序不能为了缩短标注而丢失。
跨块证据须核对返回内容是否共同覆盖必要事实，不因仅含半句就记为完整命中。
同一证据因 overlap 或重复引用出现在多个返回块中，只计一次。

## 固定比较过程

在同一独立知识库中，对每题分别执行 top_k=5 和 top_k=10 的一次检索。
记录返回块的相似度排名、文档名和原文，不把 chunk_index 当作检索排名。
逐条核对预期证据是否完整进入本次结果，再比较两个固定候选量。
若评估回答，每个 top_k 使用对应检索结果生成回答，并记录实际送入的证据。
保持其他配置一致；若上下文预算排除了某块，区分“已检索”与“已送入生成”。
独立人工核对答案中的事实、前提、时限、顺序和关键遗漏，记录无依据扩写。
答案无需逐字复述；与证据相容仍不足以证明该答案受到证据支持。

## 结果与边界

结果按题呈现证据命中事实和人工错误原因，不把生成错误归为检索漏证据。
例如记录：必要证据未进入候选、上下文未容纳、答案遗漏条件或误改顺序。
未完整标注全部相关块之前，不宣称正式 Recall@K；本阶段仅核对预期证据命中。
两条弃答题单独说明证据缺失时的最终行为，不与正例混算召回指标。
重复覆盖同一证据不会提高计数；更细的检索指标和统计口径以后补充。
若未来加入自动续检，再以候选数量或调用预算等明确上限作为停止条件。
当前固定 top_k 比较结束即结束，不推断已检查完整知识库，也不自动取下一批。

按命中文档，还是命中支持问题的具体段落验收？
