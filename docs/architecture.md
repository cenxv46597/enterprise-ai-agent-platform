# 架构设计与已实现的数据流

## 问题与首个使用场景

企业文档往往难以可靠检索。第一条完整业务链路允许本地用户创建工作空间和知识库、上传受支持的文档，并根据检索到的段落回答问题，同时提供可核查的来源信息。

首批数据已选择可公开展示的产品文档或技术文档。具体文档及带有预期答案和来源的问题，将在真实模型质量验收前确定。

## 最小可用版本的范围

- 提供创建和管理工作空间、知识库的接口。
- 支持纯文本、Markdown 和可提取文本的 PDF 入库，并明确记录处理失败。
- 完成解析、确定性切块、向量生成，以及限定范围的精确向量检索。
- 根据证据回答问题，校验文档、页码或章节、文本块的引用；证据不足时明确弃答。
- 建立少量带标注的问题，并编写接口、检索和端到端测试。

这一阶段仅是本地单用户原型。工作空间和知识库的过滤条件用于组织数据，不能代替权限控制。部署给多名用户使用前，必须实现身份认证和权限校验。

## 模块职责

- `api`：验证请求并定义 HTTP 响应格式。
- `core`：管理配置和应用共用行为。
- `db`：负责文档、文本块与向量持久化、数据库会话和结构迁移。
- `knowledge`：负责文档入库与检索业务。
- `knowledge/answers.py`：选择检索证据、生成单次回答并校验引用；持久会话模块留到后续。
- `providers`：以轻量适配层连接模型与向量生成服务。

后续的智能体模块将通过明确的接口调用经过授权的工具，并复用知识检索服务。评测应当调用与正式应用相同的检索、问答和智能体入口。

## 数据流

文档入库：上传并校验 → 保存原文和处理状态 → 解析 → 切块并记录来源信息 → 生成向量 → 将文本块与向量存入 PostgreSQL。

问题回答：问题及工作空间、知识库范围 → 检索相关段落 → 组装证据 → 调用模型 → 对照检索结果校验引用 → 返回回答和引用，或在证据不足时弃答。

当前文档入库与维护边界：

```mermaid
flowchart LR
    A[上传接口] --> B[文档入库服务]
    B -->|先保存原文件| F[本地文件存储]
    B -->|后提交元数据和状态| D[(PostgreSQL)]
    M[手动对账命令] -->|只读存储键| D
    M -->|只读文件名和修改时间| F
    M --> R[输出异常报告]
```

对账用于观察跨存储写入的失败结果，详细取舍见 [ADR 0001](adr/0001-document-storage-audit.md)。当前没有自动补偿或共享事务。

阶段 1.2 已实现的切块保存路径：

```mermaid
flowchart LR
    A[切块接口与归属检查] --> P[整批持久化服务]
    P -->|锁文档行并检查配置| D[(PostgreSQL)]
    P -->|首次读取解析文本| F[本地文件存储]
    P --> S[确定性字符切块纯函数]
    S --> C[编号、内容与字符范围]
    C --> P
    P -->|同一事务保存配置与全部块| D
    P --> R[首次结果或复用已保存结果]
```

上传和切块由两个接口分别触发。切块成功后文档仍保持原状态，没有向量索引。字符范围对应解析文本，设计取舍见 [ADR 0002](adr/0002-deterministic-text-chunks.md)；同配置重试、并发与事务边界见 [ADR 0003](adr/0003-idempotent-chunk-persistence.md)。

阶段 1.3 已实现的向量生成与保存路径：

```mermaid
flowchart LR
    A[向量接口与归属检查] --> S[短事务读取一致快照]
    S -->|释放锁后调用| P[向量服务适配器]
    P --> M[百炼兼容接口]
    M --> V[校验完整向量结果]
    V --> W[短事务锁行并复核快照]
    W -->|全部向量与状态一起提交| D[(PostgreSQL 与 pgvector)]
    S -->|已有完整结果| R[复用结果]
    W --> R
```

真实模型调用期间没有活动数据库事务；读写阶段均按知识库、文档顺序短暂锁行。文档原文和切块配置当前不可原地修改，向量写回前仍核对快照。模型身份固定在知识库中，结果全部提交后才更新为 `ready`。代码已接入百炼 `text-embedding-v4` 的 1024 维兼容接口；本轮选择先进行本地故障测试，真实模型联调待配置。详见 [ADR 0004](adr/0004-embedding-generation-and-storage.md)。

阶段 1.4 已实现的检索路径：

```mermaid
flowchart LR
    A[问题与工作空间、知识库 ID] --> S[短事务共享锁：检查归属、模型和候选]
    S -->|无候选| E[返回空结果]
    S -->|释放锁后调用| P[已有向量服务适配器]
    P --> V[校验查询向量]
    V --> R[短事务共享锁：刷新归属和模型配置]
    R --> Q[SQL 限定知识库、ready 状态和非空向量]
    Q --> K[余弦距离升序、块 ID 升序，再取前 K 段]
    K --> H[文本、来源字符范围与距离]
```

查询向量必须与知识库已保存向量使用相同接口身份、模型和 1024 维配置。模型调用在事务外完成，返回后复核配置；查询不写库。范围筛选先于取前几名，避免其他知识库占满结果后再过滤造成漏检。当前使用精确余弦检索，没有近似索引、阈值或重排；返回的距离不是答案正确率。空库在模型配置依赖正常时跳过外部调用，配置缺失仍返回 `503`。取舍和接口边界见 [ADR 0005](adr/0005-scoped-vector-retrieval.md)。真实向量的召回率和延迟待配置后用标注语料验证。

阶段 1.5 已实现并通过本地故障验证的回答路径：

```mermaid
flowchart LR
    A[问题与指定知识库] --> R[复用范围内检索]
    R -->|无证据| N[200 弃答与空引用]
    R -->|有证据| B[按排名与字符预算选择完整块]
    B --> G[事务外调用回答模型：JSON 草稿]
    G --> V[校验结构、来源编号与连续引文]
    V -->|模型弃答| N
    V -->|合法回答| C[服务端构造引用与解析文本字符范围]
    C --> H[200 答案与引用]
    V -->|结构或引用非法| E[502 安全错误]
```

主题相关不等于证据足够。当前选择生成判断与程序校验，不设置未经语料评测的距离阈值。程序能验证引文存在、引用属于本次传入的证据，不能证明答案在语义上忠于证据。文档按不可信数据处理，尚不能保证抵御所有提示注入。详见 [ADR 0006](adr/0006-evidence-grounded-answers.md)。

向量与回答使用独立适配器和配置，复用现有 HTTP 客户端，不引入编排框架。首个回答模型已由学习者确认使用 DeepSeek 官网的 `deepseek-flash`，基础地址 `https://api.deepseek.com` 已记入配置示例，新密钥本机配置仍待完成。一次回答使用检索已返回的文本快照，无持久会话、版本引用或跨网络请求的数据库事务。本轮已完成本地替身与故障验证，真实模型的回答效果仍待联调。

## 已确定的方案与重新评估条件

### 模块化单体应用

**采用理由：** 单个 FastAPI 应用便于先完成端到端链路，同时保留清晰的模块边界和可测试性。

**代价与调整条件：** 初期文档入库与接口请求共用一个进程。如果实测入库耗时或可靠性问题要求任务独立执行，再引入可靠的后台任务处理进程。

### PostgreSQL 与 pgvector

**采用理由：** 元数据和向量可以存放在同一个数据库中。先使用限定范围的精确检索，建立质量基线。

**代价与调整条件：** 数据规模增加后，专用向量服务或近似索引可能更合适。变更存储方案前，应先测量数据量、召回率和延迟。

### 轻量模型适配层

**采用理由：** 将模型服务特有的请求和响应格式隔离在业务用例之外。

**代价与调整条件：** 在真正接入第二个模型服务，并发现明确的共性需求之前，不设计通用的多服务框架。

## 待确定的设计

工作空间、知识库和文档的字段与基础接口路径已在[数据模型与接口设计](data-api-design-proposal.md)中确认。上传上限默认 5 MiB，首个向量模型、1024 维和精确余弦检索已确认；证据回答与引用校验按 ADR 0006 实施。真实模型质量、引用版本和身份认证仍待后续验收或设计。Redis、LangGraph、MCP、混合检索、重排和前端开发不属于首条完整业务链路的范围。
