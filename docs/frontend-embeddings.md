# 网页第七步：显式预算向量化

2026-10-16，起点 `bffeb3a`。在独立文档处理页接入后端已有的预算向量化接口。

## 目标与既定取舍

对已确认的单份文档及其已有文本块，手动填写本次新生成块数上限，再显式点击“生成向量”，
校验结果并读取最新文档状态。进入页面、刷新、切块均不自动调用向量模型。
本步按学习者“开始下一步开发和讲解”的要求实施；手填预算、整份超限拒绝、不自动重试和超时政策
沿用既有 CLI，不作为新选择再次要求确认。开发与验证只使用模拟响应，未获新的真实模型调用任务与预算。

向量化是将每个已有文本块转换为一个 1024 维数字向量，不重新上传或切块，也不按语义重新分段。
`max_chunks` 是本次请求最多允许新生成的块数，不是金额、Token 或跨请求总费用预算。
本步不接问答、模型选择、配置修改或新框架。

## 预算与提交

`DocumentEmbedding` 管理本地预算输入及结果展示，App 管理实际请求、会话和导航边界。
输入初始为空，必须填写严格整数 1..1000。已解析文档当前确认有 5 块、上限填 3 时，
前端整份阻止提交，不是仅处理前 3 块。后端仍独立检查新生成上限，取用户上限与服务器配置较小值。

最新状态为 `parsed/ready`、已确认非空块数组、无读取错误且空闲时才可提交。
有效提交先清预算输入，保存此次上限用于进行中提示，防止误用旧预算再次点击。
App 同步请求锁防止双击重复提交；向量化期间禁用预算、切块和刷新，保留返回和停止等待。

请求是 `POST /api/v1/workspaces/{workspace_id}/knowledge-bases/{knowledge_base_id}/documents/{document_id}/embeddings`，
必须发送 `{"max_chunks":N}`。复用同源 Cookie、`X-EAAP-Web`、禁止缓存/重定向；
向量化 POST 单独等待最多 330 秒，其他请求仍为 10 秒。停止等待不保证后端停止或没有产生费用。
后端继续核验当前用户、成员关系和父子范围，前端不读取配置、口令或密钥。

## 结果与核对

仅 HTTP 200 且文档 ID 匹配、状态 ready、维数严格 1024、块数为 1..10000 的整数、
模型名合法、`reused` 为真实布尔值时可继续确认；App 还核对返回块数与本次已确认的文档块数一致。
不保留或直接展示任意后端错误正文。

- `reused=false` 时返回块数不能超过本次预算，显示“向量结果已保存”。
- `reused=true` 时允许结果块数超过本次新生成上限，显示“复用已有结果”。
  预算限制新生成，不限制已经保存的完整结果。
- 后端数据库结果可复用，但并发请求可能先调用模型、再发现另一请求已经保存；
  `reused=true` 不能证明这次零费用，也不保证外部模型只调用一次。
- 确认向量化结果后单独 GET 同一文档的最新详情；读取失败不抹掉已确认的结果，
  显示最新状态未确认，继续写入前需刷新核对。最新状态按 GET 返回展示，不由前端强改 ready。
- 401 清理会话与全部资源状态。403、404、409、422 显示固定安全拒绝文案，
  尤其不把 409/422 等同于没有费用。发出后的网络、超时、取消、5xx、其他异常状态或无效成功响应，
  统一为“向量化结果未确认”，可能已调用模型或保存结果，不自动重试。

未确认、拒绝或停止等待后，清理最新详情与块确认状态；必须显式刷新详情和块记录、重新填写预算，
才允许再次提交。整组 GET 成功后清除旧的未确认/拒绝提示，不伪称之前 POST 已成功；
保留历史已确认结果。退出中断向量化但退出失败时，返回页面仍提示未确认，不恢复旧预算。
返回、切换文档、退出或固定登录期限到期都取消等待并隔离迟到响应，浏览和向量化不续期。
