# 演示第四步：对已有文本块生成向量

本轮位于资料入库主线的最后一环：上传并解析 → 保存文本块 → 生成并整批保存向量 →
文档 ready，可参与检索。向量是文本的数字表示，用于比较问题和段落的相关程度；
ready 不代表任意问题都能回答，知识问答客户端仍待下一步接入。

## 接入范围

`backend/scripts/browse_demo.py` 新增独立 `--embed` 操作，必须同时给出
`--max-chunks N`（1..1000）。它与上传、切块互斥，默认仍只浏览，不自动读配置或密码文件。
登录、选择空间/知识库后，再按名称选一份已有文档；客户端不重传原件、不重新切块。
尚未解析成功的文档在 POST 前停止；没有已有文本块时后端拒绝。

向同一完整范围下的 `POST /documents/{document_id}/embeddings` 发送
`{"max_chunks":N}`。新增可选请求体，字段为严格正整数，拒绝额外字段。
有效新生成上限取本次 N 与服务器配置的较小值，复用既有服务在模型调用前的块数检查；
整份文档超限就拒绝，不是只给前 N 块生成向量。无请求体的旧客户端仍按原服务器上限，
并不因此获得本次显式预算保护。没有数据库迁移。

已有全部向量且配置兼容时可复用，返回 `reused=true`；此时结果块数可以超过 N，
因为上限限制的是本次新生成。后端向量状态和保存逻辑未改写。
并发请求可能各自调用模型后才发现另一请求已保存，因此 `reused=true` 不能证明本次零费用。

## 超时与费用边界

本次核心问题中，学习者选择“停止重复提交，先查状态”，并判断超时不能认定后端失败；
理由由导师补充：客户端没收到完整响应不等于后端停止，后端可能仍执行或已经保存。
这是确认方案和正确判断，不记为独立完整理由或本人代码实现。

向量化 POST 的读取等待单独设为 330 秒，连接、写入和其他请求仍为 10 秒。
后端配置允许整轮模型等待预算最高 300 秒，但它不是整个 API 的严格结束期限；
330 秒也不保证完成，客户端取消不保证后台中止。

超时、网络故障、中断、5xx 或无效成功响应均不自动重试，提示结果未确认。
409/422 只提示核对状态、配置及块数上限，不把拒绝等同于“未产生费用”。
成功响应核对文档 ID、ready、1024 维、块数及复用标记后，再 GET 同一文档的最新状态；
若 GET 失败，分别说明成功响应已校验、最新状态未确认。

预算单位是一次后端请求允许新生成的文本块数，不是人民币、Token 或跨请求总费用。
后端按配置每批 1..10 块串行调用向量服务，无自动重试；8 块最多 8 次模型 HTTP 请求，
默认每批 10 块时为 1 次，不能把默认值当成本机当前配置。失败也可能已有部分批次费用，
但不会保存这一轮部分向量。不保证并发下外部计费恰好一次。
