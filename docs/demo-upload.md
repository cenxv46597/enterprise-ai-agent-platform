# 演示第二步：向选中的知识库上传文档

本轮接上“企业资料入库”主线。登录和空间/知识库选择沿用已有客户端，只有显式指定
`--upload` 才发送一次文件上传请求；默认运行仍为浏览。后端已有的上传、解析接口不变。

## 本机操作

保持 Docker 中原数据库容器健康、后端运行。从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe backend/scripts/browse_demo.py --username demo_a --upload examples/knowledge/retrieval-eval/demo-export-records.md
```

隐藏输入 `demo_a` 的已有密码，按名称选择目标空间和知识库。`--upload` 后面的路径是
客户端要读取的本机文件；脚本把文件名和文件字节作为 multipart 的 `file` 字段发送。
请求携带登录得到的 Bearer Token，服务器再次检查成员关系和父级范围。

客户端先检查文件可读取、非空、为常规文件，后缀为 `.txt`、`.md` 或 `.pdf`，最多
5 MiB；它保存这份有界字节快照，上传时使用相同内容。服务器仍独立执行校验，可能
按自己的配置拒绝超限文件。密码文件和应用配置不会被自动读取。

## 结果怎么理解

接口正常创建记录返回 HTTP 201，但解析结果由 `status/error_code` 表达：

- `parsed`：文件记录已创建、解析完成；客户端显示“已解析，尚未可检索”，然后列出文档。
- `failed`：文件记录已创建、解析失败；显示安全原因并以非零退出码结束，记录仍可浏览。
- 参数、文件类型、空文件或大小不符合要求时，服务器会返回对应的 4xx 拒绝。

客户端还核对返回的知识库 ID、文件名、大小和摘要是否与本次文件相符。上传本身不会
切块、生成向量、调用模型或变成 `ready`；这部分在后续步骤接入。

每次上传都可能创建一份新文档，同名同内容也没有自动去重。超时、断线、上传中断、
5xx 或无法确认的成功响应会提示“上传结果未确认；未自动重试”。先用不带 `--upload`
的命令浏览文档核对结果，再决定是否重传；客户端不会自动再次发送上传 POST。
