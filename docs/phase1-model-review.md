# 阶段 1.9：离线模型辅助评审

## 1. 当前目标

复用已保存的公开六题问答，由可选评审模型按现有检查项提出判断、理由与对应片段。代码与模拟故障验证已完成；初次开发没有真实调用。随后经学习者授权完成一次[真实单题评审](evaluation/model-review-first-case-2026-10-11.md)，不把模拟结果当作模型效果成绩。

## 2. 为什么需要

不要求有人逐句转换全部企业文档，也不在每次问答中等待人工审批。少量固定题集用于比较生成策略；模型辅助评审用于提高批量检查效率。这对应自动化评测、模型接口抽象、故障处理和可追溯实验等岗位能力。

## 3. 核心概念

- 向量模型负责检索相关资料，不能把距离接近当作条件一致。
- 评审模型读取问题、原文、答案和检查标准，输出建议；它也可能误判。
- “答案不通过”是一次成功执行的质量判断；超时和非法输出表示评审失败，质量结论仍未知。
- 人工质量比例、AI 建议通过比例、审核覆盖率与技术失败数分别记录。
- 固定问题、证据、模型参数和提示词版本，才能解释对比实验。温度设为 0 可减少采样波动，不保证结果完全确定。

## 4. 设计与取舍

方案一是离线批量评审：不增加用户问答延迟，适合当前六题规模，不能在每次返回前拦截语义问题。方案二是在线生成后评审：可以参与返回决策，但增加费用、延迟和失败链路，仍不能保证判断正确。当前选择方案一，沿用 Python、Pydantic、httpx，不增加数据库表、任务队列或服务。

评审使用独立配置，允许用户主动配置为与回答模型相同的服务，但不自动借用生成密钥。相同模型可能具有共同盲点；AI 判断没有经人工校准之前，不作为独立正确率。

旧报告未保存实际生成上下文。本轮只能对照固定公开完整文档复核，不能据此证明回答只使用当时选中的证据，也不能当作带干扰知识库的新问答成绩。

## 5. 实现与数据流

1. `prepare` 复用现有来源校验，绑定原报告、题集、原文和审核标准，生成评审任务。
2. 所有任务与调用上限先通过校验，再允许读取评审配置。
3. `CompatibleReviewProvider` 使用共用 JSON 请求层，但与生成模型保留不同的业务契约。
4. 模型不能填写人工身份；程序设置 AI 辅助标记，核对检查项集合、答案绑定及逐字片段。
5. `run_batch` 将执行失败与质量失败分开，失败题不阻止后续题，也不自动重试。
6. 报告记录模型、提示词版本与摘要、任务摘要、已知 token 用量和逐题耗时；费用没有计价规则，记为 `null`。
7. 发请求前排他创建新报告，执行前和每题结束后更新记录。已有输出不覆盖，原始报告和人工模板保持原样。

检查点能够保留正常调用间中断前已写完的结果；当前原地刷新文件不是原子替换，写入途中进程崩溃仍可能导致报告不完整。运行状态为“运行中”时不能把它当作完整实验。尚未实现续跑。

## 6. 如何验证和使用

在仓库根目录只规划，不读取 `.env`、不连接数据库、没有模型调用：

```powershell
.\.venv\Scripts\python.exe backend/scripts/review_answers.py --plan
```

只规划一题及一次调用上限：

```powershell
.\.venv\Scripts\python.exe backend/scripts/review_answers.py --plan --case-id restart_recovery_steps --max-cases 1
```

真实执行前在本机 `.env` 设置 `EAAP_REVIEW_BASE_URL`、`EAAP_REVIEW_API_KEY`、`EAAP_REVIEW_MODEL`。基础地址不包含 `/chat/completions`；使用支持 JSON 模式的兼容接口。密钥不发到聊天或 Git。建议首轮只运行一题；下面命令会产生模型请求和可能的费用：

```powershell
.\.venv\Scripts\python.exe backend/scripts/review_answers.py --run --case-id restart_recovery_steps --max-cases 1 --report docs/evaluation/model-review-first-case.json
```

退出码：`0` 为所选题执行成功，允许模型判断答案不通过或无法判断；`1` 为批次完成但至少一题执行失败；`2` 为来源、计划、配置或文件处理错误。服务返回“待审核”时不计 AI 已完成分母；超时也不计答案不通过。

AI 建议通过比例的分母是已完成判定的题目；AI 审核覆盖率的分母是本轮选中题目。只选一题时，不能把这一题的比例推广为全部六题或整个系统。`new_model_calls` 记录 provider 调用尝试数，包括执行中或失败的调用，不代表供应商计费次数。

复用相同测试环境，可单独运行：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests/test_review_http_provider.py backend/tests/test_model_review_cli.py -q
```

模拟接口只能验证契约和故障处理，不能证明真实模型能发现语义错误。验证记录见[本轮说明](evaluation/model-review-2026-10-11.md)。

## 7. 学习与小实践

本轮代码由 AI 导师实现，不能记作学习者亲自完成或已掌握模型评审。

打开 `test_one_timeout_does_not_fail_quality_or_stop_remaining_cases`，先预测三题中的第二题超时后：第三题是否调用、AI 已完成数是多少、超时题的 `ai_pass` 应为何值。再把超时题改成第一题，修改对应断言并执行专项测试。重点是解释质量未知和执行失败的区别。

面试练习逐题进行：技术失败是否应算答案错误；同一个模型生成和评审可能有什么共同盲点；只评审部分题目时怎样报告分母和覆盖率。本轮先讨论第一项。
