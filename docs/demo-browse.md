# 首版演示第一步：登录并浏览企业资料

这一小步位于首版演示与交付主线：通过已启动的 HTTP 后端，登录一个已有账号，选择
工作空间和知识库，再查看文档的处理状态。完成条件是这条调用顺序可以复现；后续再
接上传、问答、引用和执行轨迹。当前没有前端页面。

## 在本机运行

使用已安装依赖、已完成迁移的开发环境。客户端不会运行迁移、注册或分配旧空间。
当前演示账号 `demo_a` 和 `demo_b` 已完成注册与对应空间授权。

从仓库根目录在一个终端启动后端，并保持它运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

在另一个本机交互终端，从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe backend/scripts/browse_demo.py --username demo_a
```

按本机私有凭据中的密码登录，终端输入隐藏，不会显示星号或文字；随后按显示编号选择
工作空间和知识库。密码只能在这个终端输入，不放进命令参数、聊天或 Git。本机原有
随机演示密码保存在被忽略的 `.env.demo-accounts`，客户端不会读取该文件。

后端使用其他本机端口时，可以加 `--base-url http://127.0.0.1:8001`。本入口仅接受
本机 loopback HTTP 地址，不接受远程地址、地址内凭据、额外路径或查询参数。

## 这一流程为什么这样连接

1. `POST /api/v1/auth/login`：账号密码换取短期 Token，只保留在客户端内存。
2. `GET /api/v1/auth/me`：携带 `Authorization: Bearer ...` 核对当前用户身份。
3. `GET /api/v1/workspaces`：取得后端按成员关系过滤的列表，显示编号供选择。
4. 根据选中空间 ID 查询知识库，再根据选中知识库 ID 查询文档。

编号只是客户端显示位置，实际请求使用返回的 UUID。客户端不直接读取数据库；每次
业务请求的身份和权限由后端检查。它与未来前端采用同样的接口调用方式。

每层只展示第一页，最多 20 条，不自动选中或遍历其他空间。满 20 条时会提示可能还有
更多记录，不把当前页当总量；空列表是正常结果。文档显示五种已有状态的中文含义，
不读取正文或触发处理。`parsed` 表示已解析，`ready` 才表示可检索。

## 验证范围与下一步

该客户端只有登录 POST 和资料浏览 GET，没有上传、资源写入或模型调用。HTTP 故障、
无效响应、身份/父级错配和无效选择会停止；不输出响应全文、原始异常、密码或 Token。
禁用环境代理和自动重定向，凭据不会随自动跳转发往另一地址。

程序专项使用 HTTPX MockTransport 模拟接口，检查请求顺序、范围、分页、凭据传递与
安全输出，不连接数据库或模型。这是客户端程序验证；实际本机 HTTP 演示需要按上面的
步骤运行并核对结果，不能据模拟测试声称真实联调已完成。

2026-10-14，客户端专项 **20 项通过、无跳过（0.51 秒）**，`--help`正常；未重跑
