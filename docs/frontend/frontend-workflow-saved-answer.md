# 网页第十六步：显式查看工作流已保存答案

2026-10-18，起点 `ccac1c3`，接续[有限生成失败恢复](frontend-workflow-recovery.md)。
本次只复用工作流、文档详情和分块的GET，不改后端、数据库迁移、账号或owner关系，无新增依赖。

## 目标与交互选择

解决网页等待执行结果超时、但后端可能已经保存完成答案后的查看需求。
仅限本页已确认创建、仍保留任务指针的工作流；不接任意UUID、列表、URL或刷新恢复。
比较A“先读状态，再单独查看答案”与B“读状态直接展示答案”，学习者确认A。
理由、协议校验、主体实现与模拟测试由导师完成，选择A不记为独立完整设计。

完成流程：手动读取当前状态→确认为completed→单独点击“查看已保存答案”→
重新GET同一任务并核对保存快照→核对全部来源文档及选中原文块→整批展示答案与完整引用。
读取状态本身仍只展示元数据，不查询来源或展示正文，不自动发起查看。

## 已保存结果与执行回执

新增独立 `WorkflowSavedAnswer={workflow,answer}`，不包含执行requestId或attemptNumber回执字段。
任务元数据中的attemptCount仍是已有保存记录，不是本次查看新执行了一次。
保存结果证明本次读取接纳了该任务的已有结果，不能确认先前超时请求的精确执行回执、外部调用次数或费用。
原创建、首次执行、有限恢复的请求快照与未知结果提示保留，不借只读查看再次提交或解锁写入。

completed的元数据必须来自本模块真实成功GET；WeakMap保存独立的元数据、完整检查点及答案依据。
复制或修改公开元数据、只拿执行回执元数据、没有先读状态，均不能直接调用新查看路径。
即使GET因任务变化而显示“暂停写入”，只要本次读取合法completed，仍可查看；写入锁与只读入口分开判断。

## 查看时怎样核对

1. 再GET同一工作流，复用完整结构、范围、原问题、vector策略、冻结预算、状态/阶段、
   版本、尝试数、检查点与逐字引用校验，包括已校验的距离、分数及排名字段。
2. 与刚读取的私有快照核对元数据、检查点所有选中块的顺序/身份/全文/字符位置及完整答案。
   同版本但内容变化也拒绝，不把新内容静默当成先前快照。
3. 按全部唯一来源文档GET详情，核对文档ID、知识库归属、文件名、ready。
   再GET该文档完整分块，按块ID核对文档ID、块编号、完整正文、开始和结束字符位置。
   包括最终未被引用的候选块，不能只检查引用列表或“块数相同”。
4. 任一项失败，整次查看不显示答案或引文；全部通过才作为纯文本一次展示。

合法空检查点的正常弃答无需来源GET；仍要求完成结构、弃答及空引用一致。
块列表沿用最多10000块、合计10Mi字符、连续编号及Unicode码点范围校验。
GET没有返回向量内容，因此不声称核对了非空embedding；多个GET也不是跨请求原子快照。
本路径只核对已选来源，没有全知识库重检索、重新生成、语义质量审核或实时监控。
读取时通过不保证资料以后不变。

## 等待、失败与会话边界

工作流GET、每个文档/分块GET各沿用10秒等待；不是整条链路严格总时限。
pending同步锁覆盖整个查看链路，阻止等待期间重复点击。
开始查看时清除旧的答案正文与旧回执正文，避免新核对失败时仍展示旧内容；请求快照不清除。
任一失败或主动停止后清本次正文和可查看状态，需先重新手动读取状态，才允许下一次只读查看。
手动重读状态也立即清除此前保存答案，不自动继续查看。

401清登录，404清受保护结果；其他错误显示固定说明，不回显原始detail。
取消、返回、退出、固定到期及来源等待时迟到响应，沿用取消信号和请求序号隔离。
退出失败也不能使被中断查看的迟到正文复活。
所有新增请求均GET，不访问模型，不发execute/recover，不生成新请求编号或恢复执行回执。

ADR0030固定30分钟、恢复不续期、退出只清当前浏览器Cookie继续有效。
日常库0010不变，真实检索、实际等待到期及历史未完成验收均不恢复。
