# 上传成功后直接进入文档处理

2026-10-22。学习者要求回到企业知识库问答主线并继续开发。本轮主体设计、实现、测试和运行由导师完成；本人实践及面试讨论尚未开展。

## 业务场景与完成条件

企业知识库上传文件后，需要查看解析结果，手动切块，再决定是否生成向量供问答引用。现有文档列表按创建时间升序只读第一页20条；若已有20条，刚上传的第21条即使成功解析，也不在列表。本次上传结果卡此前只提示成功，无法从那里进入处理页。

完成条件：仅对已确认201且状态为`parsed`的上传结果显示“继续处理这份文档”；点击后按已核对的文档ID打开现有处理页。列表第一页没有该记录，或上传后的列表刷新失败，仍可继续。入口不再次上传、不自动切块、生成向量或调用模型。

## 方案与实现

比较过扩大列表、把新记录插入第一页、使用上传结果中已确认的ID。扩大列表增加无关传输且仍有数量边界；插入第一页会破坏列表的排序、计数和分页含义。本轮选择按ID进入，不改列表接口或后端。

`DocumentUpload`只在`confirmed + parsed`时显示按钮。列表刷新中按钮禁用；刷新报错后上传仍已确认，按钮可用，但原上传输入仍禁用。`failed`、`unconfirmed`、`rejected`均无此入口，尤其不能把结果未知的上传当作成功。

`App`点击时重新检查会话、当前工作空间和知识库归属、文档所属知识库以及请求忙状态，随后清除本次上传结果并复用`openDocument`。原有`readDocument`按ID依次GET最新文档详情和文本块，响应仍校验ID与父级范围。详情或块读取失败时，处理页不开放切块；401清会话，返回、退出、到期及迟到结果继续由请求序号和取消机制隔离。上传结果只用于定位，不直接当作最新详情。

本步位于“上传解析 → 查看文档 → 手动切块 → 显式生成向量 → 引用问答”主线。`parsed`表示解析成功，尚不可检索。真实候选检索和模型调用继续暂停。
