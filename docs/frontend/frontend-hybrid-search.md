## 业务目的与方案

员工的问题可能带有错误码、版本号或明确文字线索，单纯语义接近不一定把这些证据排在前面。
独立检索页增加“向量检索”“混合检索（向量＋词项）”，由用户显式选择再提交，保留默认向量基线。
不把混合方式设为默认，也不对同一问题自动各跑一次：当前没有本轮真实质量比较或费用证据。
混合未必更好，中文双字等词项也可能带来主题噪声；先开放可解释的选择和候选，后续效果验收另行授权。

复用[ADR0014](../adr/0014-bounded-hybrid-retrieval.md)已有后端，不新增检索算法、服务、数据库迁移或依赖。
网页仍固定返回最多3个候选、`rerank=false`，没有重排或生成答案。
本轮只接独立检索页；网页引用问答、会话和工作流的原策略不随此下拉框改变。

“词项”指用于文字匹配的基本片段。本项目后端评分时归一化全半角与大小写，
中文连续片段取相邻双字，英文/数字及下划线错误码等保留完整词项；不是中文词典分词或同义词理解。
两路各从当前知识库符合ready且向量非空的块中独立取前20，以同一块ID合并。
词项路能补入未进入向量前20的块，但仍依赖该块已有向量和本次问题向量，不能当成不需向量服务的降级通道。

## 请求与提交快照

进入页面、输入和切换方式均不请求。点击“检索”才发送一次当前空间/知识库的`POST .../search`：

```json
{"query":"问题快照","top_k":3,"strategy":"hybrid","rerank":false}
```

API在末尾追加默认`vector`参数，旧调用保持原请求形状；非法策略在发送前拒绝。
页面结果绑定已提交问题和经核验的响应策略，之后修改问题或下拉框只改变下次提交的草稿，不能改写旧结果标签。
新提交清旧候选，单请求控制覆盖POST与全部来源GET；等待中禁重复提交和切换，允许停止等待/返回。
默认方式随检索页卸载清理，不持久化到URL、服务器或浏览器存储。

检索范围仍是当前整库全部可检索文档，不限文档列表当前页、文件名/状态筛选或刚处理的文档。
页面同时提示该选择只影响本页，引用问答仍使用向量检索。

## 结果校验与解释

向量结果须对应`vector/cosine_distance`，余弦距离有限且位于0..2，结果按距离非递减。
混合结果须对应`hybrid/reciprocal_rank_fusion`，与本次请求相同；不能把另一种策略的响应当作确认结果。
两种方式均拒绝非空顶层重排信息及非空`retrieval_rank/rerank_rank`标记（省略/null仍兼容），
保持最多3个、模型/1024维、块唯一、名称/范围/正文总量校验。
全部唯一来源文档GET核对归属、名称和ready后才展示候选，任一失败不展示部分结果。
这仍不是逐块重新读取数据库原文或替代后端授权，也不保证候选足以回答问题。

RRF为倒数名次融合：每个入选通道贡献`1/(60+名次)`，同一块两路贡献相加。
避免将余弦距离与词项BM25原分数直接相加，因为二者量纲和排序方向不同。
本次前端核验融合得分为正有限数、降序、通道名次为null或1..20整数且至少一路存在，
并以1e-12绝对容差核对既有固定公式的自洽；保留后端顺序，不在浏览器重排。
BM25原分数未用于本页展示或作为额外公共字段投影。

页面展示本次方式、融合得分（6位小数）、两路名次及余弦距离（4位小数）。
混合按融合得分从高到低，不要求距离升序；距离仍越小越接近，但不决定本次排列。
通道名次null显示“未入前20”，不是第0/21名，也不能推断完全无关或没有向量。
所有这些分数和名次都不是答案正确率；文本仍转义展示并只预览前300码点。

## 限制与故障

混合上限为2000个可检索块、100万正文码点，超限拒绝，不静默截取前半知识库。
后端在问题向量调用前及等待后都复核规模，因而422不能证明没有向量调用或费用。
网页422只给固定提示：参数或处理量可能不符合要求，说明混合上限，允许用户手动调整或换方式后重新提交；
不读任意服务端detail，不宣称本次必然超限，不自动退回vector或重试。

空候选仍是已确认检索结果，不等于空库、没有相关资料或零费用。
未知故障/来源失败仍未确认；401、退出、固定登录期限及迟到响应复用原隔离。
停止等待仅取消浏览器等待，不承诺后端停止或零费用；不因新方式延长会话。
