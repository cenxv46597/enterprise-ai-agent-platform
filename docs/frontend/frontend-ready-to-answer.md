# 可检索文档进入当前知识库引用问答

2026-10-22。上一小步补齐“上传成功→进入文档处理”，本人完成讲解后的实践与两题讨论并要求继续。本轮只补文档处理页与现有引用问答页之间的手动入口。

## 场景与完成条件

用户为文档切块并确认向量结果后，详情页显示“可检索”，但目前必须先返回文档列表才能进入“引用问答”；新文档如果不在第一页，这一步尤其绕路。完成后，处理页在**最新读取的文档状态为ready**、文本块确认非空、页面无错误且无请求进行中时，显示“前往当前知识库引用问答”。此前已ready的文档也可使用，不必重新生成向量。

比较过依据“本次向量化成功”结果卡与依据最新文档详情。成功响应后仍会单独读取详情；后续读取可能失败，或者状态随后变化，旧成功卡会继续留在页面。因此用最新详情与已确认块来决定是否开放入口，既能避免旧提示误导，也覆盖打开时就已ready的文档。

## 实现边界

按钮文案明确目标是**当前整个知识库**。现有问答接口只有工作空间、知识库及问题参数，没有单文档范围；后端从知识库内可检索资料取候选。ready表示这份文档可以参与检索，不保证它会被本次问题召回，也不保证答案正确。

`DocumentProcessing`仅为ready显示该入口，请求忙、块列表未确认或错误时禁用；`App`点击再核对会话、当前空间/知识库、详情与所选文档ID、ready、非空块及请求状态，清理文档处理上下文并复用已有`openAnswer`。打开问答页、填写问题都不会发送问答请求；只有本人再点“生成回答”才使用既有`POST /answers`。列表的通用问答入口仍允许在当前页没有ready文档时使用，因为当前页不代表整库。

本轮不修改后端、数据库、向量生成或回答服务，不开展真实检索、生成、模型重试或Cookie到期等待。验证只使用模拟请求。
