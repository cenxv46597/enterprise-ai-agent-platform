# 引用问答失败的排错编号：2026-10-18

## 修改、原因与实际场景

后端已在每次HTTP响应头返回 `X-Trace-Id`。本轮让独立“引用问答”页在原有安全失败提示旁展示合法编号，
便于用户反馈失败时提供编号，开发者据此定位对应的请求摘要。该编号本身不包含根因或业务结果。

可一次接入全部页面，也可先接一个完整业务链路。沿用每次一个小环节的约定，导师先接引用问答页，
覆盖其生成POST及后续来源文档元数据GET的HTTP状态错误；其它页面、登录页和本地校验错误展示不扩展。
此范围由导师依既定约定收拢，不记为学习者另行确认过UI方案或独立设计。

## 实现与边界

- `ApiError` 增加只读 `traceId`，默认null；`AnswerUnconfirmedError` 支持透传。
- 仅从实际错误响应的 `X-Trace-Id` 取值，要求完整36字符UUID4，大小写规范成小写。
  拒绝无效值、多值和末尾换行；不信错误JSON中的编号、不在前端生成、不回送到请求头。
- 共享request在HTTP非成功或违反expectedStatus时保存该响应编号。非预期成功状态保留原有 `status=null` 分类，
  只增加排错元信息，避免更改既有文档/切块调用契约。
- 引用问答独立POST对已知拒绝和其它非200状态读取自身编号；后续来源GET错误只透传那次GET的编号。
  成功POST A→成功GET B→失败GET C时，只能显示C；C没有合法编号也不回退A或B。
- 200非法JSON/正文、来源身份/名称/ready状态不匹配等前端语义校验，本轮没有响应元数据envelope，保持无编号。
  网络失败、超时、取消与请求前校验同样不补造编号。
- 编号附在同一个失败 `AnswerOutcome` 中，不创建全局“最近编号”状态，不写localStorage或日志文件。
- 在安全失败提示内以普通文本及code元素展示编号，保留未确认/拒绝语义，不展示原始后端detail或回答正文。
- 开始新的有效提交、取消等待、返回/重新进入、身份失效均沿用原有清理与迟到响应保护。
  发起退出时清除旧失败编号，退出失败后也不恢复它；401仍先清身份，不为显示编号延缓跳登录。

本页既有来源确认是逐条文档元数据GET，不是工作流“查看保存答案”的完整文本块核对。
本轮未增加chunks请求，也不提升原有引用正确性保证。
新的前端本地校验不生成编号；若旧结果仍在，其编号只属于该旧结果，不会变成新校验提示的编号。

没有显示编号，不证明请求没到达后端、未执行或未产生费用。显示编号同样不证明执行成功。
本轮不自动重试，不解锁结果未知操作，不把编号当业务request_id、权限凭证或可信执行回执。
会话、工作流、上传、检索等其它页面尚未展示编号；共享错误模型的扩展不等于全站接入。
