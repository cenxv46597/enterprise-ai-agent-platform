## 目标与交互选择

选择一份本地文件，核对目标工作空间、知识库、文件名和大小，点击“上传”后才发送。
学习者选择 A：先选择再显式上传；B 为选择文件后立即发送。此处只记录方案确认，
检查目标和文件的理由由导师说明，不记学习者已独立解释或完成代码实践。

本步到创建文档记录和同步解析结果为止，切块、显式预算向量化及问答仍分步接入。
支持 TXT、Markdown、PDF，网页前置上限为默认 5 MiB，后端仍独立执行实际配置限制。
UTF-8 文本或 PDF 正文是否能解析由后端判定，不把文件扩展名当作内容有效的保证；无 OCR。

## 调用链与结果边界

`DocumentUpload` 管理本地文件选择和输入提示；App 管理上传请求、结果和会话生命周期。
只选择文件不发送请求。点击提交会清空文件选择，上传期间禁用选择、上传和刷新，
同步请求锁防止重复提交；完成后需要重新选择文件才能再次上传。

调用 `POST /api/v1/workspaces/{workspace_id}/knowledge-bases/{knowledge_base_id}/documents`，
无尾斜杠、无列表查询参数；FormData 的 `file` 字段传文件名与实际字节，
由浏览器生成 multipart boundary。复用同源 Cookie、`X-EAAP-Web`、禁止重定向及缓存的请求选项。
服务端继续核验用户、工作空间成员及父子范围，前端文件校验不替代授权。

前端从所选文件字节计算 SHA-256，只确认状态码 201 且文档 ID、知识库、规范文件名、
字节大小和摘要与本次上传相符的响应。结果只保留必要展示字段，丢弃其他响应字段：

- `parsed` 且无错误码：记录已创建，文字已解析，尚未可检索。
- `failed` 且有错误码：记录同样已创建，展示固定安全的解析原因；未知码使用通用说明。
- 401 清理登录、资源选择、文件和上传结果；403、404、413、415、422 显示明确拒绝的安全提示。
- 发出后的网络故障、10 秒超时、取消、5xx、其他未知状态或无法核对的成功响应，均为结果未确认。

未确认沿用已有 CLI 策略，不自动重试：后端分阶段提交且没有上传幂等键或内容去重，
即使浏览器没收到结果，文档也可能已经创建。提供“停止等待上传结果”，不声称撤销了后端写入。
用户应先核对记录；如决定再次上传，需重新选择文件并显式点击，可能产生重复记录。
文件读取或散列期间也检查取消信号，避免停止等待后又发出迟到请求。

## 本次结果与第一页列表

后端文档列表按创建时间、ID 升序，网页只读前 20 条。新记录不一定出现在第一页，
因此独立展示“本次上传结果”，不把新记录硬插进当前页或修改当前页计数。
确认 `parsed` 或 `failed` 后都刷新列表；列表刷新失败仍保留已确认结果，401 则按会话失效清理。
未确认后允许显式刷新核对，但第一页没有新记录不能证明上传失败。

返回知识库会取消等待并清理上传上下文；导航、退出和固定登录期限到期沿用请求序号及取消隔离。
退出期间隐藏上传区，退出失败若中断过上传，返回页面保留“上传结果未确认”，不会恢复旧文件选择。
恢复、浏览和上传均不延长原登录期限。

### 逐题面试讨论

- 第一题：学习者正确选择“文档已经创建，但解析失败”，并独立说明 HTTP 201 代表创建成功。
  导师补充记录创建与解析是两个阶段，`failed` 不表示记录不存在。
- 第二题：学习者正确选择用文档 ID 定位，并独立解释文件名可能重复。
  导师补充界面可显示文件名，操作绑定对应 ID，后端仍需校验当前工作空间与知识库范围。
- 第三题：比较读取列表与上传超时后的重复请求，学习者初答不清楚。
  导师解释重读列表不会新增文档，而上传可能已创建、仅响应丢失，再传可能创建重复记录。
  学习者在已给定两次都创建成功的后续场景，正确指出会出现两份新记录。
  记录为讲解后能应用重复创建的后果，不记独立解释完整重试策略或幂等设计。
