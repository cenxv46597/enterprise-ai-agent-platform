# 网页第十步：显式创建会话与首条消息

2026-10-17，起点 `bd8b06f`。沿用现有会话后端和日常库 0010，
本步只接知识库内创建会话、一次首条知识消息及结果展示，不新增后端、迁移或模型框架。
前一步的实现与学习收尾见[独立引用问答页](frontend-answers.md)。

## 小目标与交互方案

业务链路为：文档列表→会话问答→显式创建→确认空会话→发送首条消息→展示本轮结果。
比较 A 先创建再发送与 B 首次发送自动创建并发送，学习者确认 A。
两次写入分别确认的理由由导师说明，记录为选项确认，不记独立完整交互设计。

当前知识库全部可检索资料参与会话，不限于文档第一页。当前页零份 ready 不阻止进入。
文档读取、上传、退出或列表错误期间入口禁用。
本步仅处理首条消息；继续补充、显式执行、新任务、文档状态模式与工具轨迹留到后续小步。
不会自动发送第二条消息，也不把待补状态当作完成。

## 两次写入与三层状态

1. `POST /conversations`，无请求体、无幂等键、无需模型。
   仅 HTTP 201、合法会话 ID、版本 0、idle、空任务、空近期消息和空计费结果可确认创建。
2. 用户手动输入去空白后 1..2000 个 Unicode 码点，发送一次该会话的 `POST /messages`。
   浏览器生成并在内存保留本次请求 UUID、预期版本 0 和正文快照；固定请求为：

```json
{
  "request_id":"本次UUID",
  "expected_version":0,
  "content":"本次消息",
  "mode":"continue",
  "confirm_billing_rule":false,
  "response_mode":"knowledge"
}
```

不先请求 `/search`、`/answers` 或 `/agent-runs`。
后端会话、运行、业务完成三层含义不同：HTTP 200 可包含运行失败或停止；
普通知识回答完成后外层仍可 idle；ready 是输入齐备，不代表业务已执行完成。
本次初始版本 0 的第一条 knowledge 消息只能产生 idle 或 waiting_for_user，
不能套用其他已恢复会话的 ready/completed 响应。

网页严格绑定会话 ID、请求 ID 和响应版本 1，再区分：

- `run.completed`：接纳答案/弃答，要求 reply 与结果答案一致，正常回答保留完整引用。
- `run.waiting_for_user`：展示当前待补对象、单位、整数范围、规则原文及来源。
  支持旧单整数与标准计费的次数/月数两个待补字段，不根据“全年”推断12个月，不自动补充或执行。
- `run.failed/stopped`：承认该轮消息已保存且运行未完成，显示固定安全说明，
  不展示原始错误或冒充正常弃答，也不当作网络结果未确认。

首轮现有 Agent 也可能调用算术工具。网页保留已执行算术数量的说明，不声称已核验算术明细。
步骤、指标、偏好和计算明细未在本页展示；不把它包装成完整工具轨迹或工作流完成。

## 引用与规则来源

复用已有知识问答的答案/引文接纳规则。引用还必须绑定本轮 run.evidence 的块、文档、序号和范围。
待补条件的 1 基证据编号绑定 task.evidence，任务引用须与运行引用一致；
首条消息的确认输入应为空。标准计费同时核对两个条件和计划的规则、费率单位及来源元数据。

全部唯一引用/规则来源均通过当前空间、知识库路径 GET 文档详情，核对 ID、名称及 ready 后，
才展示答案、规则或待补条件；任一来源失败，整轮展示结果未确认。来源 GET 的401清理登录。
公开 evidence 不含块正文，网页来源核对不能宣传为再次逐字校验原文或证明语义正确。
答案与规则按 React 文本渲染，完整引文不按检索预览截短，不解析 HTML 或显示内部 UUID。

## 未确认、读取和取消

创建和消息是两次独立写入。一旦本页发起创建，禁用再次创建；一旦发起首条消息，
禁用再次发送。同步 pending 锁覆盖 POST 和全部来源 GET。

- 创建未确认：可能已有空会话，但未取得可信 ID；不自动再次创建或发送消息。
  返回后重新创建仍是新的明确操作，可能留下另一份空会话。
- 消息未确认：保留已确认会话 ID、原请求编号/版本/正文，不自动重放或换编号重试。
  用户可点击“读取当前会话状态”，只发送 GET。
- GET 只接纳当前 ID、版本及状态元数据，不展示近期消息为已验证答案。
  它没有逐轮请求编号或完整引用，不能证明本次请求已提交；版本未变也不能证明原运行已停止。
  读取不会解锁第二次发送，不覆盖原本已确认或未确认的首轮结果。

创建 POST、状态 GET 和各来源 GET 分别最多等待10秒；消息 POST 浏览器等待预算为2430秒，
覆盖本步有界运行的较长等待，不是后端总时限或 POST 与所有来源核对的严格链路总时限。
现有首轮最多四次决策、三次工具执行及一次最终生成，各外部请求有各自上限；实际次数与费用不能由浏览器计时推算。
登录仍按原固定30分钟到期，通常会比消息等待预算更早取消页面等待；操作不续期。

停止等待不保证后端未创建、未执行、未提交或未产生费用。
返回、范围切换、退出和登录到期沿用取消信号与请求序号隔离迟到响应。
退出中断操作但退出失败时，保留相应创建/消息/读取未确认状态；迟到结果不能恢复旧内容。
HTTP401清理全部身份及页面状态；403/404/409/422用固定安全提示，不回显任意 detail。
其他状态、无效成功响应、断网、超时或来源失败按对应阶段未确认处理，不自动重试。

## 持久化范围与参与记录

刷新或重新挂载后清理所选会话，不自动创建、发送或恢复旧会话。
本步没有会话列表、按 UUID 读取或 URL 恢复；不能因服务端持久化就宣称网页刷新恢复已完成。
