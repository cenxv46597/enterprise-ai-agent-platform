## 场景与方案

员工不仅要查看候选段落，也希望针对带错误码、版本号的问题选择混合方式生成带引用的回答，
并把本次问题、提交方式、答案与引文一起留存，防止事后把另一种草稿方式记到旧答案上。
问答页增加独立的向量/混合选择，默认vector，top_k3、rerankfalse不变；切换不请求，点击“生成回答”才提交。
独立检索页与问答页分别选择，进入任一页面不继承另一页草稿或复用其候选预览。

复用已有`POST .../answers`，后端自身按所选策略检索、选择完整块上下文、生成并核验引用。
不先发`/search`，不自动先试一种再试另一种，不启用重排、自动重试或工作流执行。
混合只改变候选的选取/排序，不取消证据预算、逐字引用校验或证据不足弃答。
范围仍为当前知识库全部可检索文档，不限文档列表页、文件名/状态筛选或刚处理的文档。

## 请求快照与回执的区别

真实后端`AnswerRead/AnswerResult`不回传策略，且共享结果被会话、工作流等路径复用。
比较新增后端策略回执，或只记录前端提交参数，本轮选后者；不为页面标签改动共享答案契约。
`answerKnowledgeBase`追加默认vector的第五参数，使用现有SearchStrategy及校验，旧调用仍发原请求。
`parseKnowledgeAnswer/KnowledgeAnswerResult`完全保持原形状，不把请求参数伪造成服务端响应字段。

App把提交的问题、strategy与通过原有校验的result保存到同一个confirmed outcome；新字段明确叫`submittedStrategy`。
页面与TXT均显示“本次提交的检索方式”，不显示成“已验证的实际执行方式”。
这能确认前端给该次请求记录了什么参数，不能单独证明服务端全过程、模型实际调用或真实费用。
后端当前确实转发payload.strategy的代码经只读确认，不等于本轮执行过真实模型任务。

后续改问题/下拉框仅影响下次提交；新提交先清旧结果。
来源读取成功、失败、停止、关闭和导出提示更新均保留同一答案的提交方式；导出只读confirmed，不能读取当前草稿。
返回、切库/空间、401、退出和原登录到期清理原结果，重进问答默认vector。

## 来源、故障与导出

原答案/弃答结构、Unicode引文、文档身份/归属/名称/ready及全唯一来源核验继续保留。
所有来源自动核对完才显示答案与引文；正常200弃答可展示并导出，HTTP故障不是正常弃答。
手动查看完整来源仍只做GET；局部来源失败可保留原已确认答案和提交方式，导出不追加检索/生成。
问答POST等待630秒、来源GET各10秒，取消只停止浏览器等待，不保证后端停止或零费用。

hybrid的422可能来自问题、参数、上下文预算或混合处理量，提示保持这些可能原因，
说明混合2000可检索块/100万正文字符上限与未知费用；不读detail，沿用失败HTTP自己的合法排错编号。
不把422推断为一定超限、没有调用或正常弃答，不自动降级vector或重发。
选择器在生成、来源读取、退出期间禁用，原请求锁、取消信号和操作序号覆盖全链。

导出输入必须显式包含`submittedStrategy`，格式函数用共享白名单校验；缺失/非法时抛固定安全错误，
在创建下载资源前失败，不猜测或默认写vector。
TXT新增该次提交方式及“仅记录本次提交参数，不等于服务端实际执行证明”的说明。
继续只导出已确认问题/答案/完整引文与必要来源标识，不序列化账号、来源预览、排错字段或未提交输入。
正文没有自动识别/脱敏隐私。BOM、固定文件名、URL回收与下载失败保留答案规则不变；
提示请求浏览器下载不证明落盘，文件也不是服务器问答历史。
