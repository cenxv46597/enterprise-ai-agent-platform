# 历史页查看已保存答案的排错编号：2026-10-19

## 修改、原因与完成条件

接续[历史列表与状态编号](frontend-workflow-history-trace.md)，本步只扩展工作流记录页的“查看已保存答案”。
一次查看会再次GET工作流、逐个GET选中文档及完整文本块，可能在任一请求失败。
为了按编号找到真正失败的请求，保留各次失败响应自身的合法UUID4，不沿用前面成功请求的编号。
不采用“最后收到的任意编号”兜底，避免把成功步骤指认为失败步骤；沿用已有安全错误提示。
完成条件是多来源归属正确、失败不展示部分答案、生命周期不串、只读与完整来源核验保持原样。

## 实现与边界

- workflow-api的stage=answer-read为非预期HTTP状态保留自身响应编号，原状态分类/中文文案不变。
- 来源getDocument/listDocumentChunks已有ApiError编号；外层WorkflowUnconfirmedError包装时继续传递，
  仅保留实际失败错误对象的traceId，不从成功工作流、前一来源、错误JSON或异常字符串补取。
- 来源401/404继续直接抛出原安全ApiError；其他失败维持原未核验语义并保留诊断元信息。
  来源201仍保持既有status=null并带该响应编号，工作流GET的非预期201则保留status=201，不混改旧接口分类。
- 历史页savedAnswerNotice改为message/traceId同对象，复用ReadNotice，包括本人上步添加的用途提示。
  编号只在“已保存答案（只读）”区域显示，不写进列表或状态错误，不作为答案、引用或任务字段。
- 列表重读、任务切换、状态重读清旧提示；保存答案读取开始清旧结果。失败清completed读取依据及正文，
  必须先重新读状态再查看；停止/退出/到期/返回及迟到结果沿用原abort与请求序号保护。
  退出尝试立即清保存答案错误编号，退出失败不恢复旧编号或显示退出请求编号。

200后的坏JSON、任务快照/文档状态/来源全文块不匹配，网络失败、取消、超时及非法/缺失头都不补造编号。
全部选中来源（含未引用候选块）核对通过才展示整份答案；本步没有放松ID/归属/编号/正文/字符范围核对，
也不增加跨请求原子快照或语义正确性保证。不把HTTP失败当作数据库保存答案必然丢失。
创建工作流页面的保存答案提示仍是原有文案；共享函数能携带元信息不等于该页已接编号展示。
创建/执行/恢复阶段仍未接编号展示，历史页不自动重试、轮询、执行或恢复，不调用模型。
ADR0030继续有效；无本地存储或新增凭据，未接集中日志查询平台。
