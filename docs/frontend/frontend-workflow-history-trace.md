# 工作流记录页的列表与状态排错编号：2026-10-19

## 修改、原因与完成条件

工作流记录页原来仅展示安全错误文字。用户反馈列表或详情加载失败时，缺少对应HTTP排错编号。
本步沿用引用问答页的规则：编号放在所属错误下方，从实际失败响应头读取并校验，不使用全局最近编号。
完成条件是两种GET失败可定位、文字与编号对应、生命周期清旧且迟到响应不串、历史页仍只读。

## 实现与边界

- `api.ts` 导出既有responseTraceId，仍只接受36字符UUID4、规范为小写；无效、合并多值或读取头失败为null。
- `workflow-history-api.ts` 只为非预期200的列表响应附编号，保持原安全文案与状态分类，不读取失败正文。
- `workflow-api.ts` 仅在stage=read且HTTP状态非预期时，给ApiError/WorkflowUnconfirmedError附编号。
  readAnswerWorkflow解析200正文失败没有编号；创建、执行、恢复、保存答案查看的request阶段未接编号。
  共用状态读取函数的其他调用方可收到该元信息，但本步只有历史页列表和状态提示展示。
- `WorkflowHistoryView`的listNotice/readNotice由字符串改为可空的message/traceId对象；App一次保存对应错误与编号。
  页面用code纯文本展示合法编号，不回显错误JSON、异常原文、工作流/业务编号，也不向请求头回送编号。
- 新读列表清旧列表/选择/正文与两种提示；选任务或重读详情清旧详情提示及正文。
  取消/超时后无编号，迟到结果受abort和请求序号保护；返回、401、到期清历史页。
  退出尝试立即移除两类编号，退出失败不把旧读取或退出HTTP编号混回提示。

成功响应上的编号不作为任务字段展示，也不沿用成功列表编号给后续失败详情。
无响应、无合法头、200后JSON/业务契约校验失败均不补造编号或从错误正文提取。
本步不展示保存答案/来源核验失败、创建/执行/恢复或其他页面的编号，不改变原有源块核验和任务门控。
任务记录自身的errorCode表示此前执行结果，与本次读取请求traceId不同；业务failed状态可以由成功GET读出。
历史页仍手动GET，不自动重试、轮询、执行、恢复；ADR0030固定30分钟、恢复不续期、退出只清当前Cookie。
未新增本地存储、持久Token、复制/反馈上传功能或集中日志平台。
