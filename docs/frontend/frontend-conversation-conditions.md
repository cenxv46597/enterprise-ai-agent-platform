# 网页第十一步：逐项补充条件，输入齐备后暂停

2026-10-17，起点 `f1400b1`。本记录接续[显式创建会话与首条消息](frontend-conversations.md)。
此前文档里的“尚不提交补充条件”是当时阶段状态；本步复用已有后端继续消息接口，不改后端或数据库。

## 目标与选择

本步完成：首问等待补充→手动填写当前整数→确认保存→下一项→输入齐备。
比较 A 数值输入与固定单位/范围、B 自由文本由后端保守解析；学习者确认 A。
理由与实现由导师提供，不能据此记录为独立设计或实现。

网页使用 `inputMode="numeric"` 的受控输入，严格只接纳规范十进制整数；
采用文本控件保留原始键入值，避免数字控件对指数、小数等写法的隐式处理。
不接纳空白、负数、小数、指数、前导零、汉字或混填单位。次数允许0，计费月份为1..12。
字段标签、单位和范围来自已确认待补任务，提交时显式拼接为如 `3次`、`2个月`。
不会根据“全年”推断12个月，也不会把次数与月份混为一项。

## 请求和保存回执

沿用当前知识库内 `POST /conversations/{id}/messages`：

- 每个字段由用户手动提交，创建新的请求 UUID；使用上一个已确认 POST 的版本。
- 固定 `mode=continue`、`confirm_billing_rule=false`、`response_mode=knowledge`。
- 保留本次请求编号、预期版本、数值、字段标签和单位的内存快照。
- 请求成功码必须为200；回执须绑定当前会话、本次请求与旧版本加1。
- 只接纳 `run=null`、`billing_result=null`、无回答偏好更新的条件保存回执。
- 原问题、全部来源、字段顺序、范围、单位和规则保持一致；仍复用标准计费计划校验。
- 逐项核对 `confirmed_inputs`：旧输入不可变，本次只能增加当前字段及本次数值、单位、
  请求编号、原提交文本与 `user_message` 来源标记。
- 尚有字段时必须为 `waiting_for_user` 且无执行标记；填齐时必须为 `ready`，
  并明确 `execution_deferred=explicit_execution_required`。

保存回执接纳后，重新通过当前空间/知识库路径核对全部唯一来源文档的ID、名称、ready状态。
包含任务保留的非规则候选来源，不只核对当前规则引用。规则和候选的来源标签继续分别处理。
任何来源未完成核对时，隐藏旧规则和可提交表单，不能提前显示下一字段。
公开来源不含块正文；网页核对不等于再次逐字核对原文，也不能证明规则适用或语义正确。

支持原有单整数任务与次数/月数双字段任务；旧任务补齐一次即可ready。
后端仍独立校验和写入数据库。本步不会发送execute、新任务或单次检索/回答请求。
首问原本可能执行过算术，原有算术次数提示保留；“尚未执行计算”指补齐后的待办未被显式执行，
不能扩展为整个会话从未调用算术或从未产生外部费用。

## 异常与持久化边界

补充 POST 最多等待10秒，来源 GET 各自有已有等待上限，不是整个链路的严格总时限。
网络故障、超时、非预期状态、不匹配回执、来源失败及主动停止后，保留提交快照并暂停后续补充。
403/404/409/422只展示固定安全说明；401清理身份与页面。不会回显后端任意detail。
数值已由本页本地校验，若后端200没有增加预期输入，也不能假装接受；保守归入结果未确认并暂停。

手动GET只显示状态元数据，不恢复可提交任务，不解锁未知补充的重发。
发现版本或状态与已确认任务不同会暂停补充；GET404清除旧受保护内容。
返回、退出、固定到期沿用取消与请求序号保护；迟到回执不能恢复旧任务。
停止浏览器等待不能保证后端没有保存。Cookie仍固定30分钟、恢复不续期、退出只清当前浏览器Cookie。

会话指针和回执只在页面内存；刷新恢复、会话列表、精确请求回执恢复仍待后续。
ready仅表示输入齐备。页面保留已确认数值，取消“当前待补”标记且不再提供补充按钮，
明确显示“输入已齐备，尚未执行计算”；业务估算、规则适用确认、工具轨迹和工作流恢复另分小步。
