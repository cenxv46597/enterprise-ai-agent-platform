# 开发路线图

这份路线图同时记录计划和完成证据。列入计划的功能，不代表已经实现。

## 阶段 0：工程基础

1. **0.1 架构：** 明确问题、首版边界、模块数据流和技术取舍。已完成。
2. **0.2 后端基础：** 初始化本地 Git，记录设计决策，加入配置、FastAPI 健康检查和接口测试。已完成。
3. **0.3 接口与元数据层：** [数据模型与接口设计](data-api-design-proposal.md)的关键选择已确认：一次上传只属于一个知识库，首版同步处理，同一工作空间内知识库名称唯一。本轮接入 PostgreSQL、Alembic，建立 `Workspace`、`KnowledgeBase`、`Document` 元数据表及基础资源接口；从空数据库检查迁移和约束。`Chunk` 与向量表留到阶段 1。

## 阶段 1：可测量的 RAG 首版

1. 按[阶段 1.1 设计](phase1-document-ingestion.md)接入纯文本与 Markdown 的单文件同步上传，解析成功标记为 `parsed`。2026-10-10 使用真实 PostgreSQL 完成全部 52 项测试，并在临时空数据库验证迁移与模型一致性；可提取文字的 PDF 留到本阶段后续小步。
   - 架构实践补充：新增手动、只读的文件与数据库对账命令及故障注入测试，见 [ADR 0001](adr/0001-document-storage-audit.md)。自动清理、补录与重试仍未实现。
2. 阶段 1.2 已实现确定性字符切块和 PostgreSQL 整批持久化；学习者选择了“文档 ID + 块编号”唯一规则。上传后通过独立接口触发切块，同配置重试复用原记录、配置变化明确冲突。真实数据库验证覆盖并发、故障回滚和输入上限，当时完整回归为 119 项通过、无跳过；临时库通过迁移、降级后再升级与模型一致性检查。见 [ADR 0002](adr/0002-deterministic-text-chunks.md)、[ADR 0003](adr/0003-idempotent-chunk-persistence.md)。事务故障与重试练习已进行。
   - **1.3 向量生成与保存：** 已完成代码、故障验证和首次真实调用。学习者选择百炼 `text-embedding-v4`、1024 维；已有文本块通过独立接口整批保存向量，完成后标记 `ready`，同配置重试复用结果。2026-10-10 当时完整回归为 213 项通过、无跳过，模型接口使用模拟 HTTP，数据库使用真实 PostgreSQL/pgvector。本机库升级到 `20261010_0004`；临时库验证旧数据保留和升级、降级后再升级。随后真实演示的五块向量保存与复用均成功，详见 [ADR 0004](adr/0004-embedding-generation-and-storage.md)。
   - **1.4 向量检索：** 已实现知识库 `/search` 接口，复用 PostgreSQL/pgvector 精确余弦距离。学习者选择先限定知识库再取前 5 段，避免其他知识库占满结果后再过滤造成漏检。查询仅包含 `ready` 文档的非空向量，返回文档名、块 ID/编号、文本、字符范围和距离；模型调用在事务外，前后复核归属与完整模型配置。新增 49 项检索测试，当时完整回归为 262 项通过、无跳过，使用控制向量和真实数据库验证排序及故障；首轮真实检索已接通并记录延迟，更大语料的 Recall@5 和语义质量仍待验收。见 [ADR 0005](adr/0005-scoped-vector-retrieval.md)。
   - **1.5 基于证据问答：** 已实现独立生成协议、兼容 JSON 模式适配器及知识库 `/answers`。无证据或模型按契约判断不足时正常弃答，程序校验来源编号和逐字引文，再返回真实文档、块及引文位置。新增问答 45 项、生成 HTTP 71 项，当时完整回归 378 项通过、无跳过。学习者选择 DeepSeek 官网的 `deepseek-flash` 并完成本机配置，随后首轮真实六题验证成功。加入联调脚本保护测试后，最新完整回归为 399 项通过、无跳过。见 [ADR 0006](adr/0006-evidence-grounded-answers.md)。
3. 已使用可公开展示的虚构产品文档和 6 个标注问题完成首次真实链路验证：4 个回答、2 个弃答，保存逐字引用与单次延迟。详见[联调报告](evaluation/live-rag-smoke-2026-10-10.md)。原演示只有 5 个文本块且全部返回，暂不报告 Recall@5。
   - **1.6 带干扰资料的检索评测：** 按学习者选择，用支持问题的具体原文验收，见 [ADR 0007](adr/0007-evidence-level-retrieval-evaluation.md)。已实现纯覆盖计算、执行脚本、公开题集与独立演示知识库。2026-10-10 使用 4 文档、29 候选块真实运行 6 题；同一次前 10 响应的前 5 与前 10 均覆盖 4 正例的 5 条必需证据，2 负例排除评分。新增 54 项规则与脚本测试，最新完整回归为 453 项通过、无跳过。详见[评测结果](evaluation/retrieval-eval-2026-10-10.md)。本次未生成答案，扩大语料后的忠实性、弃答与完整相关性指标仍待验证；下一步检查实际送入生成的证据与答案质量。
4. 根据证据生成回答、校验引用；缺少证据时明确弃答。
   - **1.7 上下文证据覆盖：** 2026-10-11 已抽取共用的完整块选择函数，离线回放真实检索快照，比较 2 种候选量、3 种预算，共 36 条选择记录。检索覆盖不变，而上下文覆盖随预算为 2/5、4/5、5/5，见[报告](evaluation/context-eval-2026-10-11.md)。共享函数抽取后完整回归 482 项通过、无跳过，随后新模块 30 项专项通过。没有新增模型调用或策略优化；下一步核对生成答案是否保留必要事实、条件和顺序。
5. 从空数据库运行全部迁移，并完成上传、检索和端到端测试。

## 后续阶段

- **高级 RAG：** 混合检索、查询改写、重排、引用质量和对比评测。
- **智能体：** 先理解并实现有步数上限的循环、状态、工具注册与选择，再考虑使用 LangGraph。
- **高级智能体：** 记忆、MCP、多步骤工作流和失败恢复。
- **生产工程：** 身份认证、角色权限、确有需要时加入 Redis，以及追踪、限流和部署。
- **评测、前端和简历材料：** 以实际实现和测量结果为依据逐步补充。

## 学习与开发节奏

按完整小模块推进：一个核心设计问题、一次代码或故障验证、一组必要测试、一次本地 Git 提交。已理解的基础概念在真实代码中复习。每个模块以可运行能力验收，优先完成首条知识问答闭环。

2026-10-11 起，每个模块先展示修改、验证结果、待提交文件和提交信息，由学习者确认后才执行本地提交与 GitHub 推送，见[版本管理约定](github-workflow.md)。
