# 开发路线图

这份路线图同时记录计划和完成证据。列入计划的功能，不代表已经实现。

## 当前进度与接下来的主线

目前可以演示本地知识问答闭环：创建工作空间和知识库，上传 TXT/Markdown，保存文件并解析、切块，调用百炼生成向量，按知识库检索，再由 DeepSeek 回答并返回引用，证据不足时弃答。文件对账、事务回滚、幂等重试、检索覆盖和离线评测工具也已有实现。当前仍是本地单用户后端，工作空间范围检查不等于身份认证或权限控制。

阶段 1 的业务链路已接通，剩余验收是采集六题实际生成输入、完成两版真实输出和语义核对。首次六题联调成功说明链路可运行；它不能代替提示词效果比较，六题质量结论仍未知。离线工具的测试数量用于说明验证范围，不用于计算整个项目的完成百分比。

接下来按完整能力模块推进：

1. **收拢当前验收：** 固定六题与已有十六项规则，提供全选计划、缺失快照提示和零网络模拟。本轮不继续拆出新的评测阶段，也不自动更换线上提示词。
2. **混合检索：** [阶段 2.1](phase2-hybrid-retrieval.md)已实现可选词项评分与 pgvector 名次融合，保留各路排名和来源；采用有界 Python 基线，比较取舍见 [ADR 0014](adr/0014-bounded-hybrid-retrieval.md)。真实独立两路召回收益与延迟仍待验收。
3. **重排：** [阶段 2.2](phase2-candidate-reranking.md)已接入可选生成模型排列、完整编号校验与可见降级。真实质量、延迟和成本仍待对比验收；保留纯向量基线，查询改写仅在出现具体漏检问题时加入。
4. **智能体与工具：** [阶段 3.1](phase3-knowledge-agent.md)已有有界循环、只读知识工具、故障观察与轨迹；[阶段 3.2](phase3-native-tools.md)接入原生调用；[阶段 3.3](phase3-calculator.md)接入原文绑定的受限计算器和可复现多工具任务。基础部分已完成程序与协议验收，真实模型任务质量与持久恢复未完成，未使用 LangGraph。
5. **记忆与 MCP：** [阶段 4.1](phase4-conversation-state.md)已实现 PostgreSQL 会话、结构化追问、整数补充与有界近期决策上下文；[阶段 4.2](phase4-sourced-calculations.md)新增用户条件引用、有界链式算术与显式恢复执行；[阶段 4.3](phase4-standard-billing.md)增加两个条件、有限单位与固定标准估算流程；[阶段 4.4](phase4-answer-preferences.md)显式有限答复偏好已完成程序回归和应用库 0008 升级。[阶段 4.5](phase4-mcp-search.md)自建只读 MCP Server、官方 SDK Client、工具白名单及原文整批回验已完成程序验收，见 ADR 0019–0023。不能把普通算术完成当业务成功、标准估算当实际账单或有限设置当通用长期记忆。2026-10-12 学习者独立区分任务条件与持久偏好，并明确跳过本次白名单小实践；设置/清除实践、逐题面试及真实风格/忠实性验收仍未完成，不据此阻塞后续主线。MCP 目前仅接入单次 Agent、固定本地 stdio 与知识搜索；未开放删除、远端服务或任意命令，真实非空向量/模型链路质量待验收。长期记忆扩展以明确需求为前提。
6. **首版补齐与交付：** 知识库列表接口已按简单分页小步接入，验证状态见学习记录；文档/工作空间列表与可提取文字的 PDF 解析仍待。随后完成身份认证与权限、部署、前端和演示材料。缓存、限流及更完整的追踪按实际瓶颈推进。

## 阶段 0：工程基础

1. **0.1 架构：** 明确问题、首版边界、模块数据流和技术取舍。已完成。
2. **0.2 后端基础：** 初始化本地 Git，记录设计决策，加入配置、FastAPI 健康检查和接口测试。已完成。
3. **0.3 接口与元数据层：** [数据模型与接口设计](data-api-design-proposal.md)的关键选择已确认：一次上传只属于一个知识库，首版同步处理，同一工作空间内知识库名称唯一。本轮接入 PostgreSQL、Alembic，建立 `Workspace`、`KnowledgeBase`、`Document` 元数据表及基础资源接口；从空数据库检查迁移和约束。`Chunk` 与向量表留到阶段 1。

## 阶段 2：检索增强

**2.1 混合检索已实现。** 搜索与问答接受 `strategy="hybrid"`，默认向量基线保留。范围内就绪块分别进行 BM25 与精确向量排序，各取前二十，按块 ID 合并并融合名次；最多处理 2000 块和 100 万正文字符，调用问题向量前后检查容量。没有新增依赖、迁移、重排或真实模型调用。

定向 119 项通过。受控数据库场景将正确错误码资料放在向量第 21 名，混合结果补入到第 2；这是程序行为验证。历史六题前十候选内回放，原排序与融合前五均覆盖五条必需证据，不能据此宣称完整混合召回提升。下一完整模块是候选重排，保留真实策略对比为待验收项。

阶段 2.1 完成时的完整后端回归为 **767 项通过、无跳过（198.25 秒）**，使用独立数据库和模拟模型，覆盖混合实现及恢复后的六题工具。没有新增真实模型调用。

## 后续阶段

**3.1 知识智能体已接入。** 一次 `/agent-runs` 请求支持决策、搜索、观察与结束。默认最多四次决策、上限八次，重复参数停止；证据池按块 UUID 合并并限制数量和字符量。正常完成、受保护停止与技术失败分别返回，复用已有原文引用校验。仅有一个知识工具，动作使用 JSON，不是服务商原生工具调用。状态与轨迹未持久化，真实任务成功率未测量，没有新增模型服务调用。

阶段 3.1 版本全部 **868 项测试已分段验证通过**：首次 695 项通过后遇到本机数据库 TCP 连接错误；从失败项开始复测全部剩余 173 项通过。数据库为独立真实 PostgreSQL，模型为替身，没有跳过未验证测试，单次完整运行曾失败的记录保留。

**3.2 原生工具调用已实现。** 默认原生协议，通过同编号 `assistant/tool` 消息回传成功或固定错误；保留旧 JSON 适配器供显式选择，不自动切换。控制器持有每次运行的历史，新增编号、配对、单调用、JSON 歧义、总期限与体积验证。没有新增依赖、迁移、真实模型调用。后续受限计算器和多工具程序验收已在阶段 3.3 完成。测试证据见[阶段 3.2](phase3-native-tools.md)。

阶段 3.2 最终完整回归 **921 项通过、无跳过（219.87 秒）**，包含本轮新增的 53 项协议、运行与 API 测试。使用独立 PostgreSQL/pgvector 与受控模型；没有新增模型费用，改动仍在本地。

**3.3 原文绑定计算器已实现并通过程序验收。** 每个输入包含本次证据编号、一个完整数字的逐字引文与十进制字符串，程序核对来源、数字边界与值。支持两个数的加减乘除，除法最多八位小数、半偶舍入；结果独立保存并确定性生成算式与输入引用，末次计算失败未恢复时明确失败。暂不支持单位换算、百分数、指数或计算结果继续作为操作数。定向 **263 项通过（71.48 秒）**，最终完整回归 **1011 项通过、无跳过（215.48 秒）**，本轮新增 90 项。没有新增真实模型调用，真实工具和公式选择仍待验收。详见[阶段 3.3](phase3-calculator.md)、[ADR 0018](adr/0018-evidence-bound-calculator.md)。

### 对话接续约定

学习者确认在当前 Agent 与工具部分完成后新开对话。基线收尾标准为：有界循环、工具注册、原生调用、知识搜索与计算器两个受限工具、可复现多工具任务及必要验证。当前已达到该标准，本轮收尾提醒学习者并提供[接续摘要](handoff-agent-tools.md)；不自动创建任务或提交代码。基线功能完成不代表真实质量、持久记忆、MCP 或整个企业平台完成。

**2.2 候选重排已接入。** 搜索与问答通过 `rerank=true` 显式启用，默认关闭；先召回 `candidate_k` 段，模型一次返回完整编号排列，然后选最终 `top_k`。模型调用在事务外，原文总量最多两万字符。超时与输出异常返回原顺序并标记降级；配置缺失和输入超限报错。没有新增依赖或迁移，也没有新增真实模型调用。真实排序收益待验收，下一开发模块是有步数上限的智能体与知识工具。

阶段 2.2 完成时完整回归 **818 项通过、无跳过（198.35 秒）**，使用独立 PostgreSQL/pgvector 与模拟模型，覆盖当时可选重排、混合召回与全部既有后端功能。定向回归 158 项通过；当轮没有付费模型调用，今天修改未提交或推送。

- **高级 RAG：** 混合检索真实收益验收、重排、按漏检需要引入查询改写、引用质量和对比评测。
