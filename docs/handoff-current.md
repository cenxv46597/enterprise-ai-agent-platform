## 2. 项目目标与当前位置

目标是本科实习求职项目：企业知识与工作流智能体平台。主要面向企业员工查询制度、
产品资料、技术文档和 SOP，并完成有证据、有工具、有状态的多步任务；最终能演示、
测量效果，并在面试中解释设计和取舍。

核心 AI 后端已经建立，目前进入权限与首版交付阶段。业务主线始终是：

企业资料入库 → 员工提问 → 检索与引用回答 → 缺条件时追问 → 工具/工作流处理 → 保存状态。

学习者最近感到方向不清，明确希望每轮先说明“位于哪条主线、完成条件是什么”，改动
范围保持可理解，同时避免大量零碎提问和无必要重复测试。不能以测试数量计算完成率。

## 3. 已实现的能力及边界

- **资料入库：** TXT、Markdown 和可提取文字 PDF 上传，保存原件、解析、确定性切块、
  PostgreSQL 持久化和 1024 维向量生成。PDF 上传与首次切块共用解析函数，原件只保存
  一份；默认 5 MiB，PDF 另限 100 页、1,000,000 个提取字符。没有 OCR 或 PDF 页码引用。
- **RAG：** 知识库范围检索、基于证据回答、逐字引用校验和证据不足弃答。可选 BM25/
  向量检索、RRF 融合和候选重排，故障可见降级；真实策略收益仍待验收。
- **Agent：** 有步数上限的显式循环、工具注册、原生工具调用、重复动作保护、执行轨迹。
  现有知识搜索和受限计算工具；未使用 LangGraph，也没有任意工具执行能力。
- **会话与计算：** 数据库保存会话、结构化待补字段及有界近期上下文；“三次”可绑定
  到正在等待的上门次数并跨请求恢复。原文双数值计算器、用户条件/先前结果引用计算器、
  固定标准计费是不同能力。标准估算须补齐次数与计费月数、显式确认规则适用，再由程序
  执行固定公式；不代表真实账单或通用政策验证。
- **显式偏好：** 知识库级 concise/detailed/null 设置，版本化更新/清除；不自动从聊天
  抽取，无 TTL，成员共享。它不是个人私有记忆或通用长期记忆。
- **只读 MCP：** 自建固定本地 stdio Server、官方 SDK Client（`mcp==2.3.0`）、工具
  白名单及 Host 整批原文回验。单次 Agent 可选 MCP 搜索；与 rerank 同用拒绝。没有
  删除、远端 MCP 或任意命令，Server 本身不验证用户身份。
- **固定问答工作流：** 独立创建/读取/执行接口，检索→生成两个固定步骤、持久检查点、
  来源复验和失败恢复。执行权/版本/900 秒租约保护写回，最多五次尝试；不恢复任意
  Agent，不保证外部模型费用恰好一次。
- **资源管理：** 工作空间、知识库、文档三级列表；有界分页，文档状态在数据库内先
  过滤再分页。管理列表可显示 failed，检索仍只使用 ready 且向量非空的块。
- **身份代码：** 注册、登录、当前用户；Argon2id 密码哈希与 30 分钟 HS256 JWT；每次
  HTTP 请求读取用户和成员关系，再沿用原有父子范围校验。未登录 401，非成员 404；
  创建者原子成为 owner，只有 owner 可添加已注册 member。

身份首版仍有明确限制：member 可以调用已有下级写入/模型接口，不是只读角色；会话和
偏好尚未按员工私有隔离；未实现完整 RBAC、公开注册限流、密码重置、刷新/撤销令牌。
本地空签名密钥会生成临时值，重启需重新登录；生产要求私有配置至少 32 字符密钥。

## 4. 日常应用库与尚未回答的选择

上轮只读核对的日常应用库仍为 `20261012_0009`，含两个历史演示工作空间：
“RAG真实联调演示”和“检索评测演示”（实际名称还有演示后缀）。本次交接整理未重新
连接数据库；下一对话应私下核对实际版本、空间 ID 和必要计数，不输出连接地址或口令。

`20261013_0010` 已在代码中，但尚未应用到日常库。它只新增用户和成员表，不自动认领
旧空间。学习者还没有回答两个空间由同一账号还是不同账号持有，也没有指定用户名。
不得凭猜测把历史资料分给新注册者。

正确接续顺序：

1. 确认两个旧空间的计划所有者用户名和范围；不要求在聊天中提供密码。
2. 核对日常库和迁移，按确认的过渡方案受控升级到 `0010`；保留旧表、文件与数据。
3. 指导学习者在本机注册账号。`0009` 没有 users 表，不能在迁移前直接调用注册 API。
4. 对明确指定、完全无成员的空间运行 `python -m app.auth.assign_owner`；不要从公开
   HTTP 接口自动接管空间。若已经有成员，该命令会拒绝再次认领。
5. 验证登录、本人空间列表、原资料访问、跨公司拒绝和 owner 邀请。
6. 完成一个小实践与 2–3 道逐题面试后，收拢身份模块。

原有空间在 `0010` 后、成员关系建立前会对登录用户不可见，接续时必须解释并安排
完整过渡，不能把“代码已写好”等同于“日常应用已完成部署”。

- 全套运行在 871 项通过后，旧文档断言失败：不存在/无权访问的 workspace 被入口
  guard 返回“工作区不存在”，旧预期仍为“知识库不存在”。已按新契约修正测试。
- 修正后整份文档接口 **28 项通过（73.01 秒）**；尚未执行的后半段 **825 项通过
  （259.17 秒）**。前段与文档专项重叠 16 项，覆盖当时 1708 个不同测试。
- 随后新增本地空密钥启动测试，最终身份专项 9 项包含它；当前 1709 个节点均有对应
  通过记录。**没有单次连续 1709 项全绿运行，也没有本轮所有最终代码的一次全量成绩。**
- 更早单次完整 **1646 项通过（633.72 秒）**是阶段 4.6 历史基线，不覆盖之后的新代码。

身份反例已验证匿名拒绝、篡改/过期令牌、跨工作空间访问、owner 邀请、列表先按成员
过滤再分页；甲的令牌访问乙的检索/问答/MCP Agent/会话/工作流返回 404，未产生会话/
工作流记录。无需数据库的旧参数测试显式覆盖鉴权，只能证明参数路径。

测试使用独立 `eaap_test` PostgreSQL、随机 schema 和模拟/受控模型；不得使用日常库
跑测试。本轮没有新增真实模型调用，程序通过不代表真实语义、真实任务成功率或生产
多租户安全验收。已有少量真实 RAG 演示与检索报告，六题人工审核、真实策略比较和
完整 Agent benchmark 仍待完成。

文档修改只需检查内容、引用、Git 差异；业务验证按影响范围选择，失败或新问题才扩大。
Windows pytest 临时目录曾出现 WinError 5；它是准备阶段故障，不是业务断言失败。
