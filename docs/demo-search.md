# 演示第五步：用问题检索知识库中的候选段落

这一小步接上资料问答的前半段：用户输入问题 → 后端生成问题向量 → 比较已保存的
段落向量 → 返回排名靠前的原文。先展示检索候选，方便判断系统找到了什么，随后再接
生成回答；本操作不调用 answers、Agent、重排或生成模型。

## 概念与学习记录

2026-10-15，学习者独立解释：问题也需要向量化，才能与文档向量比较相似度。
导师补充，当前向量检索必须使用与文档相同的向量模型、接口身份和维度；维度相同
并不保证来自同一种向量空间。这是当前向量检索的要求，不是所有文字相似度方法的限制。

学习者已完成上一小步真实向量化操作：`demo-export-records.md` 的 8 块、1024 维
结果已保存，最新状态 ready。那次上限不覆盖本次问题向量化的调用授权。

## 客户端行为

新增 `--search`，与上传、切块、向量化互斥，不接受 `--max-chunks`。
登录后选择工作空间、知识库，交互输入一次 1..2000 字符的问题（去掉首尾空白）。
不要求选择文档或知道内部 UUID；检索范围是整个所选知识库，不局限于文档列表第一页。

向所选范围的 `POST /search` 只提交一次，参数固定为：

```json
{"query":"本次交互输入的问题","top_k":3,"strategy":"vector","rerank":false}
```

后端已有权限/范围检查及 ready、向量非空过滤，本轮不改后端接口或数据库。
有可检索候选时，问题最多生成一个向量，当前提供器最多发送一次向量 HTTP 请求；
没有自动重试或查询缓存。初次检查没有候选会直接返回空，但并发变化可能导致调用后
返回空，不能据空响应断言零费用。关闭重排不会调用其延迟生成服务。

客户端核对 vector/cosine_distance 模式、模型与 1024 维、最多 3 条结果；核对块 UUID
唯一、文档 UUID、正整数块序号、字符范围与正文长度、有限且非递减的 0..2 距离。
正文总量超过 100000 字符即拒绝该响应，这是客户端接纳限制，不是传输字节限制。
随后在所选知识库路径下 GET 每个唯一命中文档，核对 ID、父级、文件名及 ready 状态；
全部通过后才显示任何候选正文。同一文档多块只复核一次，不重新获取整份文件或全部块。
客户端复核不替代后端授权，也不代表像 MCP Host 那样逐块回验数据库原文。

每段展示文件名、块序号、解析文本字符范围、余弦距离和最多 300 字符的原文摘录。
先隐藏本次密码/Token 再截取，控制字符转义，不打印原始错误正文。距离越小表示越近，
不是答案正确率；本轮没有相关性阈值，返回的最近段落仍可能无关，3 段也可能来自同一文档。
候选为空正常退出，展示的摘录不是生成答案，不以检索排名代替证据判断。

检索 POST 的读取等待沿用向量操作的 330 秒，其余请求仍为 10 秒；不是整个 API 的
严格完成期限。超时、网络故障、中断、5xx、无效结果或来源核对失败都不自动重试，
提示“检索结果未确认，可能已调用向量服务”。HTTP 409 提示模型配置不一致。
