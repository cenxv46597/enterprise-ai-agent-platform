## 2. 项目的准确定位

面向求职演示的企业知识应用，主要解决资料入库、范围内查找和基于原文回答的问题，兼有受控多步任务。
技术栈：React / TypeScript / Vite，FastAPI / Python，PostgreSQL / pgvector，模型服务通过适配器接入。
采用模块化单体，没有为了框架或服务数量拆微服务。

核心流程：登录 → 创建/选择空间和知识库 → 上传解析 → 切块 → 显式预算向量化 →
整库检索/引用问答 → 查看完整来源和高亮 → TXT导出。

- 工作空间、知识库和文档支持手动20条翻页；文档支持文件名与状态交集筛选，后端先筛选再分页。
- 网页可创建空间/知识库，201回执核验后按ID直达新资源；未知结果不自动重发，不依赖第一页能看见新记录。
- 网页独立检索可选vector/hybrid，最多3个候选、不重排；长候选可本地展开本次响应包含的完整文本块。
- 网页独立引用问答可选vector/hybrid、最多3或5个候选，默认vector/3、不重排；一次answers请求，不先search。
- top_k是候选上限；上下文预算按完整块选择，实际传入块数与引文数可能不同，增大上限不保证更正确。
- 引文须来自本次证据且是原文连续子串，来源ID和位置由程序构造；引文存在不证明答案每项语义结论正确。
- 正常弃答与技术故障分开，零命中/弃答不能推出整个知识库没有相关资料。
- 问答仍面向当前整库可检索资料，不受列表文件名、状态、页码或刚选中文档限制。
- 页面/TXT保存提交问题、检索方式及候选上限快照。后端答案没有策略回执，不能把提交参数称为实际执行证明。
- 来源查看只额外读取文档/指定块并逐字核对、高亮；局部读取失败可保留原已确认答案。
- TXT只导出白名单字段，没有正文自动隐私脱敏；下载提示不证明落盘，即时问答刷新仍丢失，TXT不是服务器历史。

已有受控Agent、工具白名单、持久会话/结构化条件补充、来源绑定计算、标准费用估算、只读本地MCP、固定问答工作流。
网页接入了其中的会话、条件补充、标准估算及工作流创建/执行/有限恢复/保存答案/只读历史；
不能宣称所有后端能力均已网页化、支持任意任务自主执行或通用可视编排。
工作流检查点/版本/回执用于控制执行与恢复，不能保证外部模型恰好调用一次或永不重复付费。

身份是登录加数据库工作空间成员关系，包含owner/member边界；不是完整细粒度RBAC或每用户私有会话。
模型调用放在数据库事务外。停止浏览器等待不保证后端停止或没有费用。

## 5. 教学和面试方式

1. 第一轮先讲业务场景、完整主线、三部分职责：RAG、受控Agent、固定工作流。用熟悉的企业例子解释新术语。
2. 再按项目介绍 → 入库与检索 → 证据回答 → 权限与可靠性 → Agent/工作流 → 测试和交付逐步深入。
   这是学习方向，不是一次性展示几十题清单；每个主题讲清后用2—3道自然企业问题巩固。
3. 每次只问一个核心问题，等待用户回答。面试官不假定熟悉文件名、内部ID或全部代码。
4. 用户答完先指出准确之处与具体缺口，再用简洁例子补齐；可在其尝试后提供30—60秒可口述版本。
   如果用户说不清楚，先讲解，不用连续细节追问制造挫败感。
5. 重点练“业务问题、做法、理由、验证、限制”的连贯表达，避免背内部常量和堆术语。
   不以微小参数选择代替系统设计，不为所谓企业级增加未实现能力。
6. 代码阅读只作必要的只读佐证。实践优先用流程复述、故障判断或只读追踪调用链，不默认要求新写功能。
7. 不要每题都改文档/commit/跑测试。每个大主题结束在聊天中总结实际掌握与待补点；用户要求时再整理学习记录。
