# 引用问答错误码与HTTP排错编号：2026-10-19

## 修改、原因与完成条件

引用问答原先将EmbeddingTimeoutError与GenerationTimeoutError合并处理，旧业务日志没有HTTP排错编号，
难以从相同504定位问题向量化还是答案生成环节。本步接既有访问摘要，帮助按页面编号找到已知失败分类。

学习者选择A：访问摘要按需增加固定error_code，同一条记录包含HTTP定位与业务分类。
B为额外写结构化业务错误事件，适合后续更多事件，但查询时需关联两类记录。本步先保持单条摘要。
完成条件是状态/正文与既有行为一致、分类与本次响应编号对应、并发不串、成功不带旧码，且无敏感内容。

## 实现与固定分类

- `api/answers.py` 注入Request，在既有异常分支向本请求state写入AnswerErrorCode枚举，不额外执行检索或生成。
- `observability/answer_errors.py` 定义12个应用拥有的分类及各自预期HTTP状态。
- `observability/http.py` 只在枚举类型可信且观察到的状态匹配时追加error_code；任意字符串、字典或状态不匹配均不输出。
  不读取入站错误码头、不复制异常文本、不记录问题/草稿/来源正文、URL查询参数或资源ID。
- 原访问摘要十字段保持语义，有已知分类时为十一字段；没有分类时不填null或猜测原因。
  记录仍是INFO和尽力输出，日志故障不替换业务结果，也不保证日志送达。
- 本接口原来包含知识库ID和动态异常类名的三处warning/error输出由受控摘要分类替代，不再重复记录。
  仅治理本接口这些分支，不能扩大为旧业务日志及Uvicorn异常traceback已整体脱敏。

固定分类及边界：

- `answer_knowledge_base_not_found`（404）：进入问答函数后捕获的知识库不存在/父级不匹配。
- `answer_embedding_profile_conflict`（409）：检索向量配置不一致。
- `answer_retrieval_capacity_exceeded`（422）：有界混合检索容量超限。
- `answer_input_or_context_invalid`（422）：检索输入或回答上下文预算无效，两类仍保持原合并响应。
- `answer_rerank_input_invalid`（422）、`answer_rerank_configuration_invalid`（503）：明确捕获的重排输入或配置拒绝。
- `answer_generation_configuration_invalid`（503）：明确捕获的生成配置拒绝。
- `answer_embedding_timeout`、`answer_generation_timeout`（均504）：分别表示问题向量化与答案生成超时。
- `answer_embedding_failed`、`answer_generation_failed`（均502）：分别表示向量调用/结果异常、生成调用或草稿/引用校验失败。
  尤其generation_failed不等同“模型服务宕机”，真实引文校验失败也属于此类。
- `answer_retrieval_state_invalid`（500）：已知检索数据状态异常。

只覆盖引用问答函数内部已捕获的这些失败。身份/成员拒绝、FastAPI输入校验、进入函数前的embedding依赖503、
未分类异常仍按原响应与通用摘要处理，不编造上述错误码。已处理的重排降级也不能仅凭本字段当成问答失败。
已处理HTTP异常的outcome仍可为completed，包括明确返回的500；它表示HTTP调用完成，不表示业务成功。
错误码不是鉴权、幂等键、模型费用/执行次数证据，也不表示应自动重试。
当前没有修改网页、响应体或错误提示，也没有集中日志查询平台。
