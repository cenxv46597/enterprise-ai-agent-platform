# HTTP请求排错编号：2026-10-18

## 改动、原因与实际场景

为进入后端应用的每次HTTP请求生成新的UUID4，在响应头 `X-Trace-Id` 返回，
同时写入一条带同编号的访问摘要。开发者可按响应头中的编号查对应接口、状态和耗时，缩小故障范围。
该摘要不包含根因细节，不能仅靠它判断一次失败的完整原因。

学习者确认A“后端每次生成新编号”。B为优先沿用调用方合法UUID，缺失/无效再生成；
本轮先实现服务端独立生成，不接跨服务关联。见[ADR0031](../adr/0031-server-http-trace.md)。

## 代码与契约

- `app/observability/http.py` 提供纯ASGI中间件、专用logger配置及通用500处理器。
- `app/main.py` 注册新中间件和500处理器，保留FastAPI对象及依赖覆盖方式。
- 请求状态使用 `http_trace_id`；覆盖响应中已有同名头，最终只返回一个服务端UUID。
- 忽略入站同名头，包括重复或无效值；响应体、业务 `request_id` 和幂等逻辑不变。
- 成功、认证拒绝、参数错误、ready失败、404/405和未捕获500均可关联到摘要。
- 500保留 `Internal Server Error` 纯文本、补同编号与no-store，不返回异常原文。
- 新层不签发Cookie，既有登录/恢复/退出仍按ADR0030；本后端阶段不接网页。
  后续仅[引用问答页的HTTP失败](../frontend/frontend-answer-trace.md)接入编号，其它页面仍待分步接入。

专用日志器 `eaap.http` 使用INFO、独立StreamHandler、propagate=false，仅配置一次，不修改root。
一行JSON固定字段为event=http_request、trace_id、method、route、status_code、elapsed_ms、outcome。
method使用白名单，其余为OTHER；route来自应用声明的模板，例如 `/documents/{document_id}`，
未匹配为 `<unmatched>`，不会回退记录实际URL。请求正文、请求头、身份、资源ID、查询参数、原始异常不进入新增摘要。

outcome口径：

- completed：应用返回且响应内容/所承诺的trailers已结束，含正常返回的401/403/422/503。
- error：有未捕获Exception；尚无响应头时记录500，已有响应头则保留观察到的状态。
- interrupted：BaseException中断，例如未发送响应时的取消；此时status可为null。
- incomplete：应用返回但未观察到响应完成。

status_code记录应用观察到的响应开始状态，不保证客户端实际收到；例如流式发送200后报错，
摘要仍是200和error，不能改写已开始的响应。completed也不是工作流状态，不证明业务成功。
elapsed_ms覆盖本次ASGI调用，可能含流式及背景任务，不代表浏览器等待或Agent控制器耗时。
无Token/费用、外部观测平台、分布式span、数据库持久化、聚合/限流或日志送达保证。
日志输出故障不会使业务响应失败；也可能丢失本次记录，不把“不中断业务”说成“日志必达”。

## 使用方式与现有日志边界

当前README启动命令增加 `--no-access-log`，关闭Uvicorn默认的原始URL访问日志，避免重复采集。
示例假设已有私有配置/数据库就绪，在仓库根目录CMD启动：

```cmd
.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --no-access-log
```

本轮没有执行上述启动命令，也没有读取实际私有配置。部署时如使用其它入口，需相应配置访问日志。
现有业务logger与Uvicorn异常traceback未全部治理；框架发送500后仍向服务器抛异常，
`--no-access-log`不会关闭异常traceback。不能把本轮摘要字段安全扩大为全进程日志已脱敏。
