# 阶段 1.10：真实单题评审与生成证据快照

## 1. 当前目标

完成首轮真实模型评审，并让后续公开问答实验能够保存生成模型准备收到的输入。本轮完成一次 DeepSeek 评审；快照能力采用本地模拟模型验证，尚未采集新的真实生成请求。

## 2. 为什么需要

比较提示词必须固定问题和证据。检索到五块不代表五块全部送入生成；预算可能跳过部分块。只查看最终引用，也不知道模型看到了哪些未引用资料。记录适配器实际构造的请求可以让实验输入可核对。

## 3. 核心概念

- 检索候选、预算选中资料和答案引用，是三个不同集合。
- 来源编号对应本次选中资料的顺序，不等于数据库块编号。
- 请求发送前快照证明本机准备了什么，不能证明远端处理成功。
- 正常响应、引用真实与答案语义正确需要分别验证。
- 超时是执行结果不确定，不能据此断言文档没有答案。

## 4. 设计与取舍

业务层记录便于追踪块身份，适配器记录能覆盖最终消息、提示词与参数。当前选择适配器回调，在公开演示中显式启用，适合六题规模；完整在线追踪需要更多存储和访问控制，目前不引入。理由见 [ADR 0012](../adr/0012-generation-request-snapshots.md)。

## 5. 实现与数据流

`/answers` 检索 → 共用预算选择 → 生成适配器构造 JSON → 可选回调核对公开资料 → 保存快照 → 发出请求 → 路由验证引用 → 报告保存响应。

`generation_snapshot.py` 验证请求字段、固定问题、顺序编号与公开原文，保存正文和内容摘要。共享请求层传递副本，保存失败则停止请求。正常 API 默认关闭采集，返回格式保持现有契约。

`live_rag_smoke.py` 新增 `--capture-generation`。根报告的 `prepared_generation_requests` 在发送前保存；成功的逐题结果附带相同快照及 `answer_response_received`。没有生成请求的正常弃答记录 `null`。旧报告不补写历史快照。

## 6. 如何验证和使用

本轮真实评审仅选 `restart_recovery_steps`，调用一次，不重新检索或生成。三项检查建议均通过，用量为输入 3346、输出 1636、合计 4982 token；费用未按价格推算。人工完成数仍为 0/6。详见[首轮记录](../evaluation/model-review-first-case-2026-10-11.md)。

快照测试验证保存先于请求、记录失败零请求、副本隔离、公开资料边界，以及三块候选中只选两块时的实际输入。自动化测试使用模拟模型，不产生模型费用。

本轮专项 150 项通过（3.42 秒），随后加入实际预算链路测试，完整后端回归 **597 项通过、无跳过（156.80 秒）**，使用独立 PostgreSQL/pgvector。当前 126 个待版本管理文件没有发现本机现用 API 密钥和数据库口令的字面值，`.env` 未被跟踪；此检查不代替通用敏感信息审计。

下一次决定真实采集时，从仓库根目录使用新文件；此命令会调用真实向量和回答服务，保存演示资源，本轮没有执行：

```powershell
.\.venv\Scripts\python.exe backend/scripts/live_rag_smoke.py --run --capture-generation --case-id restart_recovery_steps --report docs/evaluation/generation-snapshot-local.json
```

新报告续跑时同时使用 `--resume --capture-generation`；不能将此选项加到旧六题报告上。此步骤目前只记录输入，尚未实现两版提示词的重放比较。

## 7. 学习与小实践

打开 `test_generation_snapshot_records_budgeted_sources_not_all_retrieval_candidates`。先预测将预算从 8 改为 4 时剩下哪些资料及编号，再修改受控响应与断言运行该测试。测试中的模型是模拟服务，不用真实密钥。

本轮代码与测试由导师实现，学习者尚未独立完成上述实践。学习者已正确指出超时题不能默认通过；仍需区分“未知答案质量”和“确认没有证据”。

面试练习逐题进行：发送前已有快照但随后超时，能够证明什么；快照和最终引文为什么不能互相替代；同一输入的两次生成为什么仍可能不同。本轮先讨论第一题。
