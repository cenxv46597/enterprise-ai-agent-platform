# 数据库升级回归：0009 → 0010 保留旧资料

2026-10-21，起点`a0615a4`。用户大致理解CI/GitHub Actions/Docker关系后要求下一步，导师选择把已有身份迁移的代表性升级场景纳入独立数据库CI。本轮新增验证，不新增迁移版本，也不在日常数据库执行升级。

## 业务问题和基础概念

程序版本升级时，数据库中的表和字段也可能需要变化。按顺序修改数据库结构的脚本称为“迁移”；本项目用Alembic执行脚本并记录当前版本。

已有`0009 → 0010`增加用户与工作空间成员表。目标是旧工作空间、知识库继续保留，同时不能自动把旧资料分配给新用户；既有业务决策见[ADR0026](../adr/0026-user-workspace-access.md)。历史身份迁移测试和日常库过渡证据保留，不重复初始化既有账号或归属。

## 方案与实现

- 直接按当前ORM模型建表只能证明新结构可建立；旧测试逐模块调用`upgrade()`还绕过了迁移入口、版本图和版本记录。本轮使用正式`alembic.command.upgrade`，先按图建立0009，再升级固定0010，不用`stamp`冒充执行。
- [env.py](../../backend/alembic/env.py)支持官方的`Config.attributes['connection']`模式，复用测试事先限定的连接；注入路径不读取Settings、不另建Engine、不关闭调用者连接。默认迁移仍使用原Settings与NullPool路径，增加finally确保Engine释放。`version_table_schema`让版本表明确落在本次区域。
- [alembic.ini](../../backend/alembic.ini)声明`path_separator=os`，让公共路径配置按操作系统分隔，避免正式入口触发旧路径分割弃用警告。
- 新固定测试[auth_upgrade_ci_db](../../backend/tests/test_auth_upgrade_ci_db.py)只用本次临时身份拥有的`eaap_test_<uuid>`，每个事务重新设置search_path。schema可理解为独立测试库中本次专用的数据区域，不扩大清理前缀去复用旧历史测试区域。

## 一个场景的完整执行过程

1. 在独立`eaap_test`内验证实际库名及本次临时身份，创建随机区域。
2. 通过正式入口从空区域升级至`20261012_0009`，核对版本表及尚无用户/成员表；插入一条虚构工作空间和一条虚构知识库，保存原字段快照并提交。
3. 新连接读取已提交旧版本与快照，再升级`20261013_0010`并提交。
4. 再用新连接核对0010版本、旧记录ID/名称/时间/父子归属与向量配置字段快照、新增用户/成员表为空，以及当前ORM结构一致；重复升级同一目标仍不改变资料或自动分配归属。
5. 只在实际测试库且schema归属为本次身份时清理该区域，最后由专用runner核对临时身份及剩余区域清理。

ORM比较时，PostgreSQL反射将当前search_path区域表示为默认schema(None)，比较上下文采用同一别名以排除Alembic自己的版本表；正式升级仍显式指定版本表区域，版本值也通过限定schema的查询单独核对。不能为消除假失败跳过业务表或版本断言。

## 前置扩展和CI入口

从0001重建旧结构会经过向量字段迁移，需要`public.vector`扩展。它是数据库支持向量类型的组件，不是本轮检索或模型质量验证。

[专用runner](../../backend/scripts/run_postgres_tests.py)在确认实际测试库、管理身份和端口后先检查扩展：缺失才在`eaap_test`的public安装并复核；已有public则复用，位于其他区域则失败，不移动、升级或删除。临时测试身份继续为非超级用户。此扩展作为本机独立测试库基础设施保留，不随随机schema删除；CI整个数据库容器结束后销毁。

固定数据库清单由17增至**18项**：原列表14、ready3和新增迁移1。新节点缺失或被替换也不能变绿。工作流标签同步18项；依赖版本不变。`--check-entry`仍只跑替身安全检查，不连接数据库；它新增扩展前置、正式迁移入口连接归属和默认资源释放回归。

从项目根目录用CMD：

```bat
.venv\Scripts\python.exe -I backend\scripts\run_postgres_tests.py --check-entry
.venv\Scripts\python.exe -I backend\scripts\run_postgres_tests.py --docker-exe "<已核对的docker.exe完整路径>"
```

第二条需确认原项目容器和独立测试库可用，不需要在聊天提供密码，不调用模型或检索。不要改连日常数据库，也不要用普通pytest缺配置时的skip当完成。
