# 阶段 1.8：回答质量评测设计草案

状态：离线审核工具已实现，六题逐项人工验收待完成。2026-10-11 开始；今天后续修改先保留在工作区，学习者决定收尾时再确认提交与推送。

## 1. 当前目标

复用已保存的六题真实问答，建立可复查的回答质量基线，核对事实、条件、操作顺序和弃答。先完成离线评测与故障验证，不改变线上问答策略。

## 2. 为什么需要

前两个模块分别评测检索证据和送入模型的上下文，本模块检查最终答案。真实岗位需要能够定位错误发生在哪个环节，并用固定案例解释改进依据。

## 3. 核心概念

- 引用有效性：编号、逐字引文与字符范围能否对应实际证据。
- 回答忠实性：答案中的结论是否受到证据支持，是否改变条件或顺序。
- 回答完整性：有没有回答问题要求的必要事实与步骤。
- 弃答正确性：资料足够时不应错误弃答，资料不足时不应编造答案。

这些维度分别记录，不能用词语命中或引用存在代替全部语义验收。

## 4. 方案与推荐

方案一是明确检查项加人工语义核对。现有题集只有六题，逐题定位原文和结论成本较低，便于学习者复查；缺点是需要审核时间，不能直接扩展到大量题目。

方案二是额外调用模型担任评审。它更适合较大题集，但增加费用、输出波动和评审误判，需要先用人工案例校准；不能将模型给出的分数当作确定事实。

首版推荐方案一：程序检查报告身份、引用、评审记录结构和统计规则；语义判断逐项保存判定与理由。没有完成审核的案例保持待审核，不记为通过，也不并入已审核质量分。AI 导师可以提供初步判断，但不能冒充学习者已独立审核或掌握。

## 5. 实现范围

输入复用 `docs/evaluation/live-rag-smoke-2026-10-10.json`、对应题集和公开原文。公开检查项保存在 `examples/evaluation/answer-review-rubric.json`，绑定原报告、题集的规范 JSON 摘要和规范文本摘要，将问题、实际答案、引用与验收检查项关联起来，保留原报告，不覆盖原响应。

离线模块位于 `backend/app/evaluation/answers.py`，不依赖数据库或外部模型。`evaluate_answer` 核对公开引文、来源与重建块范围，验证审核记录绑定同一答案，再按审核记录计算人工结论；`summarize_answers` 分别记录审核覆盖率和已完成人工审核的通过比例。

测试使用受控答案注入条件遗漏、顺序颠倒、无依据补充和错误弃答，并使用受控审核记录验证分层记录与统计。程序不会自行识别这些语义错误。正式问答接口的契约错误继续由现有业务层处理。

这份小型基线评价的是原始六题问答，不能冒充带干扰知识库的新一轮生成成绩，也不能据此宣称整体系统可靠。

## 6. 验证

首个实践使用公开运维说明中的重启流程。学习者预测：引文真实且编号正确时，改变条件的答案仍会通过 `_validate_citations`。新增 `test_real_citation_validator_accepts_answer_that_drops_required_condition` 已验证该预测；另一个测试为同一反例记录人工不通过，证明引用检查与语义结论可以不同。

脚本 `backend/scripts/evaluate_answers.py --plan` 只显示汇总；`--write-report` 生成新的审核模板。原始报告、题集或语料变化时拒绝继续；审核副本改变展示答案或检查项时也拒绝复用判定。所有输入输出限定在公开报告目录，已有文件不被覆盖，错误不输出原始输入。

## 7. 学习验收

能够解释每个判定由谁负责、自动检查能覆盖哪些错误，以及为什么待审核不等于通过。需要学习者实际判断和修改测试后记录掌握情况，不能用 AI 完成的代码代替学习证据。

## 8. 下一步

首个代码评审问题已回答，审核记录与统计模块已经实现，方案记录在 [ADR 0010](adr/0010-offline-answer-review.md)。学习者指出当前没有专职审核者，后续已加入[可选离线模型辅助评审](phase1-model-review.md)。人工可以核对少量样例，无需逐句转换所有文档；AI 建议单独报告，不能代填人工结论。

收尾时逐题讨论引用校验的边界、人工与模型评审的取舍、以及如何定位检索和生成错误；本轮不一次提出多道问题。
