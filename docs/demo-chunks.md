# 演示第三步：处理已上传文档的文本块

本轮继续“资料入库”主线：选择已上传的文档，调用后端现有切块接口，再查看块数、字符
范围和文档最新状态。客户端不重新上传原文件、不调用向量或生成模型，后端接口未变。

## 本机操作

保持原数据库容器健康、后端运行，从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe backend/scripts/browse_demo.py --username demo_a --chunk
```

隐藏输入已有密码，按名称选择空间、知识库，再选择刚上传的 `demo-export-records.md`。
使用当次列表显示的编号，客户端取出对应 UUID；不需要自己查内部 ID。这里是对指定
文档执行管理操作，后续普通知识问答仍由系统检索相关文档。

`--chunk` 与 `--upload` 互斥，每次只进行一种操作。空列表或所选文档尚未成功解析时
停止，不发送切块请求；后端仍会重新鉴权并检查文档归属、当前状态及已有配置。

## 调用与结果

选中文档后，客户端发送 `POST /documents/{document_id}/chunks`（省略空间与知识库前缀），
固定 JSON 为 `{"chunk_size":500,"overlap":50}`。后端读取保存的原件，返回 HTTP 200 和
文本块列表；同一文档的参数及算法版本一致时复用已有块，配置不同返回 409，不覆盖。

客户端核对块 ID、所属文档、连续块序号及字符范围/文本长度的一致性，只展示块数及
前 3 块范围，不打印正文。`[0, 500)` 表示从第 0 个字符到第 500 个字符之前；下一块
通常从 450 开始，保留 50 字符重叠。这些位置对应后端解析文本，不是原文件字节偏移。

随后用 GET 文档详情读取最新状态。切块本身不改变文档状态：新上传的 `parsed` 文档
仍是“已解析，尚未可检索”；已 `ready` 的文档同配置复用后仍可检索。本接口无法区分
这次是首次保存还是复用，所以客户端不声称“新建”或“已复用”。

超时、5xx、中断或无效成功响应只提示结果未确认，不自动重试；后端的同配置幂等语义
允许核对后显式重试。若切块响应有效，但后续详情读取失败，会分别提示“切块响应已
校验，最新文档状态未确认”，不会把两件事混成未执行。

## 学习和验证

2026-10-15，学习者已截图确认上一小步真实上传成功：新文件记录创建、状态 parsed，
并出现在知识库列表。本轮选择后端统一切块为确认选项；学习者表示不理解理由，导师
补充了原件已保存、规则和块身份统一、多个客户端复用接口等原因，不记独立完整解释。

本轮实现和测试由导师团队完成。客户端专项 **49 项通过、无跳过（0.94 秒）**，包括
既有 35 项及新增 14 项；这是本轮一次联合成绩，不与历史相加。全部 MockTransport，
本机临时文件只用于既有上传测试；未访问日常库、执行真实切块或调用模型。验证目标
包括选中文档 UUID/Token/固定参数、状态拒绝/空范围/互斥参数、POST 故障不重试、
块归属错配及详情父级错误、复读最新状态。模拟返回相同块 ID 只验证客户端不误称新建，
数据库幂等性依据既有后端专项，不由本轮 Mock 测试证明。`--help`正常。
