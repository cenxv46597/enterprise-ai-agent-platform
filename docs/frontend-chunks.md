# 网页第六步：独立文档处理页与显式切块

2026-10-16，起点 `fdc5ac4`。在已有网页文档列表和上传流程上，接入后端已有的文档详情与切块接口。

## 目标与方案

从某一张文档卡片进入独立处理页，读取最新状态与已有块，显式点击“切块”，查看数量和正文预览。
学习者选择 A：独立文档处理页；B 是在列表内展开。此处记录为方案确认，
集中单份文档上下文与页面切换的取舍由导师说明，不记独立完整设计。

本步复用已有算法及持久化服务，不添加路由框架、数据库迁移、参数编辑或自动处理链。
固定配置为每块最多 500 个字符、重叠 50 个字符；向量化及其真实模型调用预算仍单独推进。

## 身份、读取与展示

列表按钮显示“查看与切块”，内部绑定被点击记录的文档 ID，不以文件名识别同名文档。
App 分开保存选中文档快照、最新详情、已确认块数组和切块操作结果：

- `GET /api/v1/workspaces/{workspace_id}/knowledge-bases/{knowledge_base_id}/documents/{document_id}`
  读取最新详情，再 `GET` 同路径的 `/chunks` 读取已有切块；进入页面不发送 POST。
- 详情严格校验文档 ID、知识库 ID、文件名与状态，只保留必要字段。
  服务端继续校验当前用户、工作空间成员及父子范围，文档 ID 本身不代表权限。
- `parsed` 既可能尚无块，也可能已有块，不能从状态推断是否切块。
  `chunks=null` 代表记录未确认，`[]` 只代表当前没有块，不代表未解析或读取失败。
- 文档名保留选中快照作上下文，最新状态未确认时明确提示，不将快照当作最新状态。
  块读取失败仍可展示已确认的详情，但禁用切块操作；401 清理全部身份与资源，404 显示范围错误。
- GET 返回的现有块可使用非默认配置，不强制按 500/50 校验。
  列表按后端从 1 起连续编号，核对严格 UUID、文档归属、唯一块 ID、序号、字符范围及正文长度。
  首块从字符 0 开始，后续范围递增且无间隙；最多 10,000 块、总正文最多 10 Mi 个字符（含重叠）。
  长度按 Unicode 码点计算，与 Python 字符切片一致，不使用 UTF-16 单元数冒充字符数。
- 展示整批块数，只预览前 3 块、每块最多 300 个字符。预览按码点有界读取，正文用 React 文本转义；
  字符范围为解析文本中的 `[开始, 结束)`，不是原文件字节偏移。不显示内部 ID 或任意后端错误字段。

## 显式切块与结果确认

只有最新状态为 `parsed/ready`、详情和已有块均已确认、空闲且无读取错误时允许“切块”。
发送同一文档路径的 `POST /chunks`，固定 JSON 为 `{"chunk_size":500,"overlap":50}`。
复用同源 Cookie、`X-EAAP-Web`、禁止重定向及缓存、每次请求 10 秒超时，不自动重试。

后端同参数及算法版本复用已有块，不同配置返回 409、不覆盖；前端不重写这项规则。
HTTP 200 的非空块数组通过整批校验后，只称“切块请求成功，返回 N 个文本块”，
不声称本次新建或复用，因为响应没有该标志。切块不会直接改变文档状态或生成向量。

确认切块后保留返回块和操作结果，再单独 GET 详情核对最新状态。
若这次读取失败，提示“切块响应已确认，但文档最新状态未确认”，不抹掉切块成功；
401 按会话失效清理，404 也不继续展示原正文。未确认最新状态时不能继续写入。

401、403、404、409、422 使用固定安全拒绝文案；409 不能靠未校验的原始错误详情
猜测一定是状态问题或配置问题。发出后的断线、超时、取消、5xx、其他未知状态或无效成功结果
均显示“切块结果未确认”，不自动重试；必须显式刷新核对当前详情和块记录后，才允许再次点击。
刷新全部成功后清理旧的未确认或拒绝提示，只确认当前记录，不伪称此前 POST 已成功；
已确认的切块成功结果仍保留。刷新失败则保留原提示。

“停止等待切块结果”仅取消浏览器等待，不保证服务端停止。返回文档列表重新读取当前库第一页。
导航、停止等待、退出和原登录期限到期均沿用取消信号与请求序号隔离迟到响应；
退出进行中隐藏正文，退出失败若中断切块则保留未确认提示，不能恢复旧的可写状态。
浏览和处理均不续期，不自动执行向量化或模型任务。

### 逐题面试与概念澄清

- 第一题讨论切块成功后查询最新状态超时。学习者初答不清楚，导师讲解两次请求应分别确认。
  学习者随后正确说明切块确实成功，只是后续查询失败，显示“切块失败”会与事实不符。
  记录为讲解后能准确解释已确认成功与后续未确认的区别，不记初答独立掌握。
- 第二题讨论切块从 `500/50` 改成 `800/80` 为何不直接覆盖旧块。
  学习者先表示不理解参数，导师讲解块长、重叠、字符范围及正文改变后向量/引用的一致性问题。
  学习者随后正确指出正文改变后不能直接认为旧向量仍适用，因为旧向量来自旧文本；
  不记独立完整设计重建、向量更新及引用维护流程。
- 学习者进一步主动询问向量化的含义。导师区分切块与向量化，结合数学向量解释每块的 1024 维数字表示、
  已训练模型推理、问题向量和余弦距离。学习者正确回答 5 个文本块对应 5 个向量，
  并自行提出问题向量也应为 1024 维、与候选向量比较；导师补充维数相同还不够，
  当前项目还须使用同一模型及兼容配置，检索范围是有权访问知识库中的可检索块。
- 学习者主动询问切块是否按语义。导师结合真实算法说明当前按固定字符窗口及重叠切分，
  不判断句子、段落或主题边界；重叠只能帮助边界上下文，不保证完整语义。
  对比段落/句子边界与语义切块作为概念，不新增算法或效果验收。
